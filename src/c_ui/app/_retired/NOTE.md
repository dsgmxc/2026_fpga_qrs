# `_retired/` —— 退役但保留的文件

## 为什么这个目录不在 `app/*.c` 的通配里

`Makefile` 的 `APP_SRC := $(wildcard app/*.c) $(wildcard ui/*.c)` **只扫一层**。
放子目录里等于"留在磁盘上、不进编译",既保留追溯,又不会和
`app/pynq_protocol.c` 撞重复符号。

## `pynq_protocol_stub.c`(2026-10-05 退役)

`display_protocol.h` 的**空实现**:`Request*` 一律返回 `false`,界面上每个
测量按钮都显示「指令发送失败」。

退役原因:它当初的定位是"测量链接通之前的占位",而**方案 A**
(2026-10-05 定)让偏压和激励**现在就能真的驱动硬件**了 —— 留着空实现等于
把已经能做到的事继续报成失败。

取代它的是 `app/pynq_protocol.c`。新文件保留了它的两样东西:

| 保留 | 说明 |
|---|---|
| `CV_UI_DEMO=1` 演示叠加 | 模型生成的 Cs/Cp/D,用来把扫压页画满以检查曲线渲染 |
| `CV_UI_DEMO_PAGE=<n>` | 无值守跑一遍再切页,用于截图 |

**差别**:新文件里扫压在两种模式下**都真的驱动 DAC**,`CV_UI_DEMO` 只控制
要不要把编造的电容值一并塞进曲线。所以演示模式下的偏压数字现在也是真的。

**保留它不是为了回滚**(真要回滚就把它拷回 `app/` 并删掉 `pynq_protocol.c`)，
而是为了报告里的对照:同一份 `display_protocol.h` 接口,空实现和真实现各长
什么样,是"软硬件划分"那一节最直接的证据。
