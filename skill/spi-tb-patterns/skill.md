# spi-tb-patterns

> 自检测试台(testbench)的设计范式:**让测试台自己证明它会失败**。
> 名字来自 SPI 主机的验证,但**整套方法是通用**的 —— 任何"只观察引脚、不窥探内部"的
> 协议类 RTL 验证都适用。

## 适用范围

- 手工 Verilog TB + Vivado `xsim`。
- 适合验证的对象:**协议类 / 时序类模块**(SPI、I2C、并口采集、FSM 驱动的外设控制器)。
- 前提:被测模块有**可观察的引脚级行为**,且有**权威的期望值来源**(数据手册 / 参考实现)。

**不适用**:需要覆盖率的复杂验证(UVM / 约束随机)、纯数据通路模块(该用参考模型直接比)。

---

## 使用方法

### 一、核心原则:测试台必须先被证明"会失败"

> **不先证明测试台会失败,测试通过就没有信息量。**

做法是**变异测试(mutation test)**:向 DUT 注入 N 个已知缺陷,确认测试台**每个都抓得到**。

本项目实测强度:

| 对象 | 基线 | 变异体 | 结果 |
|---|---|---|---|
| `spi_master` | 5 模式 × 25 检查 **ALL PASS** | **7 个**注入缺陷 | **7/7 全抓** |
| `dac_1220` | **21 项 ALL PASS** | 4 个 | 17 PASS / **4 FAIL** |
| `adc_9833` | **10/10 PASS** | 变异 B(`c[27:14]`→`c[27:15]`) | 帧 5/7/9 **FAIL**,帧 4/6/8 全过(判据**有区分力**) |
| `adc_9833` | 同上 | 变异 C(后置锁存加状态限制) | 帧 6–9 **MISSING** |

变异 C 尤其值得抄:**它验证的不是"功能对不对",而是"某一行代码是不是必需的"**。
只动了那一行的位置语义,一个原本稳定的触发就消失了。⇒ 那行位置**不是装饰**。

### 二、从机模型**独立实现**,不引用 DUT 内部信号

```verilog
// ✅ 从机模型只依据协议语义(CPOL/CPHA 推导前导沿/后随沿)
// ❌ 一碰 DUT 的 bit_cnt / state / t_flag,两边就会同错同过
```

**理由**:如果从机模型复用了 DUT 的内部状态,那么"DUT 错的地方模型也跟着错"
⇒ 仿真会**假通过**。独立实现是让两边成为**真正的独立观测者**。

### 三、判据要盯**两个方向**

```
slave_rx_cap === pat_tx    // MOSI:主机发对了没
rx_data      === pat_rx    // MISO:主机收对了没
```

只查一个方向,另一个方向的故障会被漏掉。

### 四、🔴 测试图案的**判别力必须实测**

**这一条是本项目最贵的教训。**

模型原本选 `A5A5` 作图案,理由写的是"0/1 交替,对位序反转最敏感"。
变异测试注入"`mosi` 位序反转"后,这组图案**只抓到 2/6 帧**。

**根因**:`A5A5` = `1010 0101 1010 0101` —— **倒过来还是它自己(回文)**。
`8001`、`0000`、`FFFF` 同理。**对回文图案做位序反转,结果不变,当然抓不到。**

**更正**:改用**非回文 / 单比特**图案(`0001` / `8000`、`AAAA` / `5555`),
同一变异体的抓到率从 **2/6 → 5/6**。

> **"看起来复杂"不等于"判别力强"。用回文图案等于自我否定。**

**选图案的检查表**:
- 位序类缺陷 ⇒ 用**非回文**图案
- 位宽类缺陷 ⇒ 用**单比特置位**(`0001` / `8000`),一眼看出错位
- 边界类缺陷 ⇒ 用 `0000` / `FFFF` 测端点
- 行走的 1 / 行走的 0 ⇒ 定位具体是哪一位出问题

### 五、🔴 负测试**自己也要被验证**

为了验证"参数不匹配会被抓到",用 `sed` 改 DUT 参数再跑。两条 `sed` 命令**都没匹配上**:

```bash
s/parameter MSB_FIRST = 1,/.../     # ❌ MSB_FIRST 是最后一个参数,没有尾逗号
.MSB_FIRST  (MSB_FIRST),            # ❌ 用了 7 个空格,文件里是 2 个
```

**后果**:那两组"负测试"实际是在参数**没被改动**的情况下跑的 ⇒ **恒 PASS**。
`sed` 不匹配**不报错**,`xelab` 也不报错,**测试看起来"通过"了,实际什么都没测**。

**更正**:改用不带逗号的模式,并**先确认改动真的落到文件里**再跑。
修正后同一测试立刻抓出 **5 个 FAIL**。

> **判据:一个"应该失败"的测试如果 PASS 了,第一反应不能是"设计真健壮",
> 而要是"这个测试可能根本没生效"。**

### 六、看门狗是必需品,不是可选项

`adc_9833` 的变异 C 一跑,`xsim` 在 shell 里 120 s 不返回。第一反应是"xsim 挂了"。

用 `run 8 ms` **定量跑一次**,2 秒就跑完 8 ms 仿真时间 ⇒ **仿真本身没挂**,
是 TB 的 `wait(frame_i >= 7)` 在等一个被变异体丢掉的帧,`$finish` 永远到不了。

**改法**:把结果打印抽成 `task report;`,再加一个看门狗:

```verilog
initial begin #6000000; $display("---- TIMEOUT ----"); report; $finish; end
```

⇒ 证据从"卡死"变成"逐帧可读的 MISSING"。

> **没有看门狗的 TB,会把被测对象的缺陷伪装成仿真器故障。**

### 七、期望值来源必须独立于 DUT

**首选数据手册**,并在注释里写明依据哪一版哪一张表。
**不要从 DUT 的输出反推期望值** —— 那是循环论证。

本项目一条正面样本:`adc_9833` 的查表函数有**两条互证** ——
更新时喂 `code=0xA3D70A`(init 里用过的频率字),发出的两帧与 init 的第 2、3 帧
**逐字节相同**。这证明两处用的是手册表 9 的**同一条规则**。

### 八、采样沿必须与 DUT 语义一致

`CPOL=1 / CPHA=0` ⇒ 从机在**下降沿**取数 ⇒ TB 也在**下降沿**采样。
这个沿写反会让整份结论作废(本项目在 `dac_1220` 的调试中踩过,见
`skill/measurement-instrument-can-be-wrong/`)。

### 九、已知盲区要**写进报告**,不要藏

`spi_master` 的验证报告里显式标注:

> ⚠️ **「DUT `CPHA=1` + 从机 `CPHA=0`」这类模式错配组合会假通过**(时序巧合)。
> 已用变异测试对冲,但盲区确实存在。

⇒ 这条让结论**可用且诚实**;藏起来才经不起追问。

### 十、参数边界扫描

不要只测"选定的那个值"。扫一遍参数,把余量**算出来**:

| `SPI_HALF_T` | 结果 | 余量 |
|---|---|---|
| 2 | ❌ FAIL | −2 |
| 3 | ❌ FAIL | −1 |
| 4 | ⚠️ ALL PASS | **0**(靠 delta 周期侥幸,**上板必踩线**) |
| 6 | ✅ PASS | 2 |
| 10 | ✅ PASS | 6 ← 工程取值 |

**正确推导**:DUT 在下降沿后 `SPI_HALF_T − 2` 拍采 `miso`;从机 MISO 在下降沿后 2 拍稳定
⇒ **余量 = `SPI_HALF_T − 4`**。

> ⚠️ 注意 `SPI_HALF_T = 4` 那行:**仿真 PASS 了,但它是"侥幸"而非"满足"**。
> 参数扫描的价值就在于把这类"仿真过、上板挂"的取值挑出来。

## 失效条件

- ⛔ **测试台自己没被变异测试验证过** ⇒ 它的 PASS 说明不了任何事。
- ⛔ **从机模型引用 DUT 内部信号** ⇒ 同错同过。
- ⛔ **用回文图案测位序类缺陷** ⇒ 零判别力。
- ⛔ **`sed` 类改动不确认落盘** ⇒ 负测试恒 PASS。
- ⛔ **没有看门狗** ⇒ 挂死被误读成仿真器故障。
- ⛔ **期望值从 DUT 反推** ⇒ 循环论证。
- ⚠️ **仿真通过 ≠ 上板可用**。本项目 `spi_master` 的结论是在 `SPI_HALF_T = 10` 下取得的,
  **`= 256`(工程实际取值)下未重跑**。

|---|---|---|
| SPI 主机:5 模式 × 25 检查 | **ALL PASS** | `sim/logs/` 7 份原始日志 |

## 来源

1. **`LLM-005`(2026-09-15)** —— 三条**模型自身的错误**,全部由模型自己实测发现:
   - **轨迹 A**:图案判别力判断错(回文图案),2/6 → 5/6。
   - **轨迹 B**:时序余量推导错("和 `SPI_HALF_T` 多大无关"),边界扫描直接证伪。
     > 教训:凡"某两个量无关"的判断,**先找一条能把它变成相关的路径**再下结论。
   - **轨迹 C**:`sed` 静默失配制造出**空转的负测试**,恒 PASS。
   同轮还暴露一条**环境问题**:用户看到 Vivado 编辑器里的 tb 是旧版 ⇒
   **Vivado 编辑器不会自动重载外部修改的文件**,而且在该标签页 Ctrl+S
   会把新版**覆盖回旧版**。⇒ **验证结论必须落到磁盘核对,以磁盘为准。**
2. **`LLM-014`(2026-09-20)** —— 看门狗的引入(变异 C 挂死),以及
   **模型报了一个假 FAIL**(期望值把 7 位十六进制当 8 位算)。
   矛盾点提示了方向:帧 7 走同一条 MSB 路径却 PASS ⇒ 路径不是整体坏的 ⇒ 回头审期望值。
3. **`LLM-010`** —— `dac_1220` 自检型 TB 的写法:只观察引脚、期望值全部来自手册、
   按手册 Table 6/7 解码命令重建寄存器比对。
