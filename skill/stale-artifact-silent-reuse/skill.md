# stale-artifact-silent-reuse

> **工具缓存与产物,比源文件活得更久 —— 而且不报错。**
> 本技能收录本项目同一母题的**四次发作**,症状各不相同,根因同构。

## 适用范围

- 任何"改源文件 → 跑工具"的流程:Vivado(综合 / 实现 / 位流 / BD)、
  仿真器(`xelab` / `xsim`)、编辑器、版本控制、构建系统。
- 尤其命中:**GUI 与 CLI 混用**、**批量(非工程模式)脚本**、**跨会话继续工作**。

---

## 使用方法

### 四次发作的形态(先认症状,再对处方)

#### 形态 1:上板跑的是旧位流 —— 现象刚好"像功能坏了"

`dac_1220` 驱动 DAC1220,**输出始终 0 V**。模型把票押在"引脚接错"上,
做了完整的引脚核对(结论:引脚全对)。

**真根因是用户自查出来的**:

> 「刚刚应该是没有及时更新烧录的旧程序一直在 0v,现在正确了」
> —— 重新烧录当前 `.bit` 后,板上输出正常。

**为什么难发现**:旧位流的**行为**就是一个"正常的但过时的设计",
它不会报错,只会输出一个看起来像 bug 的结果。
⇒ **上板现象与静态分析矛盾时,先确认"板上跑的是哪一版程序"。**

**可用的排除手段(以及它的边界)**:

```bash
# 文件级排除:比较 io.xdc / 报告 / .bit 的时间戳先后
io.xdc 09-20 22:12  →  qrs.bit 09-20 22:28   ✅ 位流晚于约束
```

> ⚠️ **时间戳法只能排除"忘了重跑综合",不能证明"板上那份与本地这份相同"。**
> `scp` 之后本地文件没再改动,也**不能**推出板上那份没被覆盖。
> 严格说法:这只证明"本地这份没变"。

#### 形态 2:配置文件的文本搜索 ≠ 工具已回读

删掉 3 个冗余 `.v` 后,模型用 `grep -c <名> qrs.xpr` 查到 **0 处**,
就宣布"没有悬挂引用"。

**实际**:`remove_files` 之后的 `close_project` **并没有把改动落盘**,
`.xpr` 里那三条 `<File Path="$PSRCDIR/sources_1/new/*.v">` **一直都在**。

**怎么暴露的**:**不是靠模型自查**,而是**下一次会话跑综合时 Vivado 自己报出来的** ——
开工程即打 3 条

```
CRITICAL WARNING: [Project 1-19] Could not find the file '…'
```

**根因**:把**文本搜索**当成了**验证**。`grep` 只能证明"文件里没有这个字符串",
证明不了"Vivado 加载工程后不引用这个文件"。**工具的语义边界没对齐。**

**修法**:重做一遍,并**用 md5 坐实落盘**(`4ea53826bf8c…` → `6d417373ae9c…`),
再**重跑综合**确认那 3 条 CRITICAL WARNING 消失。

#### 形态 3:BD 的模块引用缓存过期 —— **症状是"没有症状"**

给 `cv_sys.v` 加了 41 根 `M_AXI` 端口后,在 BD 里 `delete_bd_objs` + `create_bd_cell`
重建 `cv_sys_0`,预期新端口自动出现。

**结果:一个 `m_axi` 引脚都查不到,而且没有任何报错。**

**怎么发现的**:`get_bd_pins /cv_sys_0/*` 的输出里没有 `m_axi`,
但 `cv_sys.v` 文件里的端口明明写着。
⇒ 「**文件里有、BD 里没有、且不报错**」这个组合本身就说明中间夹着一层缓存。

**踩到的第二个坑**:Vivado 官方的 `update_module_reference` 命令**存在但不可用** ——
不带参数、`-quiet`、绝对路径、`current_bd_design` **四种写法全部返回 `rc=1` 且错误信息为空**
(Vivado 2025.2 批量模式)。

**真因**:缓存目录

```
<proj>.gen/sources_1/bd/mref/cv_sys/component.xml
```

**时间戳早于本次 RTL 改动**(那次是 `10月 1 17:04`,正是上一次打开 BD 的快照)。

**修法**:

```bash
rm -rf <proj>.gen/sources_1/bd/mref/cv_sys \
       <proj>.runs/synth_1/.gen/sources_1/bd/mref/cv_sys
# 然后再 delete_bd_objs + create_bd_cell ⇒ /cv_sys_0/M_AXI 出现,41 根引脚
```

> ⚠️ **这一条只在下次改端口时才暴露,而且不报错,只会让 BD 拿旧端口表干活。**
> ⇒ 应固化为**改 RTL 端口后的标准动作**。

#### 形态 4:`xelab -R` 在编译失败时**回放上一轮 PASS 输出**

测试台有两处编译期错误(声明成 `reg` 却用 `assign`;标识符使用先于声明)。
修完第 2 个错误重跑,`xelab -R` **打印出了上一轮的 PASS 输出** ——
因为编译根本没成功,跑的是**旧的可执行文件**。

**之所以没被糊弄过去**:模型注意到

> **新加的那一行「ARLEN 越界」没出现在输出里。**

⇒ `rm -rf xsim.dir` 重来。

> **「输出比预期少一行」和「输出报错」一样是信号,而且更隐蔽。**
> **判据 = 比对输出行数,不是比对有没有 "PASS"。**

---

### 通用处方

| 动作 | 做法 |
|---|---|
| **改完让工具自己回读** | 关闭再重开工程 / 重跑一次 / 读报告原文 —— **不要用 grep 配置文件代替** |
| **确认产物真的换了** | 用 md5 或时间戳**同时**记录**输入与输出**;位流要 `md5sum` 板上那份 |
| **清缓存** | 端口/接口定义改动后,清 `mref/` 一类的引用缓存 |
| **判据看行数** | 仿真/构建的输出,**比对行数与关键新增行**,不只看有没有 PASS |
| **引用数字当场读文件** | 不要凭"我记得刚看过"复用报告里的数字(本项目因此写过两版读数) |

---

## 失效条件

- ⛔ **`grep` 配置文件当作"改动已生效"的证据** —— 语义边界不对齐。
- ⛔ **只看"有没有 PASS"** —— 编译失败时的回放输出也是 PASS。
- ⛔ **用文件大小判断"改了没"** —— 见 `skill/measurement-instrument-can-be-wrong/`。
- ⛔ **改了 RTL 端口就直接重建 BD cell** —— 会拿到过期端口表,且不报错。
- ⚠️ **时间戳法的边界**:只能排除"忘了重跑综合",**不能证明**板上那份与本地一致。
- ⚠️ **`update_module_reference` 不是可靠兜底**:Vivado 2025.2 批量模式下会静默失败。

## 已验证的效果

| 形态 | 结果 | 证据 |
|---|---|---|
| 旧位流 | 重新烧录后**板上输出正常**;三点电压与预期表一致 | `LLM-012`(用户实测) |
| `.xpr` 残留引用 | md5 `4ea53826…` → `6d417373…` **坐实落盘**;重跑综合确认 3 条 CRITICAL WARNING **消失** | `LLM-021` |
| BD mref 缓存 | 清缓存后 `/cv_sys_0/M_AXI` **41 根引脚全部出现**;位流后续上板跑通 | `LLM-031` |
| `xelab -R` 回放 | 发现方式 = **新增行缺失**;`rm -rf xsim.dir` 后结果正确 | `LLM-031` |

⚠️ **本技能包的一条诚实记录**:形态 2 的纠错**不是模型自己发现的**,
是**下一轮综合时工具报出来的**。模型当时在自己的结论上
**没有加"待 Vivado 回读确认"的限定词** —— 这正是本技能存在的理由。

## 来源

1. **`LLM-012`(2026-09-19)** —— 上板 0 V,根因是烧了旧程序。
   同轮还有一条同型:模型把**加 ILA 之前**那份实现报告的数字写进了文档
   (`布线 246/246`、`DRC 仅 1 条`),而当时盘上已是加 `ila_0` 之后的新报告
   (实际 `2817/2817`、`DRC 无 Error`)。发现方式:**写完之后回读原始 `.rpt`**。
   ⇒ **引用报告数字时必须当场读文件。**
2. **`LLM-021`(2026-09-25)** —— `.xpr` 残留引用。
   根因是**把文本搜索当成了验证**;与 `LLM-003` / `LLM-012` / `LLM-018` 同型:
   **拿局部观察当完整结论。**
3. **`LLM-031`(2026-10-02)** —— 一次会话内**两个形态**:
   BD mref 缓存过期(静默),`xelab -R` 回放旧结果(伪装成成功)。
4. **`LLM-005`(2026-09-15)** —— 同母题的早期形态:Vivado 编辑器不自动重载外部修改,
   用户看到的是旧文件;并警告**不要在该标签页 Ctrl+S**(会把新版覆盖回旧版)。

> 💡 **这四次发作分布在 4 个不同工具上**(烧录器 / 工程文件 / BD 缓存 / 仿真器),
> 说明这不是某个工具的 bug,而是**一类系统性风险**:
> **凡是"源文件 → 中间产物 → 最终结果"的链条,中间层都会撒谎。**
