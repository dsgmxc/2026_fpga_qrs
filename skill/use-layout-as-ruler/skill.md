# use-layout-as-ruler

> 当观测者是人(用户 / 测试员)时:**别用他的手当量具,用被测对象自己的几何当量具。**
> 把问题从"**偏移多少**"改成"**有没有越过某个已知边界**"。

## 适用范围

- 任何**依赖人眼 / 人手做观测**的验证:屏幕显示、触摸坐标、机械位置、按键反馈、声光指示。
- 特别适合**远程协作**场景:模型看不到设备,只能靠用户的一句话回报 ——
  **问法设计得好不好,直接决定那次回报有没有信息量**。
- 不限于硬件:任何"让人看一眼然后告诉我"的验收动作。

---

## 使用方法

### 一、先算人这个量具的分辨力

**手的瞄准重复性大约是 ±10 px 量级。**
在屏幕上,这个数和很多"要测的效应"**同量级** —— 一旦同量级,这套量具就**没有分辨力**。

**事故**:用户报「画面整体稍微向右平移」。模型画了 5 根已知位置的竖条,
让用户逐条**点中心**,读回触摸坐标:

| 竖条 | 帧缓存中心 | 点到 | δ |
|---|---|---|---|
| 红 | 131.5 | 140 | +8.5 |
| 绿 | 323.5 | 339 | +15.5 |
| 白 | 515.5 | 523 | +7.5 |
| 黄 | 707.5 | 711 | +3.5 |
| 蓝 | 899.5 | 900 | +0.5 |

δ **单调递减** ⇒ **看着像"约 1.4% 的欠标定"**,模型几乎就要这么写。

**自己推翻它的证据**:同一条蓝条,**上一轮量到 +10.5,这一轮 +0.5** ——
同一条、同一位置、同一个人,**两次差 10 px**。
而绿条那次的 y=285,其余四条都在 294~304 ⇒ **它是瞄歪的,不该进拟合**。

> ⇒ **手指瞄准的重复性就是 ±10 px,与要测的效应同量级。**
> **这套量具没有分辨力,不应该继续解读它。**

### 二、换问法:把"量多少"改成"越没越过界"

判据**不从人身上取,从被测对象自己的布局里算出来**:

```
首页两张大卡:各 453 × 156
左卡  x ∈ [48, 501]
右卡  x ∈ [523, 976]
中间缝隙 = 523 − 501 = 22 px      ← 这个 22 是 UI 框架自己算的,不是量的
```

**问法**:

> 按住 x ≈ 512(缝隙正中),看哪张卡进入按下态。
> - 右卡亮 ⇒ δ > +11
> - **都不亮 ⇒ |δ| ≤ 11**
> - 左卡亮 ⇒ δ < −11

**用户回复:「两张都不变」⇒ |δ| ≤ 11 px,收工。**
**一次按压。** 缝隙边界由被测系统自己确定,手指偏 10 px 也还在缝里。

> ⇒ **同一个问题,换一个不需要人量尺寸的问法,立刻有解。**

### 三、给观测者一个**能一次区分多种故障**的图案

"屏亮了没有"这种问法只能得到一个是/否,**分不出"缺一块"**。

**正确做法**:设计一个多元素图案,**一次回报同时排除多个假设**:

```
整屏绿(底色) + 中间红横带(行 290–309) + 左上白块(行 40–119 / 列 40–199)
```

用户回一句"三元素全对",**一条信息同时否掉**:

| 观测 | 排除的假设 |
|---|---|
| 三元素全对 | 全通 |
| **少了角块** | 行内偏移 |
| **全黑** | 无数据 |
| **底色变了(绿→红/蓝)** | **R/B 位序交换**(红横带顺带做了这项检查) |

对照:"人眼看 LED 判断写成功"属于**一层不可靠转述** ——
本项目在同一天把它换成了 **PS 侧独立读回复核**(厂商 RTL 写自增数,按键前是 DTB 头、
按键后是 `1…16`)。

### 四、同一原则的其他形态:**硬件寄存器当独立观测者**

让"寄存器读数"和"人眼"成为**两个独立观测者**,一致才下结论:

```
axi_or_nz = 1 / px_or_nz = 1 / rresp = OKAY     ← 观测者 A:硬件寄存器
用户目视三元素全对                                ← 观测者 B:人
```

**两个独立观测者一致** ⇒ 结论强度远高于任一单独使用。

## 失效条件

- ⛔ **手指当量具** —— 分辨力 ±10 px,很多效应做不到这个量级。
- ⛔ **从人的回报里反推数值** —— 用户的量级感和测试的量级可能根本对不上。
  (本项目用户后来说「偏移严重多了」,而模型的测试只排得掉 δ≥8。)
- ⛔ **不声明分辨力就下结论** —— 8 px 的白条**只能排除 δ ≥ 8**,
  排不掉 3 px;而模型把它当成了 δ≈0 的证明。
- ⛔ **问"亮没亮"这类布尔问题** —— 信息量太低,分不出故障类型。
- ⛔ **不给观测者多元素图案** ⇒ 一次只能排除一个假设,要来回好几轮。

## 已验证的效果

| 项 | 结果 | 证据 |
|---|---|---|
| 用布局当尺子定触摸偏移 | ✅ **一次按压**得出 **\|δ\| ≤ 11 px**,问题结案 | `LLM-037` |
| 手当量具(反例) | ❌ 两次读数差 10 px;δ 数列看着像 1.4% 欠标定,实为噪声 | 同上 |
| 多元素图案当观测者 | ✅ 用户回"三元素全对",一条信息否掉行内偏移假设 | `LLM-036` |
| 硬寄存器 + 人眼双观测者 | ✅ 显示通路端到端判定 | 同上 |
| 帧缓存内容对称性 | ✅ `/dev/mem` 读回 1024×600×2 RGB565,顶栏满宽 x=0..1023、卡片中心 511.5 | `LLM-037` |

> 📌 配套的一条:**用户的"叫停"是有效信号。**
> 本次是用户说「这完全没达到之前我看到的那种画面漂移的程度,感觉只是手指误差而已,
> **这样测没什么意义**」之后,模型才换的量具。
> **用户说"这个测法没意义"时,不要解释测试的有效性 —— 换一个测法。**

## 来源

**`LLM-037`(2026-10-03)** —— 同一轮里模型**错了两次**:

1. 把 ±10 px 的噪声当成 1.4% 的标定误差,差点写成结论(自己发现并推翻)。
2. 做的"边缘判定"**没有声明分辨力**,却当成 δ≈0 的证明。

两次都出在同一个地方:**没有先算量具的分辨力,就开始解读它给出的数。**

配合 **`LLM-036`** 的"多元素图案"与"双观测者"两条正面做法。

**相关技能**:`skill/measurement-instrument-can-be-wrong/`(本技能是它的正面解法;
那条判据「如果一个数字要写进结论,它必须**先有已知分辨力**」即出于此)。
