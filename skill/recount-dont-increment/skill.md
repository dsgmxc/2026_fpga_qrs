# recount-dont-increment

> **汇总类数字(合计、计数、覆盖率)一律现场重跑,不做"上一版 + 增量"的算术。**
> 增量算术会让你**同时继承别人的错误基线、又叠加自己的增量** ——
> 你不只是可能算错一行,是**两头都不对**。

## 适用范围

- 任何有"**累计数**"的文档 / 索引 / 仪表盘:技能条目数、记录总数、
  通过率、覆盖率、缺陷数、代码行数。
- 尤其命中:**多轮增补的长文档**、**由人手工维护的汇总行(footer / 总计)**、
  **"上一版写着 N,我这版加 1"** 的写法。
- 与项目领域无关 —— 只要有"总数"就有这个坑。

## 使用方法

### 判据:凡是要写进文档(或当成结论说出来)的合计,必须是**跑出来的**,不是**算出来的**

```bash
# ⛔ 反面:读上一版的汇总行,然后在脑子里 +1
# ✅ 正面:现场跑【三条互不相同】的路径,对得上才算数

ls -1 report/llm-log/LLM-*.md | wc -l                  # ① 文件系统
grep -c '^| \[LLM-' report/llm-log/INDEX.md            # ② 索引表行计数
awk '…解析每一行…' report/llm-log/INDEX.md             # ③ 解析脚本自己的合计
```

三条路径**互相独立**(目录列举 / 行计数 / 字段解析),
**对得上**才说明数字可信;**对不上先怀疑自己的解析脚本**,而不是先怀疑计数器。

### 事故复盘

本项目 `report/llm-log/INDEX.md` 的 footer 一路写着 `合计=64`。
写新记录时,我按"64 + 我这一行 = 65"**手写**了一个数。

**实跑之后是 69。** 差的不是 1 行,是 **4 行**:
表里早就有 **68** 行,而 footer 一路写 **64**(少记 4 行,
且 `✅` 虚少 3、`⚠️` 虚少 1)。

三处对账**全部**支持 69:

```
① ls -1 … | wc -l          = 69
② grep -c '^| \[LLM-'      = 69
③ 解析脚本 合计            = 69   (✅=24  ⚠️=44  ❌=0  无标记=1)
   编号 001–069 连续无缺口
```

**改法**:以实跑为准,**并把这次漂移记下来**(与更早那次同类漂移并列),
不静默改数字 —— 静默改掉会让下一个读的人以为是同一份基线。

### 附带产出:对账会抓出**口径**歧义

同一手法在另一处抓到:某账本计数器的清零点在**进程初始化**而不是**每轮开始**,
所以它是**进程累计**(本轮实为 `223 − 199 = 24` 次,而不是账面上的 223)。
⇒ **数字跑对了,口径仍可能不是你以为的那个。对账之前先确认口径。**

## 失效条件

- ⛔ **不要因为这个判据就每次全量重跑大脚本** ——
  它约束的是"**要写进文档 / 要当结论说出来**的合计",不是每次聊天。
- ⚠️ **三条路径必须真的独立**。若工具把行数写进缓存、脚本再读缓存,
  那就等同于一条路径。
  (参见 `skill/measurement-instrument-can-be-wrong/` 判据 2
  「**证据条数 ≠ 证据强度,独立性才是**」。)
- ⚠️ **对账只能证明"计数过程"自洽,不能证明"计数定义"正确**。
  定义错了,三条路径会**一致地**给出同一个错数 —— 那时要靠**人工读几行原始记录**兜底。
- ⚠️ 文档里出现过的手写数字**不构成基线**:发现 footer 与实跑不符时,
  **以实跑为准**并加漂移说明,**不要**为了"保持一致"去回头改历史记录里的数。

## 已验证的效果

| 项 | 改前 | 改后 |
|---|---|---|
| `INDEX.md` footer 合计 | 手写 **65**(沿用错误的 64 基线) | 实跑 **69**,附漂移说明 |
| 三处独立对账 | 未做 | 全部对齐(69 / 69 / 69,编号无缺口) |
| 分组表 vs 独立账本(另一处) | 分组表 32 次 | 账本 **36** 次 ⇒ 查出两处归组错误后重算,逐字吻合 |

- 后一项同时抓出**两类**归组错误:把收尾的 `✓ 重采第 N 次自洽` 行误当拒收行计、
  以及**漏了一整条腿**(COSS 的两组),后者还推翻了我先前"A 类灾难性坏字
  只在 CRSS 高压端"的断言。
