### 与推荐结构的差异

与指南 3.3.5.4 的推荐结构相比,本项目**新增 3 个目录**,其余目录与推荐结构一致:

| 新增目录 | 理由 |
|---|---|
| `docs/` | 集中存放**器件与硬件的接口规格文档** —— 芯片命令与时序常量(如 DAC1220 的命令字、帧格式、`tXIN` 时序窗口)、开发板扩展口引脚表、量程与传递关系标定记录等。这些是设计报告「软硬件划分依据与接口设计」一节的**原始依据**,体量与更新频率都独立于报告正文,与 `report/` 混放会使报告正文被规格表淹没,也不便于脚本引用。<br>另收录 **`dev_workflow.md`(开发流程手册)** —— 串口连接、直连网线配置、`scp` 传输、板上运行命令与实测踩坑记录,即**从零复现本项目所需的操作步骤**(对应必做点 M5 / 加分项 B5) |
| `src/constrs/` | 引脚约束**单独成目录**而非并入 `src/rtl/`。理由:约束与 RTL 的**修改时机和验证方式都不同**(改端口 ⇒ 两个都要动;改球号 ⇒ 只动约束),且本工程实际存在**两个 `.xdc` 但只有一个生效**的陷阱,**混放会让人以为它们是平级的** |
| `src/c_ui/` | PS 侧界面**用 C 写**(LVGL),与 `src/python/` 的 Python 编排代码是**两个进程**、两套构建方式(C 侧在板上 `make`)。放进 `src/python/` 会造成"Python 目录里躺着 C 工程"的误导 |

> ⚠️ `docs/dev_workflow.md` 中的**串口参数与启动跳帽**引自《领航者ZYNQ之PYNQ开发指南_V3.2》p22,属**外部资料转述**;
> 其余条目(网络配置、`sudo -E` 用法、踩坑记录)均来自本项目**板上实测**,原始证据见 `report/measurements/`。

### ⚠️ `sim/logs/` 当前为空 —— 这是**有意**的

`sim/` 收录的是**仿真平台本身**(`tb_spi_master.v` / `tb_dac_1220.v` / `tb_adc_9833.v`)
与**整理后的验证报告**(`spi_master_verification.md` / `dac_1220_verification.md` / `adc_9833_verification.md`)。
**仿真器输出的原始 `.log` 没有入库** —— 验证报告里已经逐项引用了它们的关键行(含变异测试的
FAIL 行),原始文本属于"跑一次就能再出来"的中间产物,不入库以免把证据淹在噪声里。

⇒ `sim/logs/` 目录**保留占位为空**。若要连同原始日志一起提交,把它们从工作区拷进来即可,
`.gitignore` **不会**拦截(`*.log` 未做全局忽略,原因见 `.gitignore` 内的说明)。

## 其他

本仓库的文本文件**均为纯文本**(Markdown / 源码 / CSV),可直接阅读。
唯一的二进制是 `board/qrs.bit`(位流)及其配套 `board/qrs.hwh` —— 两者**必须成对更新**,
PYNQ 的 `Overlay()` 需要与位流**同基名**且**匹配版本**的 hwh 才能正确解析。
