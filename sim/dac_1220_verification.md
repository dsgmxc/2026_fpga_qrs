## 1. 验证目标

`dac_1220` 的职责是:上电后按手册的 **SCLK Reset Pattern** 复位芯片 → 发**自校准**命令序列 →
置 `init_done` → 此后每收到一个 `set_in` 脉冲,把 20 位码值通过 **DIR 寄存器**写进去。

本测试台只回答一件事:**这些动作在引脚上做对了没有。**
判据全部来自 TI 手册 SBAS082G,不来自 RTL 源码(见 §2)。

---

## 2. 方法:两个刻意的设计选择

### 2.1 只观察引脚,不看 DUT 内部

测试台把 `dac_sclk` / `dac_mosi` / `dac_cs` **当成外部示波器探头**,只做三件事:

1. 数 SCLK 边沿、量相邻边沿之间的间隔(用 `gap_cnt` 计数);
2. 在**下降沿**采样 `dac_mosi` 移位进 `sh`;
3. 当 SCLK 静默超过 `GAP_TH` 拍时,把 `sh` 当作一个完整字节推出。

**不窥探 DUT 内部信号。** 这样测出来的就是「**DAC 芯片真正会看到的东西**」。
(前一版测试台用 `force` 脚本 + VCD 波形解码,量具本身出过两次错 —— 见 `report/llm-log/LLM-009.md`。)

### 2.2 期望值全部来自手册,不来自 RTL

| 判据 | 出处 |
|---|---|
| 复位图案四窗口取值 | 手册 Table 5(换算基准 `tXIN = 406.90 ns`) |
| 命令字节格式(bit7 R/W、bit6:5 MB、bit3:0 ADR) | Table 6 / Table 7 |
| 校准序列 = `24 20 A0 05 A1` | 本项目决策 D19(多字节命令)+ Table 11 寄存器地址 |
| `DIR = code20 << 4` | **手册 p14「left justified」+ Table 9 算例** |
| CMR 各 bit 含义 | Table 13 |
| `t14 ≥ 41 tXIN` | 手册 Table 4 |

> ⛔ **这条是本报告最要紧的方法论**:2026-09-18 那版判据的期望值**是从 RTL 里抄的**,
> 于是「波形与期望一致」**恒真**,通过了也不含任何信息 —— 它**漏掉了 DIR 三字节切片的真实缺陷**。
> **判据的来源必须独立于被测物**,详见 `report/llm-log/LLM-010.md`。

### 2.3 寄存器比对与字节切分解耦

测试台内部**实现了一遍手册 Table 6/7 的命令解码器**:看到 `0x40` 就知道后面跟 3 个字节、
目标是 ADR=0,于是把三个数据字节拼成 `DIR[23:0]`,再和 `code << 4` 比。

**这意味着判据不预设"字节该怎么切"** —— 无论 RTL 如何切,拼出来的 DIR 必须等于 `code << 4`。
缺陷正是被这一条抓出来的。

## 3. 结果

### 3.1 字节流(核心结论)

激励:等 `init_done` 后打两个 `set_in` 脉冲,`code` 分别取刻意非回文、且**中间位段非零**的值。

| 帧 | `code` | 实测字节流 | 期望 | 判定 |
|---|---|---|---|---|
| 校准 | — | `24 20 A0 05 A1` | `24 20 A0 05 A1` | PASS |
| 1 | `20'h12350` | `40 12 35 00` | `40` + `code[19:12]` + `code[11:4]` + `{code[3:0],4'b0}` | PASS |
| 2 | `20'hABCDE` | `40 AB CD E0` | 同上 | PASS |

DIR 拼接结果:`24'h123500` / `24'hABCDE0`,与 `code << 4` **逐位一致**。

> 📌 这两个 `code` 是**刻意挑的**:`code[11:4]` 在两者中都非零。若沿用 `code = 0x80000`
> (旧测试台的做法),三个字节里有两个是 `0x00`,**切片错了也看不出来**。

### 3.2 复位图案(手册 Table 5 窗口)

| 段 | 实测 | 窗口 | 判定 |
|---|---|---|---|
| `t16` | 260.02 µs | 208.32 – 325.52 µs | PASS |
| `t17` | 10.02 µs | ≥ 4.08 µs | PASS |
| `t18` | 570.02 µs | 416.66 – 732.42 µs | PASS |
| (低段) | 10.02 µs | 手册未单列 | — |
| `t19` | 900.02 µs | 833.32 – 976.56 µs | PASS |
| `dac_cs` | 复位后恒为 0 | 手册 p11 `(CS tied low)` 路径 | PASS |

### 3.3 寄存器语义(按 Table 6/7 解码后重建)

CMR 实测 `16'h20A1` / 期望 `16'h20A1`,逐位核对:

| bit | 值 | 含义 | 判定 |
|---|---|---|---|
| 15 `ADPT` | 0 | 自适应滤波开(默认) | PASS |
| 14 `CALPIN` | 0 | 校准期间输出关(默认) | PASS |
| 13 (保留) | 1 | Table 13:「Write '1' to this bit」 | PASS |
| 7 `RES` | 1 | 20 位模式 | PASS |
| 5 `DF` | 1 | 直通二进制 | PASS |
| 1:0 `MD` | `01` | 自校准模式 | PASS |

> 厂商 STM32 例程此处高字节写 `0x00` —— **本项目写 `0x20` 是对的,例程不合规**。

### 3.4 其他时序实测

| 项 | 实测 | 手册要求 | 判定 |
|---|---|---|---|
| `init_done` 时刻 | 2423.93 µs | 必须在**最后一个校准字节之后**(不能在校准期就置位) | PASS |
| SCLK 半周期 | 256 拍 = 5.12 µs → **97.66 kHz** | `f_SCLK ≤ 246 kHz` | PASS |
| SCLK 半周期抖动 | 0 拍 | — | PASS |
| 字节间隔 `t14` | 1791 拍 = **35.82 µs** | ≥ 16.68 µs | PASS(+115% 余量) |

**合计:21 项检查,PASS 21 / FAIL 0。**

## 4. 变异测试:证明判据"能失败"

「测不出失败的测试通过」没有信息量(本项目在 `sed` 静默失配事件上栽过,见 `LLM-005`)。
因此把 RTL 改回**修正前的写法**重跑:

```verilog
// 变异(2026-09-19 之前的写法)—— 丢弃 code[11:4]
code_in_d[1] <= code[19:16];
code_in_d[2] <= code[15:8];
```

| | 结果 |
|---|---|
| `tb_dac_1220_fixed.log` | **21 PASS / 0 FAIL** |
| `tb_dac_1220_mutant.log` | **17 PASS / 4 FAIL** —— 4 项**全部落在 DIR 判据上** |

变异体实际发出 `40 01 23 00` / `40 0A BC E0`(期望 `40 12 35 00` / `40 AB CD E0`)。
**判据具备失败能力,§3 的通过结论有效。**

---

## 5. 这个缺陷是什么,影响多大

| 项 | 内容 |
|---|---|
| **缺陷** | DIR 三个数据字节按 `code[19:16] / code[15:8]` 切,丢弃了 `code[11:4]` 这 8 位 |
| **正确** | `code[19:12] / code[11:4] / {code[3:0],4'b0}`(手册 p14 + Table 9 + 例程三处互证) |
| **有效码值** | `code & ~20'h0FF0` |
| **最大偏差** | 4080 码 ≈ **0.39% 满量程**(±10 V 模块上约 78 mV) |
| **有效分辨率** | 20 位 → **约 12 位** |
| **为什么难发现** | 输出**仍然单调**,逐点看电压表/示波器**看不出来** |

## 6. 未覆盖项(引用本报告时必须一并说明)

- ⚠️ **三个毫秒级等待(`PWR_WAIT` / `CAL_WAIT_T` / `SETTLE_WAIT`)被参数压缩**
  → 验的是**协议层与状态机转移**,**"等多久"本次没有验证**(真值只有手册出处)。
- ⚠️ **未综合、未做时序分析、未上板** → **M03 / M04 / M13 仍无任何证据**。
- ⚠️ 未测:SDIO 读回路径(设计上就没有,见决策 D18)、`set_in` 恰好打在建立窗口内的边界行为。
- ⚠️ 时钟按 **50 MHz** 标定;若实际挂到别的时钟域,§3 的全部时间数字要重算(手册窗口是绝对时间)。
