| 项 | 内容 |
|---|---|
| **日期** | 2026-09-15 |
| **被测对象** | `spi_master.v`(AD9833 激励源配置用 SPI 主机,**用户自写**) |
| **测试平台** | `sim/tb_spi_master.v` |

## 1. 验证目标

`spi_master` 的职责是向 AD9833 写 16 bit 配置帧。本测试台要回答三个问题:

1. **发送通路**——`tx_data` 是否被逐位、按正确位序送上了 `mosi`?
2. **接收通路**——`miso` 上的数据是否被正确采样、组装成 `rx_data`?
3. **协议时序**——`sclk` 边沿数、`cs` 行为、`busy` 握手是否合法?

> **注意**:AD9833 是 **写-only 三线接口(无 MISO)**,接收通路在上板时用不到。
> 之所以仍然验证,是因为 `spi_master` 是通用模块,且接收通路的存在能让"发送通路"
> 被独立交叉验证 —— 一个方向错了不会两个方向同时掩盖。

---

## 2. 测试平台结构

```
tb_spi_master
├── 时基与复位            100 MHz,复位 10 拍
├── DUT                   spi_master(参数化:CPOL / CPHA / MSB_FIRST)
├── 从机模型              ★ 独立实现,不引用 DUT 内部信号
│     · 按 SPI 模式语义推导采样沿/换位沿
│     · MOSI 移位寄存器 → slave_rx
│     · slave_tx(预设图案)→ MISO
├── 记分板                check() 任务,自动 PASS/FAIL 计数
└── 激励                  6 帧 + 边沿计数 + 看门狗
```

**从机模型的独立性**是这套测试有效性的前提。它只依据 SPI 模式语义实现,
**不碰** `bit_cnt` / `state` / `t_flag` 等 DUT 内部信号 —— 否则两边同错会同过。

**两个方向独立断言**(每帧 4 项):

| 断言 | 验证的通路 |
|---|---|
| `slave_rx_cap === pat_tx` | 发送通路(MOSI) |
| `rx_data === pat_rx` | 接收通路(MISO) |
| `rcv_cnt === DATA_WIDTH` | 从机确实收满 16 位 |
| `drv_cnt === DATA_WIDTH` | 从机确实发满 16 位 |

帧末另查 `sclk_edges === 6 × 2 × DATA_WIDTH`(32 沿/帧)。

## 3. 测试图案的选取依据(经变异测试实测,不是猜的)

初始用过 `16'hA5A5` / `16'h8001`,理由是"0/1 交替对位序敏感"。**这是错的**——
`A5A5` = `1010 0101 1010 0101`,**倒过来还是自己(回文)**;`8001` / `0000` / `FFFF` 同理。
位序反转的变异体实测**只能被这组图案抓到 2/6 帧**。

改用非回文 / 单比特图案后,同一变异体抓到 **5/6 帧**:

| 图案对(master 发 / 从机回) | 作用 |
|---|---|
| `0001` / `8000` | 单比特在两端 —— 位序反了必错 |
| `8000` / `0001` | 反向再来一次 |
| `AAAA` / `5555` | 交替但**非回文**(`AAAA` 倒过来是 `5555`) |
| `1234` / `5678` | 一般图案 |
| `0000` / `FFFF` | 只证明"确实发了",**不测位序** |
| `5678` / `1234` | 连续两帧 —— 抓"只能发一帧" |

**两个图案必须不同**,否则 MISO 断路也会判 PASS。

## 4. 结果

### 4.1 配置矩阵

| # | CPOL | CPHA | MSB_FIRST | 检查项 | 结果 |
|---|---|---|---|---|---|
| 1 | 0 | 0 | 1 | 25 | ✅ ALL PASS |
| 2 | 0 | 0 | 0 | 25 | ✅ ALL PASS |
| 3 | **1** | 0 | 1 | 25 | ✅ ALL PASS |
| 4 | 0 | **1** | 1 | 25 | ✅ ALL PASS |
| 5 | 1 | 1 | 1 | 25 | ✅ ALL PASS |

> **为什么四种模式全测**:AD9833 实际使用哪种模式须以数据手册为准。
> 四种全过之后,**手册怎么说不影响结论** —— 无论最终接的是哪种模式,都有仿真支撑。

### 4.2 变异测试 —— 证明测试平台"会失败"

只会通过的测试台等于没测。向 `spi_master.v` 注入 7 个故意缺陷:

| # | 注入的缺陷 | 结果 | 说明 |
|---|---|---|---|
| 1 | `TH` 少一个半周期 | ✅ 抓住(6 FAIL) | 边沿计数 + 数据双报 |
| 2 | `mosi` 位序反转 | ✅ 抓住(5 FAIL) | 换图案前只能抓 2 帧 |
| 3 | `r_flag` 早一拍 | ✅ 抓住(5 FAIL) | 接收位号错 |
| 4 | DUT 的 `CPOL` 与从机不一致 | ✅ 抓住(5 FAIL) | CPOL 维度有效 |
| 5 | DUT 忽略 `MSB_FIRST`(`mosi` 恒 MSB 先发) | ✅ 抓住(5 FAIL) | MSB_FIRST 维度有效 |
| 6 | DUT 完全忽略 `CPHA`(采样/移位/位号全按 CPHA=0) | ✅ 抓住(11 FAIL) | CPHA 维度有效 |
| 7 | DUT 的 `CPHA` 只在采样沿失效 | ✅ 抓住(6 FAIL) | 局部失效也能抓 |

**7/7 全部被抓。**

### 4.3 `SPI_HALF_T` 边界扫描

从机模型的边沿检测比真实沿晚 1 拍,输出再寄存 1 拍 → MISO 在下降沿后 **2 拍**稳定;
而 DUT 在下降沿后 **`SPI_HALF_T − 2`** 拍采 `miso`。
→ **余量 = `SPI_HALF_T − 4` 拍**。

| `SPI_HALF_T` | 结果 | 余量 |
|---|---|---|
| 2 | ❌ FAIL | −2 |
| 3 | ❌ FAIL | −1 |
| 4 | ⚠️ ALL PASS | **0** ← 靠 delta 周期侥幸,上板必踩线 |
| 6 | ✅ ALL PASS | 2 |
| 10 | ✅ ALL PASS | 6 ← **当前工程取值** |

**结论:该模块要求 `SPI_HALF_T ≥ 5`,工程取值 10 有 6 拍余量,安全。**
(此边界是**从机模型**引入的仿真约束,不是 `spi_master` 本身的缺陷 ——
但真实从机器件同样需要建立时间,该余量在硬件上依然要重新核算。)

## 5. ⚠️ 本结果**不能**证明什么

**这是本报告最重要的部分。**

| 未覆盖 | 说明 |
|---|---|
| ❌ **上板** | 引脚约束、IOB、板级走线**完全未验证**。M13 要的是上板实测,纯仿真不算 |
| ❌ **综合与实现** | 未跑综合,无资源占用、无时序收敛数据(M03 无证据) |
| ❌ **时序分析** | 纯功能仿真,无 `set_input_delay`、无建立/保持检查 |
| ❌ **真实器件** | AD9833 未建模。其真实 `tSU` / `tHD` 是否满足**必须核数据手册** |
| ⚠️ **从机模型的可信度** | 它是"第二个实现",不是 AD9833 的模型。若与 DUT 同错会双双通过 —— 已用 §4.2 的变异测试对冲,但不能完全排除 |
| ⚠️ **已知盲区** | "DUT `CPHA=1` + 从机 `CPHA=0`" 这种**模式错配**组合会假通过(时序巧合)。匹配模式下无此问题,但该盲区确实存在 |
| ⚠️ **`CS` 保持时间** | 最后一个 `sclk` 沿到 `cs` 拉高只有约 `SPI_HALF_T + 1` 拍(≈110 ns @100 MHz)。**AD9833 手册对这段时间有最小值要求,须核对** |
