## 四、已知陷阱

### 陷阱 1 ⛔ 「官方 XDC 里没有这个球号 ⇒ 板上没有这个脚」

**这是错的。** 官方 `NAVIGATOR_ZYNQ_IO.xdc` **只覆盖板载外设**,
扩展口(J3/J4)上的引脚**本来就不在其中**。

开发指南原文:「上表列出了**除扩展口外**,开发板上所有 PL 功能外设所对应的 IO 引脚号,
关于扩展口上的排针所对应的 IO 引脚号,大家可以参考开发板的原理图或者直接查看开发板上的丝印标注。」

**实际后果(2026-09-19 真实发生过)**:
`W13` / `Y14` 在官方 XDC 里叫 `cam_data[5]` / `cam_data[7]`,而 `W15` **在官方表里完全不存在**
→ 模型据此判断「这三个脚是摄像头专用,DAC 模块根本没接到」→ **误判,浪费了一轮排查**。
真相是**这三个脚同时引到了扩展口 J4 的第 32 / 34 / 36 脚**,底板网络名叫 `CMOS_D5` /
`CMOS_D7` / `CMOS_XCLK`(因为也接了摄像头接口),**正点原子把扩展口复用成了摄像头口**。

### 陷阱 2 ⛔ 拿 J3 的引脚表套 J4

两个扩展口的引脚表**不一样**。本文档只录了 J4。

### 陷阱 3 ⚠️ 相邻脚差一位

J4 第 31/33/35 脚分别是 `B34_L4_P` / `B34_L8_P` / `B34_L10_P`(网络名 CMOS_D6 / CMOS_PCLK /
CMOS_PWDN)—— 与第 32/34/36 脚**只差一位**,而且**在另一列**。
数错一列会让三根信号全落到错误的脚上,**现象与"没接"完全相同**。
上板前请**对板上的丝印**再确认一次。

### 陷阱 5 🔴 `constrs_1/new/` 里躺着一个**不再被引用**的 `io.xdc`

**2026-10-07 实测**:`grep -o '[a-z_]*\.xdc' qrs.xpr | sort -u` 只返回 **`led.xdc`** 一个 ——
`io.xdc` **不是"被禁用",是根本没进工程**(`IS_ENABLED = 0` 的说法描述的是更早的状态)。
它现在是**死文件**,但里面的球号与 `led.xdc` **大面积打架**:

| 球号 | `io.xdc`(死) | `led.xdc`(活) |
|---|---|---|
| `U5` | `clk_65m` | 模块空脚(不约束) |
| `V5` / `V7` | (注释里的备选) | `adc_oe_n` / `adc_d[0]` |
| `V12` / `W14` / `V15` | `adc_sync` / `adc_sclk` / `adc_mosi` | `dds_sync` / `dds_sclk` / `dds_data` |

⛔ **不要把它当参考**。要看当前引脚,只有一个来源:`led.xdc`。
⚠️ 顺带更正一条旧记录:那份 `io.xdc` 的 DDS 注释**自己写着**"照 J4 表挑的空闲脚,
**不是从实际接线查来的**" ⇒ 它与用户 2026-10-07 报的 DDS 位置(`V12/W14/V15`)**逐位相同**,
但这**只是碰巧/或用户照它接的**,**不算独立证据**,别引用来"证明接线"。
🗂 该文件曾于 2026-10-05 从交付仓库删除,但 **Vivado 工程里这份仍在** —— 建议归档,但
**不要动工程布局(vivado 工程内删文件属布局动作,归用户)**。

### 陷阱 4 ⚠️ 这些脚同时接到板载摄像头接口

用 J4 的 27–36 脚时,若板上插了摄像头模块,**会与摄像头驱动信号冲突**。
本项目没有摄像头模块,不构成问题;但如果后续要同时用摄像头,必须重新选脚。
