## 1. 一句话

**ADC 采样率固定 65 MSPS(不可调),激励频率只有 10 kHz / 100 kHz / 1 MHz 三档;
解调按「整窗 DFT」做,窗长由激励频率现算,最长的 10 kHz 需要 6500 点
⇒ 采集缓冲从 4096 点加长到 8192 点。**

---

## 2. 为什么采样率固定 65 MSPS

| 项 | 值 | 来源 |
|---|---|---|
| ADC 器件 | **AD9238-65** | 硬件已定;型号后缀 `-65` = **额定最高 65 MSPS** |
| `clk_adc` 基准 | **130 MHz** | MMCM:VCO = 50 × 26 / 1 = 1300 MHz,CLKOUT0 = 130 MHz(与 `clk_axi` 同源) |
| 分频 | `f_s = 130 MHz / max(DIV, 2)` | `adc_capture.v` |
| **DIV** | **2(固定)** | ⇒ **65.0 MSPS** |

- **65 是器件的额定上限,不是随便挑的数。** DIV 取 2 已经贴顶,
  再小(1)会被 `max(DIV,2)` 折回 2 ⇒ **65 MSPS 就是本硬件能到的最高采样率**。
- **为什么不再提供其他档**:采样率与激励频率是两个必须**一起验算**的旋钮。
  旧界面把采样率做成 6 档、激励做成 5 档,却**从没算过组合**——
  65 MSPS + 10 kHz 这种组合在旧窗长下**数学上不成立**(见 §4),
  而界面照旧把它摆出来给用户点。**固定采样率,把可调的自由度收到激励一侧**,
  是让"界面能点的组合 = 数学上成立的组合"的唯一做法。
- **`max(DIV,2)` 的由来**:DIV=1 会让分频器输出 = `clk_adc`,而数据稳定窗的计算
  依赖偶数分频(`PH_OFF` 的合法范围 `[−P/2, P−1−P/2]` 在 P=1 时为空)。
  ⇒ 硬件直接把下限钳到 2,**行为可预期,不靠软件自觉**。

## 3. 解调:整窗 DFT

### 3.1 唯一要求

解调要求**窗内覆盖整数个激励周期**:

```
L · f_e / f_s ∈ ℤ
```

**它不要求 `f_e/f_s` 是无理数的有理逼近,也不要求 `f_s/f_e` 是整数**——
只要窗长 `L` 与两个频率构成整数比即可。满足后:

- **`2f_e` 谐波项被精确抵消**(零点落在 `2f_e`);
- **频谱泄漏为零**(窗的两端相位连续,不需要窗函数)。

### 3.2 窗长怎么现算

把 `f_e / f_s` 约到最简分数 `p/q`(`gcd(p,q) = 1`),则:

```
窗口最小单位  l0 = q
窗内周期数    m  = (L / q) · (f_e / g)      , g = gcd(f_e, f_s)
参考表长度    = L(进表的是 cos/sin(2π·m·k/L),k = 0..L−1)
```

实现上取 `L = ⌊n / q⌋ · q`(不超过采集点数 `n` 的最大 `q` 整数倍),
`m = (L / q) · (f_e / g)`。**表长只跟 `L` 走,与频率比无关** ——
这是 2026-10-08 与"按 `f_s/f_e` 整数倍建表"的旧实现最大的区别。

### 3.3 两道守卫

| 守卫 | 条件 | 挡住什么 |
|---|---|---|
| 窗内至少 1 个整周期 | `L ≠ 0 && m ≥ ADC_DEMOD_MIN_M`(=1) | 窗比一个周期还短,解调无意义 |
| 每周期至少 4 点 | `L / m ≥ ADC_SAMPLE_DEMOD_MIN_N`(=4) | `N = 2` 正好在 Nyquist 上、`N = 1` 混叠到 DC,算出来是噪声 |

## 4. 三档激励与窗长(65 MSPS 下的实际取值)

| 激励 `f_e` | `p/q` | `q` | **窗长 `L`** | **整周期 `m`** | **点/周期** | 一次采集耗时 |
|---|---|---|---|---|---|---|
| **10 kHz** | 1/6500 | 6500 | **6500** | **1** | 6500 | 126 µs |
| **100 kHz** | 1/650 | 650 | **7800** | **12** | 65 | 126 µs |
| **1 MHz** | 1/65 | 65 | **8190** | **126** | 65 | 126 µs |

> 采集耗时恒为 `DIV × BUF_DEPTH / 130 MHz = 2 × 8192 / 130 MHz = 126 µs`,
> 与激励无关 —— 一次采集**总是收满整块缓冲**,窗长是后处理时截出来的。

### 4.1 ⛔ 10 MHz 已删除(算术成立、物理不成立)

10 MHz 在这一代硬件上 `q = 13`、`L = 8190`、`m = 1260`,**数学上完全成立**,
但**输出不了**:

- AD9833 的 MCLK 是**板载 25 MHz 晶振,焊死**(决策 D10),`f_out = code × 25 MHz / 2^28`;
- 25 MHz MCLK 出 10 MHz ⇒ **只有 2.5 个 DAC 采样/周期**;
- 且 15 MHz 镜像离主频只有 **5 MHz**,低通滤不掉。

⇒ 2026-10-08 上板判定输出不了,**从界面和档位表里删除**。
这是 DAC 采样定理的硬限制,**不是配置问题**;要 10 MHz 只能换激励源(MCLK ≥ 100 MHz 的 DDS)。

### 4.2 ⚠️ 10 kHz 的 `m = 1` 是一个需要交叉核对的点

`m = 1` ⇒ 激励正好落在**第 1 根谱线**上。整窗内**基线漂移会直接进信号 bin**
(DC 不会 —— 整周期 `Σcos = 0` 精确抵消)。

**判据**:同一器件、同一偏压下,**10 kHz 与 100 kHz 反演出的 `Cs` 应当接近**;
差得多则嫌疑是漂移而不是器件特性。**该判据截至建档时尚未执行**(台面无接好的 DUT)。

## 5. 缓冲深度 8192 的由来

`10 kHz` 的最小窗长是 **6500 点** ⇒ 旧的 **4096 点缓冲装不下**。
这是"组合不合理"的**算术根源**,不是配置或代码缺陷。

```
BUF_DEPTH:  4096 → 8192      (adc_capture.v)
BUF_AW   :    12 → 13
BRAM 占用:  64 Kb → 128 Kb  ⇒ 实现后 Block RAM Tile 2.5 → 4
```

### 5.1 🔴 三道必须同时改的闸(每一道都不会报错)

改动横跨 RTL / C / 界面三层,每层都有一道"算得对、闸在中间"的关卡。
**三道闸的失效形状完全相同:数字算得出来,被静默截断/拒绝,不产生错误。**

| # | 位置 | 旧值 | 新值 | 不改的后果 |
|---|---|---|---|---|
| 1 | `cv_axi_lite_slave.v` 写掩码 | `32'h0000_0FFF` | `32'h0000_1FFF` | 写索引 ≥ 4096 被截成 `idx − 4096` ⇒ **读到的是另一个点的数据,不报错** |
| 2 | `adc_sample.c` `ADC_DEMOD_MAX_L` | `256u` | `ADC_SAMPLE_POINTS`(=8192) | `build_table()` 直接失败 ⇒ 报「窗长 6500 点,超出参考表上限 256」 |
| 3 | `ui_demo.c` `UI_WAVE_MAX_SAMPLES` | `480` | 480(不变,**改为抽稀**) | 8192 点喂进波形图**静默截断到前 480 点**,屏上"波形是平的" |

> 第 3 条不是把上限调大就完事:波形图只有 480 像素宽,8192 点本来就画不下。
> 正确处理是**先算「画几个周期」再抽稀**(见 `pynq_protocol.c::adc_feed_point_waveform()`),
> 而不是改大上限。

### 5.2 缓冲不是循环的

`adc_capture.v` 的单次采集语义:`go_pulse` 清 `wr_ptr` → 写满到 `wr_last`
(`wr_ptr == {BUF_AW{1'b1}}`)→ `busy <= 0`、`done <= 1`。
⇒ **它不是循环缓冲,索引 0 就是最早那个采样点**,加长窗只是参数变化,
不需要改控制逻辑。

## 6. 代价(M10 优化前后对比)

Vivado 2025.2,同一工程同一综合/实现策略,唯一变量是上述改动。

| 资源/时序 | **改前**(2026-10-07) | **改后**(2026-10-08) | Δ |
|---|---|---|---|
| Slice LUTs | 1662(3.12%) | **1665(3.13%)** | +3 |
| Slice Registers | 1886 | **1888** | +2 |
| **Block RAM Tile** | **2.5(1.79%)** | **4(2.86%)** | **+1.5** |
| DSPs | 0 | 0 | 0 |
| **WNS** | +1.055 ns | **+1.023 ns** | −0.032 ns |
| **WHS** | +0.045 ns | **+0.067 ns** | +0.022 ns |
| 失败端点 | 0 / 4938 | **0 / 4976** | — |
| 约束满足 | — | **`All user specified timing constraints are met.`** | — |

**判读**:代价集中在 **BRAM(+1.5 tile,占器件 2.86%)**,LUT/FF 几乎不动,
时序余量 1.023 ns 仍然充裕。**用 2.86% 的 BRAM 换回"10 kHz 与 100 kHz 可测"**
—— 这两档在旧设计里是**做不到**而不是"做得差"。

> 📌 B04「资源取舍论证」素材:这里**没有**为了性能牺牲资源的地方 ——
> 加长缓冲是**解锁功能的必要条件**,不是优化。真正的取舍发生在
> "删掉 10 MHz"和"固定 65 MSPS"这两处:两处都是**主动放弃自由度**
> (放弃扫频、放弃 10 MHz)来换取"界面能点的组合都成立"。

## 8. 失效条件与边界(接手者先看这一节)

1. **`clk_adc` 必须真的在 130 MHz。** 它由 MMCM 从 FCLK0 派生,
   而 **`Overlay()` 会把 FCLK0 复位回 `BOOT.BIN` 的 27.78 MHz**
   ⇒ MMCM VCO 361 MHz < 下限 600 ⇒ **锁不住**。
   判据:`0x90[0] mmcm_locked`。**`apply_fclk0()` 必须排在 `Overlay()` 之后**。
2. **`PH_OFF` 必须与 `DIV` 一起写。** 采样窗随 `P = DIV` 滑动;
   只改 DIV 不改 PH_OFF,采样点会滑出被驱动的窗口 —— **不报错、不越界**,
   现象是"换了速率就没波形了"。`P = 2` 时窗折回成 `[−1,−1]`(单点取值)。
3. **改激励频率之后必须重新解调。** 窗长、参考表都随 `f_e` 变;
   `adc_sample.c` 每次采集现读 `MeasureConfig` 再建表,所以**不要缓存参考表**。
4. **`0x94` 的正确写法是 13 位。** 任何按 12 位写的旧脚本(含
   `tools/adc_timing.py` 一类的历史工具)在新位流上会读到**错误的点**而不报错。
5. **`0x80` 的上限常量 `CV_DDS_HZ_MAX = 12.5 MHz` 是 AD9833 手册值,不是档位表。**
   档位表在 `ui_demo.c::g_init_dds_choices`,两处不是一回事。
6. **10 MHz 不要再加回来**(理由见 §4.1)。
