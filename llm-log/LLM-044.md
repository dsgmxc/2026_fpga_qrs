## 纠错轨迹

### A. 用户推翻我的(4 处)

1. **我断言「DDS 频率与 ADC 采样率两个旋钮不能独立调」** —— 理由是相干采样条件 `R/f_s = k/f_e` 要整数比。
   **用户反问:「dds 和 adc 频率为什么不能解哦，你调整 dft 代入的频率不就行了」**
   → **用户对**。相干条件不是悬崖:不满足只是平均窗不覆盖整数个激励周期 ⇒ 泄漏非零、2f_e 零点偏移,**是精度降级不是功能失效**;而且 DFT 参考频率本来就是软件代入的浮点数,改 f_e 就重新代入即可。
   **教训:我把"最优"当成了"必须"。**

2. **我设计成「两个 MMCM + BUFGMUX 切换」来实现非 2 的幂分频** —— 被用户一句
   **「写个分频器不行吗怎么只能二分频」** 直接推翻。
   → **用户对**。一个计数器 + 比较即可,`adc_clk = (cnt < P/2)`。我把"时钟要用时钟资源产生"错记成了"分频必须用 MMCM"。
   **教训:能用计数器做的事,不要动用时钟资源。**

3. **我推荐 PLL IP 输出 65 MHz 再由它分频** —— 用户采纳后,我自己算出这是**质因数死结**:65 = 5×13,65/n 永远得不到 10 MHz。
   → 改为 **130 MHz(65 与 10 的最小公倍数)**,P 取 2/4/5/10/13/26/65/130 即有全部常用档。
   **这是我先给结论、后被自己算推翻的一处,用户没有参与。**

4. **我断言「工程里还没有任何 clk_wiz 实例」** —— 错的。`clk_wiz_0` 存在且 VCO 已是 1300 MHz,只是它**只被遗留顶层 `qrs.v` 例化,不在真顶层里**。
   **教训:搜到的模块不等于生效的模块 —— 要顺着例化链确认到真顶层。**

### B. 工具链踩坑(全部实测复现过)

5. **`buf` 是 Verilog 门原语保留字** —— `xvlog` 报 `VRFC 10-4982 syntax error near 'buf'` + `VRFC 10-8549 Verilog 2000 keyword 'buf' used in incorrect context`。缓冲区数组改名 `cap_mem` 后通过。

6. **`adc_capture.v` 初版用了未声明的标识符**(`clk_axi` / `cfg_oe_n_d` / `cfg_pdn_d` / `mmcm_locked_i`)—— 补进端口表并改回真实信号名后通过。

7. **`$llength(oldnames)` 在 TCL 里被解析成数组访问** —— 报 `can't read "llength(oldnames)": no such variable`,整个批处理脚本中止。正确写法 `[llength $oldnames]`。
   **教训:Vivado TCL 的字符串里写 `$var(arg)` 就是数组语法,不是函数调用。**

8. **`save_project` 在 Vivado 2025.2 不存在** —— `ERROR: [Common 17-163] Missing value for option 'name'`。工程本身由 Vivado 自动持久化;要显式保存应走 `close_project` 或 `save_project_as`。

### C. 🔴 本次最大的坑:`update_module_reference` 静默失败

9. **现象**:给 `cv_sys.v` 加了 16 个 ADC 端口后,BD 里的 `cv_sys_0` 始终只有 51 个引脚,`get_bd_pins cv_sys_0/adc_*` 为空。
   **试过的**:
   - `update_module_reference cv_sys_0` / `/cv_sys_0` / `[get_bd_cells cv_sys_0]`,加 `-module_reference` / `-path` / `-verbose` / `-quiet` —— **全部 rc=1 且错误消息为空**,`errorCode = NONE`,日志里连一行 ERROR 都没有;
   - 把 `ip/system_cv_sys_0_3/` 目录改名移走再重开工程 —— **毫无变化**,说明 BD 的端口边界不是从那个 `.xci` 来的;
   - `create_bd_cell -type module -reference cv_sys` 建一个**全新探针 cell** —— 也只有 51 个引脚。
   **根因**:`qrs.gen/sources_1/bd/mref/cv_sys/component.xml`(**IP-XACT 缓存**,时间戳与那个 `.xci` 同为 10-05 16:23,内容里 `grep -c adc_` = 0)。IP Integrator 建 module_ref 时读的是它,不是 HDL。
   **解法**:把 `qrs.gen/sources_1/bd/mref/`(以及 `qrs.runs/synth_1/.gen/` 下的副本)整体移走后重开工程 → 探针 cell 立刻给出 **56 个引脚**(51 + 5),`adc_clk / adc_oe_n / adc_pdn / adc_otr / adc_d` 全在。
   **最终解法**:既然刷新命令不通,就**删掉重建** —— 先 dump 出 `cv_sys_0` 的完整连接(17 根普通线 → BD 端口 / `s_axi_aclk` / `s_axi_aresetn` / `M_AXI` / `S_AXI`),`delete_bd_objs` 后 `create_bd_cell` 同名重建,再逐条 `connect_bd_net` / `connect_bd_intf_net` 接回,最后**重赋地址 `0x43C00000`**。
   **教训:`update_module_reference` 失败时不要死磕它 —— 检查 `.gen/` 下的 IP-XACT 缓存;「刷新」不通就「删了重建 + 按 dump 重连」,并把地址段一起恢复(dump 里要连 `get_bd_addr_segs` 一起抓,否则会丢 0x43C00000 和 M_AXI 的 DDR 段)。**

10. **`make_external` 不是这个版本的命令名** —— `invalid command name "make_external"`。正确的是 **`make_bd_pins_external -name <port> <pin>`**。

### D. 我自己发现、用户没提的(1 处)

11. **同步器寄存器没有 `ASYNC_REG`** —— 复核 `adc_capture.v` 时发现所有 2-FF 同步器(`rst_sync` / `div_s*` / `pho_s*` / `cont_s*` / `go_s*` / `locked_s*` / `done_s*` / `busy_s*` / `otr_s*`)都没打属性。
    → 补 `(* ASYNC_REG = "TRUE" *)`(必须打在**第一级**上;只打第二级无效),并配套在 `led.xdc` 加 `set_clock_groups -asynchronous`。
    → 时钟名从 `report_clocks` **实测**取得,不用通配符兜(通配符匹配不到时是静默失效)。

## 沉淀

→ 候选 `skill/module-ref-cache-staleness/` —— **IP Integrator 的 module reference 端口边界缓存在 `.gen/.../bd/mref/<mod>/component.xml`,不在 `ip/<ip>/` 的 `.xci` 里;`update_module_reference` 可能静默失败,可靠路径是"清缓存 → 删 cell → 同名重建 → 按 dump 重连"。**

→ 候选 `skill/async-reg-on-first-stage/` —— **同步器要打 `ASYNC_REG` 且必须打在会进亚稳态的第一级;同时用 `set_clock_groups -asynchronous`,时钟名一律从 `report_clocks` 抄实测值,禁止用通配符。**

→ 扩展 `skill/stale-artifact-silent-reuse/`(见 LLM-011)—— 本次的 `.gen` 缓存是同一类问题的第二个实例:**生成物比源文件更"有权威"时的排查顺序**。
