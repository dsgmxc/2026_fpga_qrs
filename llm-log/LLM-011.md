# LLM-011: 顶层 `qrs.v` 最简上板例化 —— 例化补全 / code 初值 / `set_in` 单次脉冲

- **日期**: 2026-09-19(接 LLM-010 同日)
- **模型**: Claude(本会话)/ 用户为参赛学生
- **任务**: 用户明确要求 —— 「在顶层模块 `qrs` 完善例化,code 设置初值,
  然后仅在初始化完成后 `set_in` 一次,做一个最简例化」

## 提示词

```
帮我在顶层模块qrs完善例化，code设置初值，然后仅在初始化完成后setin一次就行，进行一个最简例化
```

## 模型回答(改动内容,共 4 处)

| # | 改动 | 理由 |
|---|---|---|
| 1 | 端口 `wire clk_in1, wire rst_n, wire dac_*` → `input wire` / `output wire` | ANSI 端口表里写 `wire` **不带方向是非法的**,原文件无法通过综合/仿真 |
| 2 | 补 `wire [19:0] code; wire set_in; wire init_done;` | 原来这三个是**隐式网络**(`default_nettype wire` 下靠名字自动连线),能过但会出警告,且改名即静默断线 |
| 3 | `wire [19:0] code = 20'h80000;` | 码值初值取 20 位中值;模块层双极性下约 **0 V**(见 `docs/dac1220_interface.md` §八补),万用表最容易判读 |
| 4 | `init_done` 上升沿 → 单拍宽 `set_in` 脉冲 | 用户要求「仅在初始化完成后 set_in 一次」 |

第 4 处的实现(与 `dac_1220` 同域,不需要 `cdc_sync`):

```verilog
reg init_done_d;
always @(posedge spi_clk_50m or negedge rst_n)
	if(!rst_n) init_done_d <= 1'b0;
	else       init_done_d <= init_done;

assign set_in = init_done & ~init_done_d;
```

**一拍宽够用**的依据:`dac_1220` 的 `NORMAL_WAIT` 对 `set_in` 上升沿是
**无条件锁存**成 `set_pending`(LLM-009 修掉触发死锁时改的),不依赖脉冲宽度。

`dac_1220` 的参数**保持默认真值**(`PWR_WAIT` 200 ms / `CAL_WAIT_T` 600 ms / `SETTLE_WAIT` 30 ms)——
上板要的就是真实等待。

## 结果

✅ **直接可用**(有 elaboration 零错 + 顶层仿真 9 字节实测)

## 验证方式

### 1. 语法与 elaboration
用一个 `/tmp` 下的 `clk_wiz_0` **桩模块**(真 IP 不参与仿真)跑
`xvlog qrs.v dac_1220.v spi_master.v clk_wiz_stub.v` + `xelab qrs`:
**零 error、零 warning**,`Compiling module work.qrs` 通过 → 端口方向与例化接线成立。

### 2. 顶层行为仿真(引脚级)

把顶层复制一份到 `/tmp`,**只**把 `dac_1220` 例化处的三个毫秒级参数覆写成小值
(`PWR_WAIT(1000) / CAL_WAIT_T(3000) / SETTLE_WAIT(1500)`),其余(含 `code` 初值、
`set_in` 单次脉冲逻辑)**逐字不动**;用 `sed` 改并 `grep` 确认**只改了这一行**。

跑 3 ms(远超全部加速等待之和),只观察 `dac_sclk` / `dac_mosi`:

```
  init_done = 1
  code      = 20'h80000
  SCLK 边沿总数 = 150
  收到的字节数 = 9
   [字节 0..4] 0x24 0x20 0xa0 0x05 0xa1      ← 自校准 5 字节
   [字节 5..8] 0x40 0x80 0x00 0x00           ← DIR = 0x80000 << 4 = 0x800000
  0x40 命令字节出现次数 = 1  (应为 1 —— set_in 只打一次)
 结论:PASS
```

两个关键点:

- **字节流 `40 80 00 00`** = `code[19:12]=0x8` / `code[11:4]=0x00` / `{code[3:0],4'b0}=0x00`
  → 与 LLM-010 修正后的切片一致;
- **`0x40` 只出现 1 次,且是跑满 3 ms(≈ 2000 个 `SETTLE_WAIT`)之后** →
  证明 `set_in` **确实只打了一次**,不会在 `NORMAL_WAIT` 里反复重发。

### 3. 局限(引用时必须一并说明)

- 顶层仿真用的是**加速副本**,不是 `qrs.v` 原件 → **三个毫秒级等待的真实时长仍未验证**;
- `clk_wiz_0` 用的是**桩**,**真 IP 的 MMCM 锁定过程与时钟抖动没有进仿真**;
- **仍未综合、未写 XDC、未上板** → **M03 / M04 / M13 仍无证据**。

## 纠错轨迹

1. **【量具错·第 4 次】模型的引脚监视器把采样沿写反了。**
   本 SPI 是 CPOL=0/CPHA=1,**数据在下降沿被采样**,而监视器写成
   `if (sclk_d == 1'b0)`(上升沿采样)→ 收到的字节全是错位垃圾
   (`12 10 d0 02 d0 20 c0 00`),顶层被判 **FAIL**。
   → **RTL 没问题,是量具错。** 判据是**边沿总数 = 150 = 6(复位图案) + 5×16 + 4×16** ——
   这个数**从第一跑起就是对的**,说明 9 个字节一个不少地发出去了。
   与 LLM-009 的 VCD 解码器错位、LLM-010 的三处量具错**同源**:
   **先证明量具可信,再相信结论。**
2. **【量具错·新形态】gap 法抓不到"最后一个字节"。**
   监视器靠「SCLK 静默超过阈值」把移位寄存器里的 bit 推成一个字节 ——
   而**帧的最后一个字节后面没有下一个沿了**,永远等不到触发 → 稳定少报 1 个字节(nbyte=8 而非 9)。
   修法:仿真收尾时补一次 flush。
   → 教训:**基于"下一个事件"的读取方式,天然读不到最后一个事件。**
3. **【工具链陷阱】`xelab` 会静默复用上一次的仿真快照,让一次失败的编译看起来像一次成功的运行。**
   中途一次命令里 `$S` 变量没展开(前一条 Bash 的 shell 状态不跨调用保留),
   `xvlog` 报 `Can not find file: /dac_1220.v` 而**模型没有先看这条**,
   直接读 `xelab` 的输出 —— 它拿**上一轮的 `xsim.dir`** 编出了快照并跑出结果。
   输出的 FAIL 与上一轮一字不差,**差点被当成"新结果"**。
   → 教训:**改了源码后,`xelab` 必须配 `rm -rf xsim.dir`,并先确认 `xvlog` 零 error 再看下游输出。**
   与 LLM-005 的 `sed` 静默失配同类:**中间步骤静默失败,最终输出仍然"看起来正常"。**
