## 模型回答

**根因**(数据手册 SBAS082G 佐证,不是猜的):

| 出处 | 事实 |
|---|---|
| Table 13,CMR bit5 `DF` | **0 = 偏移二进制补码(上电默认)**;1 = 直通二进制 |
| Table 9(20 位) | 补码 0 V → 码 `80000h`;直通 0 V → 码 `00000h` |
| CMR 上电值 | `0x0002`(所有相关位为 0)⇒ **默认就是补码** |

**六点实测 vs 两个模型**:

| 码 | 补码模型(模块级) | 直通模型 | 实测 |
|---|---|---|---|
| `0x7FFFF` | +10.00 ✓ | 0.0 ✗ | **+9.72** |
| `0x26666` | +3.00 ✓ | −3.0 ✗ | **+2.80** |
| `0x0CCCC` | +0.82 ✓ | −5.0 ✗ | **+0.820** |
| `0x80000` | −10.00 ✓ | 0.0 ✗ | **−10.0** |
| `0x99999` | −8.00 ✓ | −2.0 ✗ | **−8.0** |
| `0xA6666` | −7.00 ✓ | −1.0 ✗ | **−7.0** |

其中 `0x0CCCC` 是**样本外**点(先预测 +0.823 V,后读数 820 mV)。

**改法 —— 两边必须是同一个 DF**:

| 侧 | 文件 | 改动 |
|---|---|---|
| PS/C | `src/c_ui/app/pynq_regs.h` | `cv_bias_volts_to_code()` 返回值 **`^ 0x80000`**(直通→补码旋转半个量程);`cv_bias_code_to_volts()` 反向再旋转一次 |
| RTL | `qrs.srcs/sources_1/new/dac_1220.v` | `cal_byte_f` 的 CMR 由 `0x20A1`(DF=1 直通 / RES=0 十六位)改为 **`0x2081`**(DF=0 补码 / RES=1 二十位) |

RTL 改动的**关键论证**(不是"顺便改"):

> 2026-09-19 那次实测(`0x40000`/`0x80000`/`0xC0000` → −5/0/+5 V)**精确落在直通二进制上**,
> 而本次六点**精确落在补码上**。⇒ 两次上电之间 **CMR 的 DF 位变了**。
> CMR 是易失的,而 RTL 那次 CMR 写**落没落进芯片无法确证**。
> **改成 DF=0 之后两种情况都对**:写进去了 → 显式补码;没写进去 → 上电默认就是 0。
> ⇒ **零回归风险**,而且消除了"每次上电偏压映射可能不同"这个隐患。
> 反过来,如果只改软件旋转而不动 RTL,下一次上电若 CMR 恰好写进去(DF=1),就又会错。

## 纠错轨迹

**这是本场最有价值的部分 —— 四个错,全部由我自己发现并撤回。**

1. **我把零点写反了。** 定稿注释里我写了「`code = 0x80000` 才是 0 V」。
   但实测那一点是 **−10.0 V**。我是在回填实测表格时对不上才发现,改成
   「**`0x00000` 才是 0 V;`0x80000` 实际是 −100 V**」,并把算术重推了三遍才落盘。
   ⚠️ 这条错误如果发出去,会直接把用户的高压侧推进 −100 V。

2. **我的 C 单元测试断言错了,而代码是对的。** 测试在 0.1 V 报 FAIL:
   我断言码是 `0x0000D`,实际 `0x0020C`。**是我算错,不是代码错** ——
   修正测试的期望值,并同步改掉头部注释里那句同样的错话。重跑 ALL PASS。
   (这里差点走进"改代码去迁就测试"的坑。)

3. **发现跨上电周期不自洽 —— 这是促使我改 RTL 而不是只改软件的那条线索。**
   文档里 2026-09-19 记的三点(−5/0/+5 V)**精确落在直通二进制**上,
   而今天六点精确落在补码上。**同一块板、同一颗芯片,两次上电格式不同。**
   ⇒ 若只改软件旋转,下次上电 CMR 写进去就又会错。据此改为"两边一起钉到 DF=0"。

4. **误判过一次硬件故障,实为我的脚本 bug。**
   `adc_dft.py` 报 `math domain error`,我一度以为 ADC 缓冲是空的。
   查下来是**那个脚本从头到尾没有 GO 触发**(从没写过 `0x8C=1`),
   读的是复位后的空缓冲。补上握手后立刻拿到正常波形。
   ⛔ 教训:**先怀疑自己的工具,再怀疑硬件。**

**另有一次判断被我主动保留为"未结案",没有粉饰**:CMR 到底有没有写进芯片,
只有间接证据("行为像上电默认值")。要坐实需要**建一个 DAC1220 SPI 从机模型跑仿真**,
或上示波器看 SPI 波形 —— 两者本轮都没做,**故如实标为未结案**,不写成"已解决"。

**还有一条我做到一半停手的**:用户说「高压级不管」时,我正在追 1.1% 的量程残差
(`19.777` vs 设计 `20.000`)。**我停止了这个方向**,并在文档里写明判断依据:
DAC1220 的增益误差规格是 **±150 ppm(±0.015%)**,1.1% 是它的 **~75 倍**;
且该芯片**没有内部基准**(`VREF` 是输入引脚),残差只能来自板上的 2.5 V 基准或
增益级电阻。**⇒ 属于 B8 OPEN/SHORT 校准的范畴,不该用万用表手读数去烘一个补偿系数。**

## 沉淀

→ `skill/binary-format-two-sides/` —— **"两端二进制格式必须写在同一处、并且钉死"**。
本案的特殊性在于:错误的表现是"设多少都读出同一个值",而**根因在两个不同的层**
(PS 的换算函数 + PL 的 CMR 配置字节),任一层单独改都只能"当前这次碰巧对"。
配套那条更硬的教训是:**格式类的错,复位值比写入值更值得依赖** ——
把两端都钉到"上电默认值"上,才能让"写没写进去"这个未知量变得无关紧要。

→ `skill/suspect-your-own-instrument-first/` —— 第 4 条纠错的直接产物。
另可并进既有的 `skill/silent-capacity-gates/`(同属"静默失配"这一类)。
