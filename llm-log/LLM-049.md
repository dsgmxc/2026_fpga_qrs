# LLM-049: 扫压「全部」只有一条曲线 —— 三条都画了,但它们逐点重合;根因是**本位流没有继电器**

- **日期**: 2026-10-06(第 46 次会话,接 `LLM-048` 上板验收之后)
- **模型**: DeepSeek-V4-Flash
- **任务**: 用户在板上跑完一轮「扫压 · 回路=全部」,看「扫压结果」页发现**只有一条曲线,而且是 CRSS 的颜色**,
  问为什么不是三条。

## 提示词

```
为什么我扫压选择全部扫描测出来就只有一条曲线crss的不应该三个吗
```

## 模型回答

**这四条串起来就是答案,不需要改任何代码:**

1. **三条都画了** —— `UI_Demo_BeginSweep()`:`g_sweep_visible_mask = (multi_path != 0u) ? 0x07u : (1u << path)`;
   而扫压页的「全部」派发到 `DisplayProtocol_RequestRgThenSweepAll()` → `sweep_start(0x07u, …)`,
   所以 `multi_path = 1` ⇒ 三条 series **全部可见**。

2. **但三条的数据逐点相同** —— `sweep_measure_point()` 里那个 `for (path = 0…2)` 循环,
   给三路喂的是**同一个** `s_pair.cs_pf`。每个偏压点只做**一次** ADC 采集,一个值填三路。

3. ⇒ 三条线的坐标**完全相同 ⇒ 完全重合**。LVGL 按 `lv_chart_add_series()` 的**添加顺序**绘制,
   后加的在上层;`ui_demo.c` 的添加顺序是 `g_sweep_series[0]=CISS`(品红 `0xd65ab1`)、
   `[1]=COSS`(红 `0xe5225b`)、`[2]=CRSS`(橄榄绿 `0x8c971d`)⇒ **最上面那条是 CRSS**,
   它的颜色盖住了底下两条。右边图例三个色块仍然都在。

4. **为什么数据必须一样 —— 硬件上根本没有回路切换**:
   真实 Ciss / Coss / Crss 是**三种不同的测量回路**(G-S 短接测 Ciss、D-S 测 Coss、G-D 测 Crss),
   要靠继电器在**每个偏压点**切一次。而本工程里 **`relay_ctrl` 这个模块根本不存在**。

**要改吗?** 建议**不改**。三条重合是"硬件只有一条回路"的**如实呈现**;
等 `relay_ctrl` 落地,`sweep_measure_point()` 里那个 `for path` 循环**已经写好**,
自动就出三条不同的线,**界面代码一行不用动**。这属于 **P4(双通道 + 继电器 + 校准)** 的缺口,不是显示 bug。

## 结果

☑ ✅ 直接可用   ☐ ⚠️ 部分可用   ☐ ❌ 不可用

**理由**:结论**四层独立坐实**(RTL / 寄存器表 / C 侧 / 派发链,见下),不需要动一行代码。

## 验证方式

**(A) 四层各自 grep,没有一层有继电器** —— 这是"数据必须一样"的硬依据:

| 层 | 查什么 | 实测 |
|---|---|---|
| RTL(交付仓库) | `grep -rln "relay" src/rtl/` | **零命中**(15 个文件里没有 `relay_ctrl.v`) |
| 寄存器 | `grep -n "1C\|relay" cv_sys.v` | **零命中** ⇒ `0x1C` 在 RTL 里**没有对应逻辑** |
| C 侧 | `grep -n "0x1C\|RELAY" pynq_regs.h` | **无** |
| Python 侧 | `cv_regs.py` | 有 `RELAY_CFG: 0x1C`,但它落在注释标注的「**测量主链(PL 侧尚未实现,见 `PL_IMPLEMENTED_REGS`)**」那一块 |

**(B) 派发链逐段读死**(不是推断):
`ui_demo.c:6400` `g_sweep_visible_mask = 0x07` → `sweep_start(0x07u)` → `sweep_measure_point()` 的
`for path 0…2` 全在 mask 内、三路同一个 `cs_pf` → `UI_Demo_UpdateSweepPoint()` 内
`g_sweep_valid[path][i]` 由**同一个** `cs>0` 决定 ⇒ 三条**同时有效、坐标相同**。

**(C) 系列顺序与颜色**(`ui_demo.c:244` 与 `:5583-5594`):`{0xd65ab1, 0xe5225b, 0x8c971d}` 依 CISS/COSS/CRSS 添加
⇒ 最后添加的 CRSS 在最上层。**这解释了"为什么偏偏是 CRSS 的颜色"**。

**(D) 🟢 板上帧缓存像素核对 —— 做成了,预测逐字命中**:
第一次抓帧抓到的是「数据导出」页(顶栏 `回路:CISS`),三个系列色 **0 命中**,连曲线都没有
⇒ 当场判为**不构成证据**(见纠错轨迹 3),请用户切到「扫压结果」页签后重抓。
第二次(`0x38100000` → `fbB.ppm`,1024×600,312 种颜色)精确计数:

| 系列 | RGB565 | 像素数 | 包围盒 | y 方向簇 |
|---|---|---|---|---|
| CISS 品红 | `0xD2D6` | **104** | x`[405,430]` y`[139,142]` = **26×4** | **1 簇 ⇒ 只有图例色块** |
| COSS 红 | `0xE10B` | **104** | x`[535,560]` y`[139,142]` = **26×4** | **1 簇 ⇒ 只有图例色块** |
| CRSS 橄榄绿 | `0x8CA3` | **4291** | x`[90,983]` y`[139,425]` | **2 簇**:`y[139,142]`(自身图例块)+ `y[167,425]` x`[90,983]`(**曲线本体**) |

三个自洽点:① **104 = 26×4**,正是 `lv_obj_set_size(line, 26, 4)` 的图例色块尺寸
⇒ CISS/COSS 的 104 像素**全是图例、曲线上 0 像素**;② 两块间距 **130 px**(405 → 535)
正好是代码里的 `item_x = 380 + index*130` ⇒ 确认是那一排图例,不是别处的巧合配色;
③ CRSS 多出的 **4187 px**(4291−104)横跨 x`[90,983]` —— 就是曲线本身。
⇒ **三条都在画、曲线上只出现栈顶那条(CRSS)的颜色**,结论由像素坐实。
完整存档:`report/measurements/20261006_sweep_all_three_series_overlap.md`(+ 两张截图)。

**(E) 旁证 —— 演示模式能出三条不同的线**:`CV_UI_DEMO=1` 时 `demo_capacitance(path, v)` 给三路
不同的 `c_max/c_min`(`{980,240,48}` / `{420,62,7.5}`),所以那档会看到三条分开的曲线。
**那是编的数**。若此前见过三条,是这一档。

## 纠错轨迹

1. **第一反应是错的:我以为"只有一条 series 的可见位被置上"**,于是先去读 `UI_RebuildSweepChart()` 找
   `g_sweep_visible_mask` 的写入点。读到 `UI_Demo_BeginSweep()` 就否掉了 —— `multi_path` 分支明写 `0x07`。
   ⇒ **症状是"只看见一条",但成因不是"只画了一条"**;差点沿着"可见位为什么只置一位"的方向白挖。
2. **把"看屏的直觉"当成了输入,差点写成结论**:如果只按用户描述去改代码(比如"把 mask 改成 0x01,只画一条"),
   就会**掩盖真实原因**(没有继电器),让下一个人以为"界面上只有一条是正确的",而三条分开的曲线其实是**迟早该有**的。
   ⇒ 先问"这三条**能不能**不同",再问"为什么看起来是一条"。
3. **未把"没抓到"说成"验证过"**:像素核对这一步我**想做**、也确实抓了帧,但抓到的是另一个页签
   ⇒ 直方图零命中时**没有**去解释"零命中说明被覆盖了"(那是编的),而是承认抓错页、记为待补。
   **这一条后来收口了**:请用户切到「扫压结果」页签后重抓,结果与预测**逐字吻合** ——
   CISS/COSS 各 **104 px = 26×4**,正是图例色块尺寸、曲线上 0 像素;两块间距 **130 px** = 代码里的 `item_x` 步进;
   CRSS **4291 px** 分两簇,多出的 4187 px 就是曲线。
   ⇒ 📌 **值得记的对比:如果当时顺着"零命中"往下编,后面这次真测量反而会显得像在给结论找台阶。**
4. **一条值得留意的形态**:这是 `LLM-048` §G「看屏会误会」的**同族**新成员 ——
   那次是"两张图画的不是同一个量"(电流有两种含义),这次是"三条图例暗示三次独立测量,实际是一个读数的三份拷贝"。
   **共同点:界面上没有硬件支撑的维度,被图例/颜色暗示成存在。**

## 沉淀

→ 候选 `skill/n-identical-series-look-like-one/`

- **适用范围**:任何"多条系列画在同一张图上"的可视化(不限 LVGL)。
- **判据**:屏上只看到一条线时,**先查是不是 N 条重合**,再查可见位。
  两条验证路径:① 读代码里 series 的**添加顺序**与**数据来源**,同源同值 ⇒ 必重合,
  栈顶 = 最后添加的那条(颜色能对上就是它);② 帧缓存像素直方图 —— **但必须先确认抓的是有曲线的那一页**。
- **失效条件**:若各系列数据确实不同,则不适用(回到"可见位/裁剪/量程"那条线)。
- **来源失败**:本次用户报告"只有一条 CRSS 曲线";表面像渲染缺陷,**实际是数据同源 + 硬件缺回路**。
- **更要紧的一半是设计侧**:⛔ **没有硬件支撑的维度,不要用图例/颜色暗示它存在** ——
  三条图例 + 三种颜色会让读图的人以为做了三次独立测量。要么图上标明"三路共用同一读数",
  要么等硬件到位再画三条。
