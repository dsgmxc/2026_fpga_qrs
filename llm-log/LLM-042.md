## 模型回答

### 1. 三次挂机 —— 根因只有一个,但模型先给出了错的

**现象**:裸读 `0x43C00000` ⇒ `mmap 返回 ✅` 后**静默 20 s、丢包 100%、只能断电**。
GP0 口无超时,从机不应答 ⇒ AXI 事务永不完成 ⇒ **CPU 卡在总线上**。

**真因**(实证,非推理):

| 证据 | 结论 |
|---|---|
| `BOOT.BIN` 860396 B 里位流同步字 `aa995566` 出现 **0 次** | 启动镜像**不含**位流 |
| `dmesg` 只有 `FPGA manager framework registered`,**无任何加载记录** | 内核也没加载 |
| `fpga_manager/state = unknown` | 同上 |
| `devcfg INT_STS = 0x00020000`(DONE 位 = 0) | **PL 上电就是空的** |

⇒ **每次上电 PL 未配置;读它的 AXI 窗口 = 挂死整机。**

**规则(本轮买来的)**:一次上电**只加载一次**位流,寄存器访问必须排在那一次之后。

### 2. 🔴 模型编了一个寄存器位,并据此反咬了用户

前两次挂机时,我用 `devcfg STATUS`(0x14)的 **bit5** 当 `PCFG_DONE`,读到 1 就断言
「PL 已配置」,再推出「PL 里残留着上一轮的位流」,进而**要求用户"真正断电"、
并质疑他上次是按了复位键**。

回到本机安装的权威头文件 `xdevcfg_hw.h`(devcfg_v3_9)一查:

| 寄存器 | 位 | 定义 |
|---|---|---|
| `STATUS` (0x14) | bit4 | `XDCFG_STATUS_PCFG_INIT_MASK = 0x10` |
| `STATUS` (0x14) | **bit5** | **无定义(保留位)** |
| `INT_STS` (0x0C) | bit2 | `XDCFG_IXR_PCFG_DONE_MASK = 0x04` ← **DONE 在这里** |

**`STATUS` 里根本没有 PCFG_DONE 这一位。** bit5 = 1 毫无含义 ⇒
「残留位流」整条推理链不成立,对用户的质疑**全部撤回并当面说明**。

**错在哪**:不是算错,是**凭印象用了一个常见但不适用于该寄存器的位定义**。
讽刺的是 `CLAUDE.md` 与我自己的记忆里都写着「规则类结论必须出示出处」。

### 3. 顺带挖出的三个环境坑(都会伪装成硬件故障)

| 现象 | 真因 | 处置 |
|---|---|---|
| `Overlay()` 报 `RuntimeError: No Devices Found` | `sudo` 不读 `/etc/profile.d/xrt_setup.sh` ⇒ `XILINX_XRT` 没导出 | 显式 `export XILINX_XRT=/usr` |
| root 下 `import pynq` 抛 `UnicodeDecodeError` | `transitions-0.7.2.egg-info/PKG-INFO` 第 30722 字节非 UTF-8,`pkg_resources` 崩 | 走服务那套 `VIRTUAL_ENV`/`PATH`;或直接手写 SLCR 绕开 pynq |
| 只改 `DIV0` 得 8.33 MHz 而非 50 | **`DIV1` 也必须置 1** | 同写 `FPGA0_CLK_CTRL = 0x00101400` |

第 3 条是**实测抓到的**:写完自认 50 MHz,数场频得 9.657 Hz(应 58.6)才对上账。

### 4. 端到端结果

```sh
FPGA0_CLK_CTRL = 0x00101400  ⇒ FCLK0 = 50.0000 MHz
  帧率法独立复测:58.606 Hz × 853440 px = 50.0170 MHz(差 0.03%)
  ⚠️ 中间那次(漏了 DIV1,8.3333 MHz)实测 8.2414 MHz,差 1.10%
     —— 若 IO PLL = 1500 应得 12.5 MHz,差 52% ⇒ IO PLL = 1000 的第 4 个独立确认
```

用户手点屏幕,后台脚本 150 ms 轮询取证,得到:

```
0x14 BIAS_CODE      62 次变化 = 2 次手动调偏压 + 60 点扫压(不同码值恰 60 个)
0x60 LCD_SWAP       109 次 front 翻转  ⇒ 双缓冲换址在真跑
0x68 TOUCH_STATUS   68 次变化          ⇒ 触摸链路在真跑
UNDERRUN / AXIERR   0 / 0
```

扫压 60 点逐点核对(码 → 栅偏压 `V = (−10 + 20·code/1048575) × 10`):

| 项 | 值 |
|---|---|
| 首 / 末 | `+0.1000 V` → `+5.0000 V`(严格递增,重复点 0) |
| 耗时 | **18.0 s = 60 × 300 ms** |
| 逐点电压比值 | mean **`1.06855`** |
| 理论 50^(1/59) | **`1.06855`** ← 吻合到小数点后 5 位 |
| 最大单点偏差 | **0.097%**(即 20 位码量化台阶) |
| 首/末步步长 | `6.9 mV` / `320.8 mV`,**相差 46.7×** |

## 纠错轨迹

1. **模型造了一个寄存器位。** 凭印象把 `devcfg STATUS` bit5 当 `PCFG_DONE`,
   由此推出「PL 残留上一轮位流」,并**据此质疑用户没真正断电**。
2. **用户没接受这个结论**(他反复重新上电,问题仍在)⇒ 迫使模型回头查出处。
3. **查到 `xdevcfg_hw.h`**,确认 `STATUS` 无此位、DONE 在 `INT_STS` bit2 ⇒
   **撤回结论 + 撤回对用户的质疑**,改用正确判据后才得到真因
   (PL 上电为空 ⇒ GP0 无从机 ⇒ 挂 CPU)。
4. **改完仍有遗留**:`0x68` 的 `err` 粘滞位全程为 1(触摸功能正常,成因未查);
   root 下 `pkg_resources` 崩溃**未修**(绕开而非解决)。
5. **另一条自己的手误**:手写 SLCR 时漏设 `DIV1`,靠实测场频才抓出来 ——
   **"写进寄存器"不等于"生效",必须独立复测。**
6. ✅ **收尾复查时又推翻了一条自己的旧结论** —— `skill/pynq-overlay-bringup/` 原先断言
   「`fpga_manager/state` 加载前后都读 `unknown`,不可作判据」。收尾做只读复查时实测:
   **开机 `unknown` → `Overlay()` 之后 `operating`**,且 `dmesg` 同步多出一行
   `writing qrs.bin to Xilinx Zynq FPGA Manager`(时间戳 `127.939679`,正是 `Overlay()` 那一刻)
   ⇒ **它是可用判据**,已更正进技能包 §0.1 与 §失效条件。
   📌 **"我测过、不行"这类旧结论同样要能追到那次测量** —— 追不到,就很可能像本例一样
   **是没测就下了结论**。这也是本轮第 **2** 次「模型自己写过的东西被自己的实测推翻」。
