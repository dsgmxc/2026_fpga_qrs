## 模型回答

1. **重启后又上电时**:软重启 → `systemctl enable qrs-ui`(用户要求开自启)→ `start` 一次,
   本周期位流恰 1 次;复核 A 挡点测日志 `(未校准)`、B 挡 `(已校准)`、AI 0.1/0.1/0.7。
2. **截图方法(不猜双缓冲)**:读 PL 寄存器 `0x43C00060` 的 `front` 位,确定屏幕正在扫的
   是 `fb0 = 0x38100000` 还是 `fb1 = 0x38230000`;再用板上 `/home/xilinx/fb_dump.py`
   只读 dump 1288800 B 的 RGB565 帧缓存;取回宿主后 **180° 旋转**(画布本身是倒的),
   `PIL` 存 PNG 到 `~/Desktop/qrs_ui_shots/<YYYYMMDD>_<HHMMSS>_<页面>.png`。
3. **截图判读**:首页(100 Ω、已校准)、系统复位页、校准页(16/16、四挡 L2*)、单点测量页。
4. **单点页被测件是标准板 1**(Cgs 1986 / Cgd 10 / Cds 104 pF),于是直接算残差:
   CISS 1995.788 pF(−0.01 %)、COSS 116.690 pF(+2.4 %)、CRSS 12.120 pF(+21 %);
   并指出 CRSS 误差大是 `|Z|/R0 ≈ 131` 的量程问题,不是校准算法错。

## 纠错轨迹

1. **把上一周期的二进制 md5 当现值**:我在报告草稿里写 `/proc/<pid>/exe = 44c1ff2b…`
   (那是 2026-10-29 那轮的),发布前现读发现已是 **`ed89168f…`**(后续会话又重编过,
   `nm` 仍含 `cal_channel_point`)。⇒ **运行中二进制的 md5 只能现读,不能抄历史记录。**
2. **截图文件名用错日期**:先按"对话里最后一次系统日期"命名成 `20261029_…`,
   而宿主 `date` 已是 **2026-11-02**(板子关机跨越了几天)。⇒ 文件名日期取
   **截图当时主机的 `date`**,不取会话记忆。
3. **界面文案过期(截图才看见)**:「系统复位」页底部仍写"采样率固定 **65 MSPS**",
   实际 `CV_ADC_DIV_DEFAULT = 4` ⇒ **32.50 MSPS**。纯文案错误,位置
   `src/c_ui/ui/ui_demo.c:3988`;改它要重编+重启服务(二次加载位流),
   本周期不做,留待下次上电前一起改。
4. **C/D 挡上板证据仍缺**:用户本轮切到 D 挡(截图里 `档位:10kΩ`)但没跑单点;
   `|a−1|` 守卫对 C/D 的拒绝仍只有宿主证据 —— **不写成已上板验证**。
