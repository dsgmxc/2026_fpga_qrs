## 模型回答

### 1. 结果页 = 顶部一排页签 + 5 个互斥子页

| 页签 | 内容 | 数据来源 |
|---|---|---|
| 单点结果 | CISS / COSS / CRSS / RG 四张卡 | 测量页最近一次回写的读数 |
| 单点波形 | 激励电压 + 回路电流两条建立曲线 | 测量过程的原始采样 |
| 扫压结果 | C-V 曲线(三路) | **与扫压页逐像素同源** |

| 数据导出 | **空占位**,写明三项待定 | — |

关键结构决定:

- **子页容器不能用 `UI_CreatePageContainer()`** —— 那是给顶层页用的,自带背景与内边距,套在结果页里会盖掉页签。新写了 `UI_CreateResultSubpage()`(透明整屏叠层,只切 `HIDDEN`,不重建控件)。
- **结果页不持有数据**:全部经 `UI_ResultsRefresh()` 从既有 getter 投影;`UI_ActivatePage()` 里挂「进入即刷新」钩子,所以「测完退出再点进来就更新了」是自然成立的,不需要额外通知。
- **扫压结果页复用扫压页的绘制回调** `UI_SweepChartDrawEvent`。对数轴的刻度文字(0.10 / 1.0 / 10 / 100)是**自绘**的,LVGL 自带的整数刻度只会把 log-milli 原值(1000 / 2000 / 3000)印出来 —— 第一版就是这样,屏幕上是一串与物理量无关的数字。
- `UI_ApplySweepViewport()` 改为 `UI_ApplyChartViewport(lv_obj_t *chart)`,原函数降为一行包装 ⇒ 结果页每次刷新都跟着扫压页的当前视口走,不改任何调用点。

## 纠错轨迹

### 1. 🔴 第一次换新二进制后,看的是**旧进程的画面** —— 追了一轮不存在的 bug

拆完页签第一次部署,截图显示:**页签停在「扫压波形」而不是「单点结果」**,标题栏也还是两字的「结果」。我先后怀疑 `g_result_tab` 初值、`UI_ResultTabApply` 的样式选择器、按钮 `user_data` 索引错位 —— 全是**猜测**,且都不成立(源码里 `g_result_tab = 0u` 写在建页末尾,紧接着就是刷新)。

**定案靠的是时间戳,不是读代码**:

```
板上二进制 mtime : 2026-10-03 15:12:36 UTC   ← 刚编出来的
c_ui 进程启动时刻 : 2026-10-03 15:04:54 UTC   ← 早 7 分钟
```

进程比二进制还老 ⇒ 屏上那一帧**根本不是新代码画的**。

**根因**:重启脚本里 `pkill -x c_ui` 需要 root,而我在 SSH 上**漏了 `sudo -S`**,以 `xilinx` 身份跑 ⇒ 杀不掉 root 的旧进程,新 `main.py` 又起不来(打不开 `/dev/mem`),脚本的等待循环 `pgrep -x c_ui` **匹配到了旧进程**于是"顺利通过",还打印出一个看起来很正常的 pid。整个失败**没有任何报错**。

**判据(以后照做)**:换完二进制重启后,**先对 `ps -o lstart` 的进程启动时刻与二进制 mtime**,再截图。两者顺序不对就什么都别解读。
⇒ 这是 `skill/stale-artifact-silent-reuse/` 的**第五种形态**:前四种是烧录器 / `.xpr` / BD mref / `xelab -R`,这次是「**重启没生效**」。

### 2. 🔴 `lv_coord_t` 是 int16 —— 我用「算出截断值再与屏幕逐位比对」定案

扫压包络页第一版的 Y 轴刻度冒出一串**现实中不存在的负值**,而曲线只剩两段竖线。

我连续否掉了三个假设,每一个都**拿证据否掉而不是换一个猜**:

| 假设 | 否证方式 |
|---|---|
| 量程没设 | 源码里设了(`UI_ResultWaveRefresh` 末尾) |
| 点数超了、写爆数组 | 建图时 `lv_chart_set_point_count(chart, UI_WAVE_MAX_SAMPLES)` = 实际写入数,不越界 |
| 数据没到 | 临时 `fprintf` 打点 → `have=1 total=60 v=[0.100,100.000] i=[0.592,277.101]`,**数据完全正确** |

数据对、量程对、不越界,但屏幕上的刻度是 `-23080 … -7892`。到这里我换了个方向:**不再猜哪里错,而是反算"什么变换能把正确的量程变成屏幕上的数"**。

我当时的量程是 `[lo, hi] × 1000`:

```
电压: (0.1 − 7.99) × 1000 = −7892        ✓ 与屏幕下端刻度完全一致
      (100 + 7.99) × 1000 = 107992  →  截成 -23080   ✓ 与屏幕上端刻度完全一致
电流: (0.592 − 22.12) × 1000 = -21528    ✓
      (277.1 + 22.12) × 1000 = 299221 →  截成 -28459   ✓
```

**四条刻度逐位吻合**,所以不是巧合,是 int16 截断:`107992 − 65536 = 42456`,再减 65536 = **−23080**;`299221 − 4×65536 = 37077`,减 65536 = **−28459**。

回查 `app/lv_conf.h:99`:`#define LV_USE_LARGE_COORD 0` ⇒ `lv_coord_t` **就是 int16**,坐标值上限 ±32767。

> 📌 **两条刻度同时逐位吻合,才算定案。** 一个数对上可能是巧合,四个数对上不可能 —— 这比"我觉得是溢出"强得多,也比再加一轮打点快。

**修复**:每条轴各自的缩放系数,保证最大值留在 ±32000 内。

```c
static const float g_wave_scale[UI_WAVE_KIND_COUNT][2] = {
    {1000.0f, 1000.0f},   /* 单点:电压 mV(≤1.1k)、电流 μA(≤0.3k) */
    { 100.0f,  100.0f}    /* 扫压:电压 10 mV(≤10k)、电流 10 μA(≤28k) */
};
```

单位串写进轴标题(`/ mV` `/ μA` `/ 10 mV` `/ 10 μA`)—— 因为 LVGL 8.2 **刻度文字不能自定义格式**,刻度上的整数就是最终显示,不存在"再除以 1000"的心算。**这条约束是本轮所有坐标轴设计的出发点**,写成注释钉在 `#define` 上方。

### 3. 🟡 缺字是**静默**的 —— Ω 与 μ 两次都是靠眼睛发现的

字库是 `lv_font_conv` 按**显式符号集**生成的子集,**不在集里的字渲染成空白,不报错、不警告**。

- 第一次:我从 `ui_demo.c` 抽字符时规则写成「`0x20–0x7E` **或** `≥0x2E80`」,`Ω`(U+03A9)正好掉进中间那道缝 ⇒ 测量卡的 `RG 12.43 Ω` 变成 `RG 12.43`。
- 第二次:`/ μA` 的 `μ`(U+03BC,新加的串,生成字库在前)缺字 ⇒ `/ 10 A`。
- 第三次:**同一个 `μ` 换了个字体又没了** —— 单位标签原先用 `lv_font_montserrat_16` 画,而 **Montserrat 本身就没有 μ/Ω**。改用中文字库才显示出来。

⇒ 抽符号集的规则改成「**字符串字面量里所有非 ASCII 字符**」(注释不算),并且**建一个 `grep -c` 之外的自查:凡是新写的非 ASCII 串,重新生成字库再上板看**。查字库生成参数:`--lv-include lvgl.h` 也漏过一次(生成物 `#include "lvgl/lvgl.h"` 编不过),虽然是硬报错,但同样是"参数漏了就废"。

### 4. 🟢 主动交代一个自动化钩子

为逐个页签截图,`UI_ShowResults()` 里读了一个环境变量 `CV_UI_RESULT_TAB`(默认 0)。它和已有的 `UI_Demo_GotoPage()` 同性质,**只用于演示 / 自动化截图**,源码里按同样口径标了注释。**正常流程里页签由触摸事件切换**,该变量不影响业务 ⇒ 已向用户交代「你要是觉得多余我删掉」。

### 5. ⚠️ 本轮**没有**产生任何测量证据

所有数字来自**演示模型**,不是测量结果。屏幕上、日志里、状态栏三处都标了「演示模式(读数为编造)」。收尾时**已把演示模式关掉**,板子回到「后端:未连接」的诚实状态 —— 不留一个"读数是编的"在板上,免得下次(人或模型)误判测量链已通。
