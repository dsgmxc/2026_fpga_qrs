# LLM-014:修 `adc_9833.v`(分帧)+ 补完正常态 —— **模型报了一个假 FAIL,还差点冤枉项目自己的常数**

- **日期**: 2026-09-20
- **模型**: Claude (Claude Code)
- **任务**: 把 `adc_9833.v` 这份半成品补成可用模块。
  用户**明确授权本次由模型写代码**(CLAUDE.md §6.0 的例外条款),并**限定不许动 `spi_master.v`**。
  分两步:① 用分帧方式修好初始化;② 补完正常工作态(等 `set_in` 沿 → 锁存码值 → 分两帧发出 → 等下一个)。

## 提示词

```
① 按照分帧的方法帮我修复adc_9833文件spi模块别动

② 帮我把正常工作状态也写完，就是init结束后等待setin边沿就锁存输入的码值
   并分帧发送出去然后等待下一个数值
```

## 模型回答

**① 相:** 原文件有三处硬伤,都不是风格问题:

| 位置 | 原状 | 后果 |
|---|---|---|
| 例化 `.cs()` / `.mosi(dac_mosi)` | 端口名根本没写对,且 `dac_mosi` 未声明 | `adc_sclk`、`adc_mosi` **两根线全程无人驱动** |
| `output reg adc_sync` | 实际由 `spi_master` 的 `cs` 驱动 | 类型冲突 |
| FSM 缺 `INIT`/`DELAY`,末尾是空壳 `FINISH` | — | 只能发一帧 |

修法:**一次 `start` = 一帧 16 位**,`cs` 由 `spi_master` 自动分帧,帧间隔用 `DELAY`(1024 拍)拉开。
初始化 4 帧 `0x2100 → 0x570A → 0x428F → 0x2000`。

**② 相:** 加 `NORMAL / GAP / NORMAL_WAIT` 三态 + `freq_word_f` 查表(28 位分两帧,
`{2'b01, c[13:0]}` 再 `{2'b01, c[27:14]}`),`set_in` 上升沿检测,`set_pending` 标志位。

**关键设计点(不是模型主动想到的,是推演手册表 9 推出来的)**:
`set_pending <= 1` **写在 `case` 之后、无条件执行**,而不是只在 `NORMAL_WAIT` 里判。
理由:一帧要 ~1.3 ms,PS 打触发的时刻不受硬件控制,沿极可能落在**发射中途**;
只在 `NORMAL_WAIT` 判会丢触发。这条后来用变异测试坐实了(见下)。

## 验证方式

**工具**:Vivado 2025.2 CLI(`xvlog` / `xelab` / `xsim`),装在 `/home/hyp/xilinx/2025.2/Vivado/bin`。
**脚本**:`/tmp/ad9833_chk/tb_smoke.v`(**故意放 `/tmp`,不进仓库** —— 仓库里的 `sim/` 归用户写)。

手法:tb **只观察三根引脚**(`adc_sclk` / `adc_sync` / `adc_mosi`),不窥探 DUT 内部;
在 `adc_sclk` **下降沿**采样(`CPOL=1/CPHA=0`,从机在下降沿取数),MSB first,每 16 位成一帧。
`PWR_WAIT` 覆写为 100 拍以缩短仿真,`CS_SETUP` / `SPI_HALF_T` / 帧间隔**保持真值不动**。

### 用例

| 帧 | 来源 | 期望值 |
|---|---|---|
| 0–3 | init | `2100` `570A` `428F` `2000` |
| 4–5 | 更新① `code=0xA3D70A`(**故意喂 init 里那个频率字**) | `570A` `428F` |
| 6–7 | 更新② `code=0x1234567` | `4567` `448D` |
| 8–9 | 更新③ `code=0x0AAAAAA`,**触发故意打在更新②两帧发射中途** | `6AAA` `42AA` |

### 三条结果

| 跑法 | 结果 | 结束时间 |
|---|---|---|
| **基线(当前 RTL)** | **10/10 PASS** | 4.438 ms |
| 变异 B:`c[27:14]` → `c[27:15]` | **帧 5 / 7 / 9 FAIL**(MSB 帧全挂),帧 4/6/8 全过 | 4.438 ms |
| 变异 C:后置锁存加 `&& state == NORMAL_WAIT` | **帧 6–9 MISSING**,tb 卡死 | **6 ms 超时** |

**三条结论**:
1. **两条查表函数互证** —— 更新①喂 `0xA3D70A` 后发出的 `570A / 428F`,与 init 的第 2、3 帧**逐字节相同**。
   这证明 `freq_word_f` 和 `init_word_f` 用的是同一条手册表 9 规则(第一次写 = 14 LSB,第二次 = 14 MSB,
   两次 `D15,D14` 都是 `01`)。
2. **"发射期间的沿不丢"确有功能** —— 变异 C 只动了那一行的位置语义,更新①的触发(落在 `NORMAL_WAIT`)照样过,
   更新②的触发(落在 `GAP`,即两帧发射中途)**直接消失**。说明那行位置是必需的,不是装饰。
3. **MSB 帧路径不是"顺带过"的** —— 变异 B 精确命中帧 5/7/9 而放过 4/6/8,判据有区分力。

⚠️ **未验证的**:
- **没上板**。AD9833 实物是否真的接受这 4 帧、真的输出 1 MHz,一次都没测。
- `t8 ≈ 256 拍 = 5.12 µs` vs 手册上限 `t4 − 5 ns = 10.24 µs` —— **仍是逐拍推源码得出的**,
  不是测的。要一次 ILA 才能坐实。
- 变异 C 里 tb 卡死是**我的 tb 同步方式**导致的(`wait(frame_i >= 7)` 等一个永远不来的帧),
  不是 DUT 死锁 —— 已加看门狗把"挂死"变成可读 FAIL。

## 纠错轨迹

### ① 模型怀疑项目自己的初始化常数是错的(错了,项目是对的)

看到 init 第 3 帧是 `0x428F`,模型按 `D15,D14` 解码成 `01`(FREQ0 低 14 位),**当场断言**:
"MSB 帧应该是 `0x828F`,项目写错了。"

**没有直接改代码,先去翻手册表 9**:

> `B28 = 1,HLB (D12) = X` …
> `0100 0000 0000 0000` → FREQ0 寄存器写入(`D15, D14 = 01`),14 个 LSB
> `0111 1111 1111 1111` → FREQ0 寄存器写入(`D15, D14 = 01`),14 个 MSB

**B28=1 时两次写入的 `D15,D14` 必须完全相同 **(都是 `01`)**。** 所以 `0x428F` 是对的,
`0x828F` 反而会把地址指到 FREQ1 去。**模型的"纠正"是错的,项目原来的常数是对的。**

> 教训与 [LLM-013] 同源:**"看起来该是这样"不等于手册是这样。** 差一步就改坏了。

### ② 模型报了一个假 FAIL —— 期望值算错(本项目第三次"量具错")

首轮仿真输出:

```
frame 9  got=42aa  exp=6aa9  FAIL
frames_captured = 10 / 10   fail = 1
```

模型**第一反应是"RTL 有 bug"**。但帧 7 走的是同一条 MSB 路径却 PASS 了,路径不是整体坏的 —— 这个矛盾才逼着回头查期望值本身。

手算复核:`code = 28'h0AAAAAA`,注意这是 **7 位十六进制数**:

```
0x0AAAAAA = 11,184,810   (不是 0xAAAAAAAA = 178,956,970 —— 模型一开始按 8 位数算的)
>> 14 = 682 = 0x2AA
⇒ 期望帧应为 {01, 0x2AA} = 0x42AA
```

**RTL 输出的 `0x42AA` 是对的,模型写进 tb 的 `0x6AA9` 是错的。**

按 `INDEX.md` 已有的编号口径,这是**本项目「量具错」第 5 次**
(第 4 次见 `LLM-011`:引脚监视器把采样沿写反;更早一次见 `LLM-009`:VCD 解码器把下降沿当采样点)。
**共同点:报错时第一个怀疑对象永远是被测对象,而实际错的是量具。**

### ③ tb 在变异体下挂死 —— 加了看门狗

变异 C 一跑,`xsim` 在 shell 里 120 s 不返回。第一反应又是"xsim 挂了"。用 `run 8 ms` 定量跑一次,
**2 秒就跑完 8 ms 仿真时间** —— 说明仿真本身没挂,是 tb 的 `wait(frame_i >= 7)` 在等一个
被变异体丢掉的帧,`$finish` 永远到不了。

改法:把结果打印抽成 `task report;`,再加一个 `#6000000` 的看门狗 `initial` 块 ——
任何 `wait()` 卡住时也会打一份 `---- TIMEOUT ----` + 结果表。
改完变异 C 就能报出干净的"帧 6–9 MISSING",证据从"卡死"变成"逐帧可读"。

> **这是本轮唯一一处模型主动发现并修掉的自有缺陷。**
> 也说明:**没有看门狗的 tb,会把被测对象的缺陷伪装成仿真器故障。**
