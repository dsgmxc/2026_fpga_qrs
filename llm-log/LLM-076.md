# LLM-076:界面整体 180° 翻转 —— `direct_mode` 与 LVGL 旋转不兼容,改分块渲染;触摸两条路径分开处理

- **日期**: 2026-10-24
- **模型**: deepseek-flash(Claude Code harness)
- **任务**: 用户要求「**能不能把整个页面翻转 180 度**」(面板是翻过来装的)。

## 提示词

```
能不能把整个页面翻转180度
```

## 方案

**显示**:用 LVGL 8.2 自带的软件旋转,但**必须放弃 `direct_mode`**。

| 方案 | 为什么不行 / 为什么行 |
|---|---|
| `direct_mode` + `sw_rotate` | ⛔ LVGL 的 `draw_ctx->buf_area` 在 direct_mode 下是**整屏**,而 flush **每个失效区各调一次** ⇒ `draw_buf_rotate_180()` 会把整块 1.2 MB 帧缓存原地翻转,一个失效区翻一次、两个区就翻回原样;而且每帧在**非缓存** DDR 上逐像素交换,帧率直接崩 |
| 分块缓冲 + `sw_rotate` | ✅ 每块最多 `DRAW_BUF_ROWS = 64` 行(128 KB,cached RAM)。LVGL 在 flush 前把**这一块**原地翻 180° 并**把矩形坐标一并镜像**(`lv_refr.c: draw_buf_rotate_180`),flush 只管按行拷进后台帧缓存 |

帧缓存从此存的是**面板朝向**的图像 ⇒ `sync_invalid_areas()` 必须先把每条 `inv_areas` 做
`mirror_area()` 再拷,否则局部刷新会退回两帧前的内容。

**触摸(两条路径,必须分开处理)**:

| 路径 | 谁翻 | 说明 |
|---|---|---|
| 单指 → LVGL `read_cb` | **LVGL 自己翻** | `lv_indev.c:332` 按 `drv->rotated` 镜像指针坐标(`lv_hal_disp.h` 里 "Does not update coordinates for you!" 是**过时注释**)⇒ `read_cb` 必须交**原始**坐标,再翻一次就会落到对角 |
| 多指 → `ui_demo.c` 捏合 | **我们自己翻** | 它走 `LV_PortIndev_GetTouchState()` 的缓存,不经过 LVGL ⇒ 在 `LV_PortIndev_Update()` 里镜像 `g_touch_state` |

两处共用一个开关 `CV_PANEL_ROTATE_180`(`app/pynq_regs.h`),显示/触摸不可能单边漂移。

## 纠错轨迹

| # | 事情 | 结论 |
|---|---|---|
| 1 | 第一想法是"direct_mode 里把 `sw_rotate` 打开就行" | **不行**。读 `lv_refr.c` 才能看见:`draw_buf_rotate_180()` 作用在 `draw_ctx->buf_area` 上,direct_mode 下那是**整屏**,且每个失效区都走一遍 ⇒ 偶数个失效区等于没翻。改为分块缓冲 |
| 2 | `lv_hal_disp.h:98` 写着 "**Does not update coordinates for you!**",据此准备在 read_cb 里手翻触摸坐标 | **会翻两遍**。`lv_indev.c:332` 已经按 `rotated` 翻过指针坐标;头文件那句是旧注释。最终 `read_cb` 交原始坐标 |
| 3 | 但 `ui_demo.c` 的捏合手势**不经过 LVGL** | 那份缓存必须单独翻,否则"单指能点、双指捏合错位"。在 `LV_PortIndev_Update()` 里翻,并用同一个宏 |
| 4 | 镜像公式写成 `W-1-x` | 对越界坐标(`uint16`)会**回绕成一个大数**;必须先判越界再翻,越界点置 0 并计数(沿用"不夹紧、不缩放"的原规则) |
| 5 | 验证同步时只抓一帧 | 抓帧看不出"后台是上上帧"——那一块恰好没变就正常。写 `fb_cmp.py` 逐像素比两块,多次采样才坐实 |

## 沉淀

- 候选 `skill/rotation-vs-direct-mode/`:LVGL 的软件旋转作用在 **flush 收到的缓冲区**上;
  `direct_mode` 下那块缓冲区是整屏,旋转会按**失效区个数**重复执行且走非缓存内存
  ⇒ **要旋转就别用 direct_mode**,或自己接管旋转。
- 候选 `skill/two-consumers-one-coordinate-space/`:同一份触摸数据被两条路径消费
  (LVGL 内部 + 应用自己的手势),框架只翻其中一条 ⇒ 先查框架是否已翻,再决定手动翻哪一份;
  **翻两次和漏翻一样是"点不准"**,而且方向正好差 180°。
