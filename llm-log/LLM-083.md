## 模型回答

1. **先分清「测量错」还是「判据错」**:用户看到的是 CISS **117.1 异常**、COSS 17.4 /
   CRSS 6.9 正常。把 117 分那条扫压的 CISS 曲线与健康基线逐点比,**整条曲线在 ±1 %
   以内** —— 测量没有问题,是判据把平台漂移当成了器件故障。
2. **分数的来源**:4 个特征里贡献几乎全在**特征 3 `log10(V75/V25)`**。
   该次偏差 **−0.021 log10(−4.8 %)**,而旧模型的 σ 只有
   `1/√2.2238e5 = 0.0021 log10(0.49 %)` ⇒ 2.4 % 就够 25 分、4.8 % 就够 100 分。
   `V25`(1.3 V 附近的交叉点)随平台状态整体移动,`V75` 很稳 —— 比值把 1 % 的平台
   平移放大成 ~5 %。
3. **旧协方差的口径**:来自 **10 颗 TH521 器件之间的差异**,完全不含**同一块板
   重复扫压**的差异。这是建模时漏掉的一个方差项,不是阈值定低了。
4. **修法**:`fit_anomaly_model.py` 增加 `--repeat`
   - 中心 = **4 轮本机健康重复扫压的特征均值**(不再用单次基线);
   - 协方差 = 器件收缩协方差(reg = 0.1)**+ `diag(平台重复性方差)`**;
   - 阈值 25 / 100 不变(改模型口径,不改判据)。
5. **重复性数据只收当前校准方案**:日志里 7 轮完整已校准扫压,5757 / 6627 / 7304 用的是
   旧的**按腿校准**(a ≈ 1.0758),8170 / 8913 / 10127 / 11055 才是 2026-10-29 起的
   **通道级校准**(a ≈ 0.983)。混在一起会把两套系数差算成"平台重复性",把灵敏度白白吃掉。
6. **新模型自检**:4 轮重复扫压得分最大 **2.40**;把用户遇到的那次扫压(日志第 11055 行)
   喂给同一份 C 代码:**CISS 1.24 / COSS 1.29 / CRSS 0.64 → 正常**。
7. **代价如实记**:CRSS 平台重复性 σ ≈ 2 %(4 轮之间有一次 ~3.7 % 的重新校准台阶),
   所以 CRSS **纯增益 10 %** 从旧模型 53.2 降到 **13.6(正常)**;要到 20 % 才 62.9(待查)、
   30 % 才 140.1(异常)。测试里把这条写成显式断言,不藏起来。

## 纠错轨迹

1. **重复性总体一开始收多了**:把 7 轮全收进来,旧校准那 3 轮让协方差整体变大,
   注入 ×1.10 的 CRSS 只剩 11.4 分 —— 判据被稀释。**发现方式**:逐轮打印特征值,
   看到两组之间是"台阶"而不是"抖动"。**改法**:`--min-line 8170` 只收当前校准方案。
2. **提取脚本漏掉 CISS**:`[proto] 扫压第 1 腿:CISS` 打在"扫压开始"横幅**之前**,
   从横幅起扫就永远收不到第一条腿 ⇒ 改为用表头 `CISS+COSS+CRSS` 初始化当前腿。
3. **提取脚本把 3312.001 写成 3312**:`%g` 只有 6 位有效数字 ⇒ 改用 `str()`
   保留日志原值;整份 CSV 重新导出。
4. **原型在 100 V 处返回 NaN**:插值函数对 `t >= 最后一个点` 直接返回 NaN,
   而 C 版是**钳到末段**。不先对齐这两处,C 与 Python 的注入分数没法逐位对。
5. **板上的 make 不能信(旧的坑又踩)** —— 板 RTC 比宿主慢 26 天,上传文件 mtime 在"未来"。
   继续按 `LLM-081` 的纪律:**先 `rm -f` 目标对象再编**,判据是产物里的常量字节,
   不是 make 的输出。
6. **没有为了"保住灵敏度"去换特征**:考虑过把 `V75/V25` 换成固定比值(`C2/C10`、`C3/C20`)
   或局部斜率 —— 它们更稳,但那等于换了一个模型语义,而且仍要靠重复性数据定尺度。
   选择**保留物理含义明确的膝宽比 + 把平台重复性显式写进协方差**,并把代价写进测试。
7. **没有把"已上板"写成"已显示"**:屏幕上的 AI 结果要等一次新扫压才会刷新,
   本轮只写到"新模型在跑、同数据复算正常"。

## 沉淀

→ 候选 `skill/covariance-needs-every-variance-source/` —— 无监督判据的协方差必须覆盖
**所有真实存在的变异来源**(器件间 / 批次间 / 同一台仪器的重复性 / 校准状态),
漏一项就会把"平台的正常漂移"当成"器件的异常";判据失效时先查**方差项**,不是先调阈值。
→ 与 `skill/unsupervised-baseline-absorbs-platform-offset/`(LLM-079)互补:
那一条只把**中心**挪到本机,本条把**尺度**也算上 —— 只挪中心不扩尺度,平台一换状态就误报。
→ 候选 `skill/one-model-two-calibrations/` —— 同一份日志里混着两套校准方案的扫压,
   **不能当作同一总体的重复样本**;分组前先核对每轮用的是哪套系数。
