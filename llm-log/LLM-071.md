# LLM-071:「全部」页三卡不显示数据 —— 根因是 UI 更新函数无人调用;顺带拉起服务并归档三腿全量扫压

- **日期**: 2026-10-23
- **模型**: deepseek-flash(Claude Code harness)
- **任务**: ① 拉起板上服务;② 排查「单点测量 → 全部」测完不显示数据;③ 记录当前扫压数据并关机。

## 提示词

```
帮我拉起服务先
现在看看，刚刚没插网线
单次测量的全部页面测试完怎么不显示数据
记录下当前的扫压数据，然后关闭系统
```

## 模型回答

1. **拉起服务**:板上电后先查 `fpga_manager = unknown`、位流 md5 与 `c92c7ed5…` 一致,再
   `systemctl start qrs-ui`;核对 `dmesg` 恰 1 条 `writing qrs.bin`、FCLK0 50.0000 MHz、
   `0x14 = 0x00000`;抓 DDR 帧缓存确认首页渲染正常。
2. **定位「全部」页无数据**:
   - 日志证明测量链正常 —— 三腿各有完整 `Z / Cs / Cp / D`,不是采集或解算失败。
   - 代码:`UI_Demo_UpdateSingleCapacitance(path=0/1/2)` 只更新**单卡** label,
     且有 `path != g_ui_single_path` 早退;「全部」模式下 `g_ui_single_path = 4` ⇒ 三腿全被挡掉。
   - 「全部」页显示的是 `g_all_result_labels[0..2]`,而唯一写它们的
     `UI_Demo_UpdateAllCapacitance()` **全工程无人调用**(仅 `_retired/pynq_protocol_stub.c` 调过)。
   - 修法:在 `UpdateSingleCapacitance()` 里检测「全部」模式并转交 `UpdateAllCapacitance()`
     (UI 自己知道当前是哪个布局,不让协议层去猜)。**只改 `src/c_ui/ui/ui_demo.c` 一处**。
3. **部署**:宿主编译通过 → 推板上 `/home/xilinx/c_ui_src/` → 板上 `make -j2` → 按红线 #4
   **整机软重启**(不 restart 服务),新上电周期位流只加载一次;新 `c_ui` md5 `ce35bc8f…`。
4. **归档扫压**:用户随后跑了一次 CISS+COSS+CRSS 全量扫压(0.1→100 V,60 点/腿),
   从 `/var/log/qrs-ui.log` 第 10617–10989 行解析出 **180 点**,
   写 `report/measurements/20261023_three_leg_full_sweep.md` + 逐点 CSV + 原始日志存档,
   然后停服务、`sync`、`shutdown -h now`。

## 纠错轨迹

1. **第一次读网口状态时 `ip` 命令没有输出** —— 实际是 `enp2s0` 处于 NO-CARRIER、无 IP;
   用户随后说「刚刚没插网线」⇒ 硬件链路问题,不是脚本问题。上电前先看链路,不看 ping。
2. **读帧缓存前 `0x60` 的一次性 Python 命令写错**(`os.open` 返回 int 而非文件对象),
   报 `AttributeError` ⇒ **没有把「读不到前台索引」当成「显示坏了」**,改为直接 dump 两块帧缓存
   并用 md5 比对(本次两块内容相同)。
3. **修复后没有保留视觉证据** —— 用户跑三腿点测时我未主动抓帧;事后板子已关机,无法补。
   ⇒ 记录里明确写「未确认」,不用「应该显示了」代替证据。

## 沉淀

- 候选 `skill/one-writer-but-no-reader/`:**函数存在、接口存在,但没有调用点** ——
  「能找到定义」不等于「数据会到它那里」;排查显示问题时先 grep **调用点**,不 grep 定义。
- 扩展 `skill/classify-by-state-not-by-intent/`:本次「日志有测量值」证明链条前半段通,
  「卡片显示 --」证明后半段断;两者分开定位,不混成一个「测量失败」。
