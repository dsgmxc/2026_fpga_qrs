## 模型回答

读工程后发现 `qrs.v` 是纯 PL 顶层(`clk_wiz` + `ila` + `dac_1220` + `adc_9833` +

## 纠错轨迹

### 1. 🔴 模型把 `X_INTERFACE_PARAMETER` 说成"时钟被识别的必要条件"(根因是模型自己的探针设计缺陷)

模型做探针 1 时,V1(无属性)/V2(仅 `X_INTERFACE_INFO`)报
`ERROR: [BD 41-758] clock pins not connected`,`V3`(带 `PARAMETER`)不报,
于是下结论:「光有 `X_INTERFACE_INFO` 不够,`X_INTERFACE_PARAMETER` 才是让时钟脚被识别为
时钟接口的那一条」。

**这个结论是错的。** 根因:探针 1 **只对 V3 跑了 `apply_bd_automation`**,V1/V2 的时钟脚
是**构造出来的悬空**,不是 Vivado 的行为差异。
改法:重做探针 3,**对四个变体全部跑 automation** → 全部 rc=0,`validate_bd_design` 全部 rc=0。
**真实结论:属性和 `s_axi_*` 常规命名可互相替代(二者有其一即可);属性真正买到的是对
接口名的控制权**,而接口名是 `apply_bd_automation`、脚本与 `.hwh` 定位对象时用的东西。

> ⚠️ 与 `LLM-023` 的探针教训**同型**:都是「**探针设计缺陷被读成被测对象的结论**」。
> 区别是 LLM-023 那次模型没下结论、回头看了解析过程;这次模型直接下了结论。

### 2. 🔴 模型断言 `GPIO_0` 会展开成 3 个端口、`_tri_i` 会卡 DRC(实测:Vivado 自动插 IOBUF)

用户把 `axi_gpio_0` 的 GPIO 接口 `Make External` 后,`.bd` 里该外部接口的 `port_maps`
显示 `TRI_I` / `TRI_O` / `TRI_T` 三条。模型据此断言:「会展开成 3 个顶层端口,
`_tri_i` 是输入、没球号会被 DRC 拦下;给它绑 H15 又会与输出冲突 —— **两头堵**」。

**是错的。** 模型随后建了 `gp.tcl` / `gp2.tcl` 探针实测两种配置,`make_wrapper` 后
读生成的 wrapper:

| 变体 | `C_ALL_OUTPUTS` | wrapper 顶层端口 |
|---|---|---|
| `GPIO_bidir` | 0(默认双向) | `inout [0:0] GPIO_bidir_tri_io` |
| `GPIO_out_only` | 1 | `output [0:0] GPIO_out_only_tri_o` |

**Vivado 在 BD 边界自动插了 IOBUF**,把 `TRI_I`/`TRI_O`/`TRI_T` 合成**一个**顶层端口。
`.bd` 里的三条线是**接口成员的内部表示,不是顶层端口**。两种配置都能直接绑球号驱动 LED,
**不存在 DRC 冲突**。

> 教训:**BD 的接口表示 ≠ 生成的 wrapper 端口。** 要断言顶层端口长什么样,
> 唯一可信的方法是 `make_wrapper` 之后读 wrapper 文件。

### 4. 🟡 探针 TCL 嵌套引号错误,导致探针跑一半失败

`gp.tcl` 里写了 `P " $m -> [expr {$pn eq "" ? \"(不存在)\" : $pn}]"` ——
`{}` 块内的 `\"` 转义在 TCL 里不成立,报语法错,探针只跑到一半。
**改法**:去掉嵌套引号,改用 `if {$pn eq ""} { set pn "NONE" }` 先行赋值。
重跑后一次通过。

### 5. 🟡 模型误读 `.hwh` 标签计数(与 LLM-023 同型,第二次)

用 `grep -oE '<[A-Z_]+' | sort | uniq -c | head -15` 统计,`head` **截断了 count=1 的标签**,
模型据此一度认为"没有 `MEMRANGE`"。改用 `grep -o "<MEMRANGE" | wc -l` 直接计数才拿到
正确值 `1`。**浅搜索的截断/遗漏产出否定结论 —— 本项目第 N 次**(前见 `LLM-012`/`LLM-021`/`LLM-025`)。

### 6. 🟢 一处正面记录:模型拒绝把"结构级证据"说成"实测结论"

追查「`module_ref` 带 AXI 是否进 PYNQ 的 `ip_dict`」时,模型走读了
`hwh_parser.py` 源码(`:177` `instance2attr` 由**全部** MODULE 建表;`:269` `mod.iter("MEMRANGE")`
**递归**,所以嵌在 PS7 里的条目也能命中;`:286` `self.ip_dict[full_name] = {}` 在 if/elif **之外**、
**无条件执行**),得出结论"会进",但**明确标注为「走读源码 + 实测 hwh 结构,不是真解析器跑出来的」**,
并如实报告「想跑真解析器时被权限拦下,理由是它来自本会话下载的外部代码、用户未点名该来源」,
**没有绕过**。

事后上板验证:`ol.ip_dict` 确实含 `axi_gpio_0` —— **恰好印证了走读结论**,
但那是**事后**才知道的,记录里不据此改写当时的证据强度标注。

**顺带查实**:`BDTYPE` 全文只出现 1 次,在 `axi_smc` 上(它有 `BD="system_axi_smc_0"`,
是**嵌套 BD**)⇒ **`BDTYPE` 只出现在层次化模块上**,普通 IP 与 `module_ref` 都没有。
这条把 `hwh_parser.py:282` 那条会追加 `/S_AXI` 后缀的分支锁死为**不触发**
⇒ 将来 `cv_axi_lite_slave` 挂进 BD 后,PYNQ 里的名字是**裸实例名**,不会变成 `xxx/S_AXI`。
