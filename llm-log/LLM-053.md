## 模型回答(做了什么)

### 一、前提:本上电周期唯一那次 `Overlay()` 已被 `main.py` 用掉

`tools/adc_probe.py` 原有每条命令都要求先 `init`,而 `init` 里的 `Overlay()` 会撞上
已加载的 PL(`lcd_fb_reader` 是自由运行的 AXI 主机,第二次 `Overlay()` 锁死 HP 口连带 CPU,
**不可恢复**)⇒ 探针在这个状态下**一条命令都用不了**。

解法:给 `adc_probe.py` 新增 **`attach`** —— 只做 `/dev/mem` 的 MMIO 映射,
**不加载位流、不碰 FCLK0**(`/dev/mem` 的 mmap 不排斥多进程);成功后主动占住 `st['ol']`,
复用 `cmd_init` 开头既有的守卫来拦住后来的 `Overlay()`。
⚠️ `init` 与 `attach` **每个上电周期只用其一**。

### 二、取数并**目视判读**(用户要求的"自己看")

采了 1 MHz / 100 kHz / 2 MHz @ 10 MSPS 与 1 MHz @ 65 MSPS 若干组合(全部在**端口 B**;
端口 A 悬空、平坦 4076),写成六联 PNG 后在本地读图判读 ——
**不是只看 p-p 数字**:1 MHz @ 65 MSPS 那一联目视数峰 ≈ 65 点/周期,
与 DFT 给出的 `L=195, M=3`(即 65 点/周期)一致。

### 三、★ 发现 65 MSPS 已经是通的 —— 且 RTL 一行不用改

```
0x88 = DIV 2    ⇒ adc_clk = 130/2 = 65.000 MHz
0x90 = 0x00000003 (mmcm_locked=1 done=1)
[go] done 置位,耗时 0.0022 s      ← 与 DIV=13 相同,无额外延迟
DIV=2 / PH_OFF=0 / 1 MHz: p-p 42,250 点里 3.85 个周期
```

全范围 `eye` 扫 ⇒ **可达刻度只有两个**:`−1` = 端口 A(死)、`0` = 端口 B(DDS 正弦)。

**交叉验证**(同一路 1 MHz 正弦,两套完全不同的窗结构):

| 采样率 | L | M | 点/周期 | mag(码) | 残差 rms |
|---|---|---|---|---|---|
| 10 MSPS(DIV=13) | 250 | 25 | 10.00 | 18.182 | 2.054 |
| **65 MSPS(DIV=2)** | 195 | 3 | 65.00 | **18.501** | 1.488 |

⇒ 幅值只差 **1.8%**,解调算法与 65 MSPS 通路都对。

### 四、★ 真正的阻塞点是一行 C

`c_ui/app/pynq_regs.h::cv_adc_phase_center()` 在 `P=2` 算出 **`+1`**,
而 `0x88` 的寄存器合法范围是 `[−P/2, P−1−P/2] = [−1, 0]` —— **不相交**
⇒ 刻度**永远命中不了**,`done` 不置位,界面表现就是"**点了没反应**"。

同一个文件里 `cv_adc_phase_center_b()`(端口 B)**本来就有折回**
(`t > hi` 时 `t -= P`),P=2 给 `0` ✅ —— **A 少了同一条**。补上后折回得 **−1**,正是实测值。

`measure_config.c::adc_window()` 同病:P=2 返回 `[1,1]`,与合法范围不相交,
`NudgePhase` 会把刻度钳到 1。同样折回 ⇒ `[−1,−1]`。

📌 **折回只改动 P=2 这一档**;P=3/4/5/10/13/26/65/130 上界都不越界,**逐位不变**
(C 与 Python 两侧逐个对拍 **9/9 一致**)。

⇒ **`adc_capture.v` 只改了 3 处注释,RTL 逻辑零改动** —— 它本来就支持 65 MSPS;
作废的是它注释里"65 MHz 接不出来 / 必须配 IDELAYE2"那几段判断(换排线后就够了)。

### 六、信号质量:限制在前端,不在算法

| | 值 |
|---|---|
| INB p-p | **44 码 = 21 mV**(满量程 2 V ⇒ **1.07%**) |
| 直流坐点 | 4076/4096 = **99.5% FS**,**离上轨只剩 9 码** |
| 解调 SNR | **22.5 dB**(残差 1.035 码 ≈ ADC 自身抖动底) |

解调残差已压到 ADC 的量化抖动底(±1 码)⇒ **算法侧没有余量可挖**。
要提信噪比只有①前端加增益、②加大激励两条路 —— ⚠️ 但直流坐在 4076,
**任何超过 ~9 码(≈4 mV)的正向摆幅都会削顶**,加增益之前必须先解决偏置点。
📌 `ADC_SAMPLE_VFS_PP = 2.0` 与 `ADC_SAMPLE_R_TIA = 1000` **两者都未标定**,码值只有相对意义。

## 纠错轨迹

1. 🔴 **★ 最要紧的一条:我做的 OEB 测试是无效的,已撤回。**
   我写 `wr 0x88 0x0002050D`(OEB_N=1)后执行 `dump 13 5 200`,得 p-p=39,
   **一度要把它记成"OEB 未复现"**。回看 `tools/adc_probe.py::cmd_go()` 才发现:

   ```python
   cfg = (div & 0xFF) | ((ph & 0xFF) << 8) | ((1 if cont else 0) << 16)
   m.write(R_ADC_CFG, cfg)     # ← 把 0x88 整个重写
   ```

   `cfg` **只含 DIV / PH_OFF / CONT**,**不含 bit17(OEB_N)、bit18(PDN)**
   ⇒ `dump`/`wave`/`eye` **每执行一次就把 OEB 清回 0**,
   我那句 `wr` 在采集起来的那一刻就被覆盖,**从头到尾测的都是 OEB 关**。
   ⇒ 正确结论是「**没测到**」,不是「未复现」;
   **第 47 次"`OEB_N=1` → 128 点全同 4095"的结论未被推翻,仍然有效**。
   📌 **教训**:**「下发参数的命令」和「执行动作的命令」合在一条里时,
   后者会静默覆盖前者设定的一切** —— 而回读 `0x88` 恰好显示的是**被覆盖后的值**,
   看日志也发现不了。**判据应该是回读位域,不是回读整个寄存器字。**
   已在三处文档撤回,并给 `docs/project_state.md` 第 47 次块加了注。

2. ⚠️ **`fe_now` 未初始化就参与除法** —— 首次 `wr 0x80` 之前 `fe_now = None`
   ⇒ `TypeError: unsupported operand type(s) for /: 'float' and 'NoneType'`。
   改为在开头就用 DDS 默认码 `0x0A3D70A` 初始化。

3. ⚠️ **把"真值"和"固件收到的值"混为一谈,导致所有行都判成"报错"。**
   DDS 输出**实际是被量化的**(`0x0A3D70A` → 999999.9776 Hz),
   而**固件收到的是标称整数 1000000**。我用前者去比对"是否整除",
   `abs(10000000/999999.9776 − 10) = 2.24e-7 > 1e-9` ⇒ `exact` 恒 False。
   加一张"寄存器码 → 标称 Hz"的映射表后正常。
   📌 与 `LLM-052` 的 DFT 讨论同源:**两个数不是同一个量,不能互相代入**。

4. ⚠️ **解调残差的相位符号写反**,配 `A·cos(2πMk/L − atan2(sq,si))` 而非 `+ phi`,
   得到 SNR −3.2 dB 之类的荒唐值。**是靠"好的采集残差应等于 ±1 码抖动底"这条预期发现的**
   —— 若没有这条预期,一堆负数残差看起来也"像个数"。改对后 100 kHz 残差 1.035、SNR 22.5 dB。

5. ⚠️ **`pkill -f "adc_probe.py serve"` 把我自己的 SSH 会话杀了**(rc = −1):
   `pkill -f` 匹配**整条命令行**,而我的命令行里就含这个字面串。
   改用不自匹配的写法:`pkill -f "adc_prob[e].py serve"`。
