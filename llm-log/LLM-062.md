## 模型回答

**第一问(回路不切换)**:查实根因不是 bug,是**一处从未落地的设计**。`0x1C`(RELAY_CFG)
能写的地方有三处,一处都没写:

| 位置 | 现状 |
|---|---|
| PL `relay_ctrl.v` | ✅ 白名单互锁 / 原子翻转 / 稳定计时 / err_code,**2026-10-10 已上板验证** |
| C 界面 `relay_view.c` | ⛔ 文件头写着「只读,一个寄存器都不写 —— 写入权归 Python 侧」 |
| C 界面 `pynq_protocol.c:RequestPath()` | ⛔ 只 `printf`「只读回读,未改硬件」 |
| Python `drivers/relay.py` | ✅ 写得完整、实测过 —— 但 **`main.py` 只 import `drivers.board`,零调用方** |

⇒ 硬件永远停在复位值 `ALL_OFF(0x10)`。**顶栏那一栏没在说谎**(它读硬件真值),
说谎的是**按钮高亮** —— 按下去只换了个颜色。

连带查实四处「假装」,全部有代码注释自认:

|---|---|

| 点 RG 单点 | 打印「无读数可填」,卡片留 `--` |
| 扫压 | 把**同一个 `cs_pf` 写进三条曲线** |

**第二问(为什么不能用 VH/VL 的相位差)**:追查前序 `~/Desktop/qrs`(STM32 工程)的 RG 算式,
逐字抄下来是 `Rg = Re(Z) + 0.7`,`Z = R0·(VH−VL)/VL`(复数)。
问题在于 `Z` 要 **VH 与 VL 的相对相位**,而当时两路是**两次独立采集**,
解调基准锚在**各次采集的第 0 点**(`adc_sample.c:372`):

```
Φ_A = 2π·f_e·t_A + ψ_DUT
Φ_B = 2π·f_e·t_B + ψ_R0
要的相位差 = (Φ_A − Φ_B) − 2π·f_e·(t_B − t_A)     ← 这一项软件不知道
```

`t_B − t_A` 中间隔着一次 8192 点读回(~2.5 ms),而:
- 1 MHz 下要 1° 精度 ⇒ 时间要准到 **2.8 ns**;板上最细的 50 MHz `clk_axi` 只有 **20 ns = 7.2°**;
- 且激励是 AD9833 的**板载 25 MHz 晶振**,与 FPGA 时钟**不同源**;
  2.5 ms 内漂 100 ppm ⇒ 250 ns ⇒ **1 MHz 下 90°**。

⇒ **任何"事后补时间差"的方案在 1 MHz 下都不成立。不是算术问题,是两次采集的相位原点本来就不同。**

**第三问(用户追问「不是已经能采到数据了吗,做 dft 相除不行吗」)**:不行,原因不是 DFT 的算法,
是**两个相量的原点不同**。DFT 本身完全正确,但 `∠Z` 里混进了 `2π·f_e·(t_B − t_A)` 这个
软件不知道的量。用户可以量到"相位差",但那不是 DUT 的相位差。

**第四问(用户追问「adc 是同步采样为什么不是统一相位」)—— 这一问把我推对了。**
用户是对的:**AD9238 在同一个转换沿上同时采 A 和 B**,产生一对同步样本,
这两个字在**同一条总线**上先后送出(tick −1 与 tick 0 就是同一个转换周期的两个半周期)。
而 `adc_capture.v:275` 当时是:

```verilog
wire samp_en = (tick == $signed(ph_off));   // 每个 ADC 周期只命中一个 tick
```

⇒ 同步的那一对里 **B 被扔掉**,要 B 只能再发一次 GO(一万多个转换周期之后)。
**不是 ADC 不同步,是采集器没接那股同步数据 —— 它就在线上,一个 tick 之遥。**
前序 `ad9238_capture.c::AD9238_Deinterleave` 正是这么做的。

于是本轮改成:一次 GO 里 A 窗、B 窗各写一次(偶地址 A、奇地址 B),缓冲 8192 → 16384 字
(每通道仍是 8192 点 ⇒ 解调窗长表一个字不用改)。

**第五问(用户拍板「把系统关了,把项目修复完整再上电」)**:把原本分两批的计划**合成一批**,
一次修完、一次综合、一个位流周期。执行顺序:

```

⑤ 上电:加载位流(本周期仅此一次)→ 板上重编 c_ui → 验证
```

## 纠错轨迹

**① 我一开始把范围判窄了 —— 漏掉「挡位」这一项。**

用户选的范围是「回路全语义修正」,我在计划里把 `0x18`(挡位)排除在外。这是**按用户原话执行的**,
但我没有主动指出一个后果:前序为 RG **强制 A 挡(10 Ω)并锁换挡**(`pc_protocol.c:282-284`),
而本项目停在 **B 挡(100 Ω)** ⇒ `VL/VH = 100/(100+Rg)`,Rg ≈ 12 Ω 时差量只有 **11%**,
噪声占比大得多。**公式没错(R0 是回读来的),但对比度差一个数量级。** 这一条我写进了代码注释和文档,
没有擅自改挡位(改了就是超范围)。

**② 我把「假话」印在了 4 个地方,改一处没改另外三处。**

`relay_view.c` 文件头写着「C 界面只读」,同一句话还印在 `relay_view.h`、`pynq_regs.h`、
`pynq_protocol.c` 的启动 `printf` 里。我先只改了 `.c` 的文件头,是**用户的范围要求**
(「回路全语义修正」)逼我去核对"还有哪里在说同一句假话"才发现的。
⇒ **规则:同一句结论印在多处时,改之前先 `grep` 那句话,不要只改"我记得的那一处"。**
(`report/llm-log/` 是 M11 的正文,日志与注释打架最伤。)

**③ `pynq_protocol.c` 里有我**自己**上一轮留下的「两路相位不相关」结论。**

这个文件 163–178 行有一段注释,斩钉截铁地说"两路是两次独立采集、相位不相关 ⇒ Cp/D 只能填 `--`"。
而本轮改的 RTL 恰好把这条**推翻**了。我不是删掉它,而是**保留原文 + 标注"原稿这一段是反的"** ——
因为那句注释在当时是**正确的**,它是"相位缺口存在过"的物证。删掉它,M11 里那条因果链就断了。

**④ 我自己搭了一处会静默失配的悬崖,自查时才发现。**

`adc_capture.v` 里我把每通道点数抽成 `CH_DEPTH`,但**声明了没用**(两个绕回比较还在写
`BUF_DEPTH/2`)。`xvlog` **不会报**声明未使用的 localparam。是我逐行回读时发现的。
⇒ 改成 `localparam [CH_AW-1:0] CH_LAST = CH_DEPTH - 1;` 并在两处比较里用它。
**这正是本轮要防的那类缺陷(改容量有多道静默闸,2026-10-08 踩过)在同一处的重演。**

**⑤ 用户连续四问,前三问我都答"做不到",第四问才把我推对。**

前三问我的回答都是**正确的**——「不能事后补时间差」「DFT 不能补相位原点」「两次采集相位不相关」。
**但它们全都是"在错的框架内正确"。** 用户的第三问「ADC 是同步采样,为什么不是统一相位」
直接把前提掀了:**我从头到尾假设了"必须发两次 GO",而 AD9238 的数据本来就同时躺在总线上。**
⇒ 我的三次回答里,只有第三次(`adc_sample.h` 的窗口表)包含了推翻自己的线索,
但我当时没往那个方向想。**教训:当用户连续三次追问"为什么做不到"时,该被质疑的是前提,不是论据。**
