## 一、文件级核验:排除「烧的是旧位流」

|---|---|

## 二、官方 C 例程逐帧对照(用户主诉「先确认不是指令问题」)

资料:`/home/hyp/Desktop/硬件资料/AD9833/DDS开发板-点频9833(ok) V2.0/`
调用链:`main.c:48-49` → `AD9833_Init()`(`AD9833.c:28`)→ `AD9833_SetFrequencyQuick(1000, OUT_SINUS)`(`AD9833.c:73`)

| 帧 | 官方 demo | 怎么来的 |
|---|---|---|
| 1 | **`0x0100`** | `AD9833_REG_CMD\|AD9833_RESET` = `(0<<14)\|(1<<8)` |
| 2 | **`0x2000`** | `AD9833_B28\|OUT_SINUS` —— **这一帧顺带清 RESET** |
| 3 | **`0x69F1`** | `freqLo = 0x4000 \| (val & 0x3FFF)` |
| 4 | **`0x4000`** | `freqHi = 0x4000 \| ((val & 0xFFFC000)>>14)` |

`val = (268435456.0/25e6) × 1000 = 10737.418` → `unsigned long` **截断为 10737**(1 kHz)

**对照结论**

| 项 | 官方 demo | 本项目 | |
|---|---|---|---|
| 帧数 × 位宽 | 4 × 16 bit | 4 × 16 bit | ✅ |
| 位序 | MSB first(`Communication.c:89`) | `MSB_FIRST=1` | ✅ |
| 分帧 | FSYNC 低→16 bit→高 | `spi_master` 的 `cs` | ✅ |
| SCLK 空闲电平 | 高 | `CPOL=1` | ✅ |
| **采样沿** | **下降沿** | `CPOL=1/CPHA=0` → 下降沿 | ✅ |
| 终态 | B28=1 / RESET=0 / OPBITEN=0 / MODE=0 = 正弦 | 同 | ✅ |

⇒ **两边落到的寄存器终态完全等价。指令内容没问题。**

**两个"看着像差异、其实不是"的坑(有独立佐证价值,可写报告)**

1. 🔴 **`AD9833_SPI_Init(0, 1000000, 1, 1)` 里的 `clockPha=1` 是死参数。**
   `Communication.c:52-59` 函数体只有 `AD983_GPIO_Init(); return SUCCESS;` —— **四个参数一个都没用**,
   真正的时序在 `AD9833_SPI_Write` 里 bit-bang。
   ⇒ 「官方用 CPHA=1、我们用 CPHA=0」**不成立**;官方实际波形就是 **CPOL=1/CPHA=0**,
   与我们查手册定的 Mode 2 **一致** ⇒ **这是本项目 SPI 模式的第一个第三方独立佐证**。
2. **`ADI_CS_LOW` / `ADI_CS_HIGH` 是空宏**(`Communication.h:55-56` 写着 `// Add your code here`)。
   官方板**根本没驱动 CS**,完全靠 FSYNC 分帧 —— 与项目决策 **D20**(CS 不参与分帧)同源。

## 四、代改一处(用户明确要求,§6.0 例外)

用户原话:「**我是说修改 `wire [27:0] adc_code = 28'h0A3D70A;` 让它换个频率输出**」

```diff
+// 频率字 = f_out × 2^28 / 25 MHz
+//   28'h0A3D70A = 1 MHz（原值）    28'h00029F1 = 1 kHz（= 官方 demo 原值，当前测试用）
+// ⚠️ 本行只影响 ~802 ms 之后（set_in 那一刻才锁存）。

+wire [27:0] adc_code = 28'h00029F1;
```

⇒ 只改这一行,上电后**前 800 ms 仍是 1 MHz**,之后才切。用户选择了「只改这一行、不动 init」。

**验证方式**:`xvlog` + `xelab` 双阶段 **rc=0**(`/tmp/qrs_chk/`,真实 `qrs.v` + `clk_wiz_0` 桩 + 7 探针 `ila_0` 桩)。

| 手册原文 | 推论 |
|---|---|

## 六、🔴 副产物:决策 D10 的理由被证伪

D10 原文:

> **AD9833 保持板载晶振,接受频差** | 备选:FPGA 提供 MCLK |理由:**晶振焊死无法改** | 放弃原因:**硬件限制,无选择余地**

用户实测澄清:**板上有外部 CLK 输入,由跳线帽选择** ⇒ 「焊死无法改」**是错的**。

旁证(`AD9833-DDS.pdf`,原理图页):

> 「AD9833主频25MHz,分辨率到0.1Hz / **可以选择外部接入1MHz晶振,分辨率可以达到0.004Hz**」

`1e6 / 2^28 = 0.0037 Hz ≈ 0.004 Hz` —— **数字恰好对上**,说明"外部时钟进 MCLK"是这块板
**设计上支持**的路径,不是我们想出来的。

**若改用 FPGA 供 MCLK 的连锁影响**

| | 现状(D10) | FPGA 供 MCLK |
|---|---|---|
| 激励/采样基准 | 两块独立晶振 | 同源 |
| 相干采样 `R/f_s = k/f_e` | 🔴 **原理上做不到** | 🟢 变成**一个可求解的整数约束** |
| 积分窗 T | 被 `sinc(Δf·T)` 卡在 **≤1 ms**(D11/D15) | 可放长 → SNR 更高 |
| 代价 | — | 多一根 FPGA 引脚;数字时钟耦合进模拟侧,**板载晶振相噪比 FPGA 干净** |

⚠️ **不得夸大成"同源后相干条件自动满足"** —— 它只是从"不可能"变成"可解",
具体 `M`/`R`/`f_s` 的整数解**还没算过**。

**模型建议:现在不改 D10,但今天必须把它标成"修订候选"。**
理由:① 影响要到 **P3** 才显现;② 现在动会打乱 P1 收口节奏;
③ 但**"焊死无法改"这条理由不能留在决策记录里** —— B09 要的正是这个。

## 纠错轨迹

1. **模型把一个推断写成了事实,并把它当成决策依据。**
   `LLM-017` 的会话里,模型据「模块 demo 只驱动 FSYNC/SCLK/SDATA 三根线」**推断**
   "MCLK 被板载 25 MHz 晶振**焊死**,接口上不引出",并标注这是"**D10 的一手依据**"。
   **本次被用户实测推翻** —— 板上明明有外部 CLK 输入且由跳线帽选择。
   ⚠️ **"demo 只驱动三根线" 只能说明 demo 不用 MCLK,推不出"板上没有 MCLK 路径"** ——
   与 `LLM-003`(把推断说成规定)、`LLM-012`(官方 XDC 里没有 ≠ 板上没有)**同型**。
   这是**同一类错误在本项目的第三次出现**。

2. **模型把真正的根因排在了第三位。**
   `LLM-017` 列了三个嫌疑,模型把「bitstream 是旧的」放在①、「MCLK 停振」放在③。
   本次文件级核验证明 ① 是**伪命题**(时间戳本来就晚),而**真正的根因是③**。
   ⇒ 教训:**先花两分钟做零成本的排除,再排序** ——
   ① 的排查成本只是一次 `ls -la`,模型却在上一轮把它排到了第一位。

3. 🔴 **模型没有主动把"能出正确的字"和"字被受理"分开。**
   模型在第二节写下「指令内容没问题」时,已知道手册那句
   「控制位在 MCLK 内部下降沿采样」,但**没有据此推出**"若 MCLK 停,4 帧再对也白搭"。
   用户用「**先确认不是指令问题**」把模型推到了正确的分界线上 ——
   **这个提问本身比模型的排查路径更准**。

4. 🔴 **模型把"位流是旧的"当成一个待处理风险报给了用户,而用户其实已经重跑过了。**
   模型核到的是 **09-20 22:28** 那版 `.bit`,据此写下"位流未重跑、板上跑的与仓库文件不对应",
   并把它列成 §一 的 🔴🔴 最高优先待办。会话后段用户自己重跑后,`.bit` 变成 **09-21 22:07**。
   ⚠️ **无法从时间戳判断模型下结论时文件是否已经更新** ⇒ **不写成"模型判断错了"**。
   ⇒ 教训(可写报告):**"位流是不是旧的""引脚加没加进去"这类结论有时效性** ——
   引用前必须**重新 `ls` 一次**,不能沿用几小时前(T 秒前)的读数。
   与「零成本排除优先」是同一枚硬币的两面:**排除动作便宜,但也正因为便宜,读数会过期**。

5. ✅ **模型本次主动做对的两件事**:
   ① 把「只改 `adc_code` 只影响 802 ms 之后、init 仍是 1 MHz」这个坑**在改动之前**讲清楚了;
   ② 用户问"是不是 1k"时,模型**分别**回答了 demo(1 kHz)与本项目(1 MHz)两个不同的对象,
   没有把两者混成一句。

## 沉淀

→ 可提炼为 skill:**「零成本排除优先」** —— 手上有静态产物(`.bit` / `.rpt` / 文件时间戳)能
  免费证伪的假设,永远排在需要动烙铁/示波器的假设之前。
  与 `LLM-012` 的「官方 XDC 里没有 ≠ 板上没有」合并为同一条 skill 的两个案例:
  **「不要用二手资料的缺失当作"不存在"的证据」**。

→ 可提炼为 skill:**「静态产物的读数有时效性」**(与上一条配对)—— 排除成本为零,所以容易
  沿用几小时前的读数当作当前事实。**同一类结论在写进报告或列成待办之前,必须重新 `ls` 一次。**
  同型案例:`LLM-013` 里"AD9833 侧一行代码都还没写"这句当晚就被查出不成立。

→ 可提炼为 skill:**「测试常量必须登记回收」** —— 为了做实验临时改的项目常量
  (本次的 `adc_code` 1 kHz),**改的那一刻就要在待办里写一条"改回去"**,
  否则它会安静地活到交付。判据:**凡是"临时值"都要能和"设计值"一眼区分出来**
  (本次靠 `qrs.v` 注释里的对照表 + 状态文档里的 🔴🔴 待办兜住)。

→ 可提炼为 skill:**「判据必须独立于被测物」的反面** ——
  本次官方 C 例程充当了**第三方参考实现**,它与我们的 RTL 无任何共享来源,
  因此"两者等价"是**有信息量**的结论(对比 `LLM-009` 那条"期望值抄自 RTL、恒真"的教训)。
