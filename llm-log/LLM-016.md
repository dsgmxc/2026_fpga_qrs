## 模型回答(交付物)

### 三处最小 diff

| 文件 | 改动 | 理由 |
|---|---|---|
| `qrs.v` 端口表 | `output wire data` → **`output wire adc_mosi`** | 原 `data` 是**从未被驱动的 1 bit 悬空输出**(`LLM-014` 已标为疑似占位符);端口数不变,顺手消掉这个悬空网络 |
| `qrs.v` 末尾 | 新增 `adc_code = 28'h0A3D70A` + `adc_9833` 例化 | 28 位而非 DAC 的 20 位;`.rst_n` 接 **`rst_n_sys`**(理由同 `dac_1220`:`locked` 未释放时 `spi_clk_50m` 不可用) |
| `io.xdc` | 新增 3 条引脚 + 3 条 `IOSTANDARD` | 见下「⚠️ 引脚是我挑的」 |

配套设计的取舍(都写在注释里):

- **`PWR_WAIT` 用默认值**(200 ms),不覆写 —— 与 `dac_1220` 并行启动,互不依赖。
  ⇒ 由此**暴露一个已知窗口**:AD9833 约 **200.8 ms** 就在加激励,而 DAC1220 要 ~800 ms 才可用,
  中间偏置未定义。这就是 **D21「上电顺序」**,**本次没有替用户决策**,只在 `qrs.v` 注释里点名。
- **`.set_in` 复用 `dac_1220` 那一次脉冲**(约 800 ms 处)而不是接 `1'b0`。
  理由:AD9833 自己 200.8 ms 就 init 完了,此刻在 `NORMAL_WAIT` 等着,收到后只是把同一个
  1 MHz 字再发一遍 —— **不改功能,但让 NORMAL 路径在上板上也真的走一次**(零新增逻辑,
  那个 wire 本来就在)。用户若不想要这个耦合,改 `1'b0` 即可。

## 纠错轨迹

### ① 「量具错」第 6 次 —— `integer` 未初始化,害我又先怀疑 DUT

第一次跑 smoke,输出是这样的:

```
  [adc 帧 x] 0x2100   @ 198.99 us
  [adc 帧 x] 0x570a   @ 408.53 us
  ...
== 采到 x 帧 ==
== 帧内容不符,请检查 ==
```

**"帧内容不符" 直接触发了我"是不是例化接错了"的念头。** 但输出里那 4 个**值全是对的**
(而且和模块级 tb 一字不差)—— 值的正确和判定的失败同时出现,这个矛盾才指向了别处:

**`integer nbit; integer nframe;` 没有初始值。Verilog 里 `integer` 默认是 `x`,不是 `0`。**
于是 `frm[nframe] = sh` 写到一个 `x` 下标上(等于没写),比较自然失败。
加 `= 0` 后一次通过。

> 与 `LLM-014` 的假 FAIL **完全同型**:失败点与"被测对象"无关,而我第一反应还是被测对象。
> `INDEX.md` 的编号口径下这是**本项目第 6 次量具错**
> (第 5 次见 `LLM-014`:期望值把 `0x0AAAAAA` 按 8 位算)。
> **判据再次应验:同一路径另一次却成功 / 失败点与改动无关时,先审量具。**
> 这次的"量具"甚至不是什么精巧的东西,就是**忘了给变量初值**。

### ② 引脚:模型主动标注"这是我挑的,不是查来的"

`LLM-012` 那次误判(把 J4 扩展口引脚判成"摄像头专用")的根源是
**一次不充分的搜索换来一个全称否定结论**。这次不重犯:**引脚是硬件事实,模型无从得知**,
所以在 `io.xdc` 里用注释显式写明"**不是从实际接线查来的 —— 上板前请对 J4 丝印核对一次**",
并给出备选方案。**宁可留一条待核实的注释,也不要让一个猜出来的球号看起来像是查证过的。**
