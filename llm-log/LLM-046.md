## C. 关键设计判断(报告 B06 素材)

### C.1 ★ 采样率**必须**和 PH_OFF 一起改

采样窗位置**随分频比 P 滑动**:窗 = `tick ∈ [2 − P/2, +1]`,中心 = `1.5 − P/4`。
只改 `0x88[7:0]`(DIV)不改 `[15:8]`(PH_OFF),采样点会滑出被驱动的窗口。
**失败方式是最难查的那种**:不报错、不越界、寄存器回读全对,只是"换了速率就没波形了"。

⇒ 设计上**不提供**单独改 DIV 的路径:`MeasureConfig_SetSampleDiv()` 内部强制
`s_phase = cv_adc_phase_center(s_div)` 与 DIV 同一次写下去。

### C.2 两个"范围"必须分清(本场自己写混过,见 §D.2)

| 范围 | tick 区间 | P=13 | 越界后果 |
|---|---|---|---|
| **寄存器合法值**(`adc_capture.v:238`) | `[−P/2, P−1−P/2]` | `[−6, +6]` | 永不命中 ⇒ `done` 不置位 —— **失败方向安全** |
| **数据稳定窗**(守卫用这个) | `[2 − P/2, +1]` | `[−4, +1]` | 在合法范围内但数据未稳定 ⇒ **采到垃圾,不报错** |

守卫**必须用窄的那个**,因为只有它能挡住"回读全对但数据是错的"。

**旁证**(不是本轮新测,是 LLM-045 的既有结论):状态文档记「复位默认 `PH_OFF = 0` 只在 P ≥ 4 时
勉强落在 A 窗口内且**贴边**」—— `0` 恰是 `[−4, +1]` 的**最右端**,而按宽窗 `[−6,+6]` 它接近中心,"贴边"不成立。

### C.3 回读核对(照抄偏压那条路的做法)

`0x80` / `0x88` 写下去之后**立即回读**,不一致只打一次提示并给出三步排查。
理由与 `bias_write_code` 相同:AXI 通路出问题时写**不报错**、寄存器里还是旧值 ——
回读是"界面点了没反应"与"硬件没接通"之间最快的分界。

### C.4 界面落点:只动「系统复位」页

该页语义就是"初始化",且面板下半截本来空着。**其余四页逐字不变** ⇒ diff 可审,
保住 `ui_demo.c` 作为「前序逐字对照」的**可辩护性资产**。

### C.5 状态行为什么**不含偏压/回路**

偏压已经由**常驻表头**每页显示(`g_header_bias_label` / `UI_UpdateCommonStatus()`)。
再放一遍会让 `measure_config.c` 需要反向去读 `pynq_protocol.c` 的 `static s_bias_volts`
—— 两个模块互相咬。接口上直接把这半句写进 `measure_config.h` 的注释,防止后人"顺手补上"。

### C.6 ⛔ `0x84`(CV_CTRL)不在复位范围内

`[0]` 是 `dac_rst_n`,**放行权由 Python 独占**(`drivers/board.py::release_dac()`)。
清掉它 = 把 DAC 重新按回复位 = 输出跳回 −10 V,而所有回读看起来都正常。
⇒ `RequestReset()` 里写成注释钉死,并在验证清单里单列一条查这位。
`MeasureConfig_Init()` **只读不写** `0x84`,发现没放行时把它喊出来,不代 Python 做决定。

### C.7 ⛔ 不把 `0x88[17] OEB` / `[18] PDN` 暴露到界面

LLM-045 实测 `OEB=1` 时 ADC 输出被冻结(128 点全 4087),而**极性约定尚未从 RTL 追到引脚**
(板子丝印 `OEB` vs RTL 信号 `OEB_N`)。放到按钮上会变成一个"一点就坏"的开关。

### C.8 档位表(20 MSPS 取不到,要在界面上说清)

| 按钮 | DIV | f_s | PH_OFF(自动) |
|---|---|---|---|
| `1MSPS` | 130 | 1.0 | −31 |
| `2MSPS` | 65 | 2.0 | −15 |
| `5MSPS` | 26 | 5.0 | −5 |
| **`10MSPS`** ★默认 | **13** | **10.0** | **−2** |
| `13MSPS` | 10 | 13.0 | −1 |

- **20 MSPS 在 130 MHz 基频下取不到**(130/20 = 6.5 非整数)⇒ 档位最高 13 MSPS。
  界面提示文字里直接写明是按 130 MHz 基准算的,不然看起来像漏了一档。
- ⛔ **不给 DIV=5(26 MSPS)** —— 决策 D13 定 `f_s ≤ 20 MSPS`。
- 默认 10 MSPS:与 RTL `0x88` 复位值(DIV=13)一致,也正是 LLM-045 采出教科书正弦的那组。

## D. ★ 纠错轨迹(本场 3 例)

### D.1 `snprintf` 隐式声明 —— 我把"应该是"当成了"查过"

**我的动作**:为拼状态提示,在三处用了 `snprintf`。
**我的断言**:「`ui_demo.c` 里 `snprintf` 出现 22 次,所以 `<stdio.h>` 必然经传递包含进来了。」

**编译器打脸**:`make -j4` 只在**我新写的那三行**报 `warning: implicit declaration of function 'snprintf'`。

**查证**:`grep -o '[a-z_]*snprintf' ui/ui_demo.c | sort | uniq -c` → **`19 lv_snprintf` / `3 snprintf`**
—— 那 3 个 `snprintf` 就是我自己刚写进去的。**22 次里 19 次是 `lv_snprintf`(LVGL 自己的),
`ui_demo.c` 根本没有 `<stdio.h>`。**

**为什么这条值得记**:我先数了个总数,就把"总数多"当成"头文件在",**没区分同名不同族的两个函数**。
这是典型的**用一个聚合数字代替逐项核对**。

**中途还错了一次**:改法一度是加个变参助手 `UI_InitAnnounceFmt(format, ...)`,
写完才发现 `va_list` 要 `<stdarg.h>` —— **同一个坑的第二次**,还是要动前序的 include 块。

**最终改法(不碰前序 include 块)**:
```c
/* 保留纯文本路径 */
static void UI_InitAnnounce(const char *text);      /* 内部 lv_label_set_text */

/* 带格式的三处直接在调用点内联 —— 照 UI_UpdateCommonStatus() 的既有写法 */
if (g_status_label != NULL) {
    lv_label_set_text_fmt(g_status_label, "状态:激励已设为 %s", g_init_dds_texts[index]);
}
```
顺带把三个事件回调里已无用的 `char text[48/56]` 局部变量删掉。

### D.2 ★★ 窗口公式写反 —— **上一轮刚得出的结论,本场自己又用错了**

**我的动作**:写 `measure_config.c::adc_window()` 时,按 `adc_capture.v:238` 的注释
`有效范围 [0−half, P−1−half] = [−P/2, P−1−P/2]` 写了 `*lo = -half; *hi = p-1-half;`(P=13 → `[−6,+6]`)。

**矛盾暴露**:同一个文件**上方几行的注释**却写着「反推核对(P=13):窗应为 −4…+1」
—— **代码与自己的注释打架**,宽度 13 vs 6。

**根因**:`adc_capture.v` 里那两个数说的是**两件事**,我没分清就抄了先看到的那个:
- `[−P/2, P−1−P/2]` 是**计数器够得着的刻度**(`tick = cnt − half`,`cnt ∈ [0,P−1]`)⇒ 13 个
- `[2 − P/2, +1]` 是**数据真的稳定的那几拍** ⇒ 6 个

而 LLM-045(上一场)已经把后者**实测**出来了(双端口、窗宽 `P/2`、中心 `1.5 − P/4`),
状态文档里也白纸黑字写着。**我当时读过、写过,仍然抄错了。**

**危害**:守卫放行到 `[−6,+6]`,用户可以 nudge 到 `[−6,−5]` 或 `[+2,+6]` ——
**落在合法范围内但数据未稳定**,采到垃圾且不报错。**这正是守卫存在的唯一理由。**

**修正**:守卫改用窄窗,直接用窗定义本身,不绕中心:
```c
static void adc_window(uint32_t div, int32_t *lo, int32_t *hi)
{
    uint32_t p    = clamp_div(div);
    int32_t  half = (int32_t)(p >> 1);   /* P/2 = 下降沿刻度,也正好是窗宽 */

    *lo = 2 - half;
    *hi = 1;
}
```
**修完自检**(穷举,不只查五档):`DIV ∈ [2,255]` 全部满足 `窗含自身中心` ✓。

| DIV | f_s | 窗 | 中心 | 窗宽 |
|---|---|---|---|---|
| 130 | 1.00 MSPS | `[−63, +1]` | −31 | 65 |
| 65 | 2.00 MSPS | `[−30, +1]` | −15 | 32 |
| 26 | 5.00 MSPS | `[−11, +1]` | −5 | 13 |
| 13 | 10.00 MSPS | `[−4, +1]` | −2 | 6 |
| 10 | 13.00 MSPS | `[−3, +1]` | −1 | 5 |

**过程中的第三个错**:第一次改写成
`*lo = center - span + ((p % 4u) ? 0 : 0);` —— 三元两边都是 `0`,**加了等于没加**。
纯属用复杂式子掩盖没想清楚。改成上面两行直给。

**教训**:窗口公式在本项目里**有两个**,名字都叫"有效范围"。抄之前先问"这是谁能取的值,
还是数据好的值"。**引入第二个公式时必须把两者的区别写进注释**,否则下一个人(包括我自己)还会犯。

### D.3 `dds_set_hz()` 变成死函数

**我的动作**:把 `pynq_protocol.c` 的 `dds_set_hz()` 改成委托 `MeasureConfig_SetDdsHz()`,
想保留原函数名做薄包装,兼容既有调用点。

**编译器报**:`warning: 'dds_set_hz' defined but not used` —— 两个调用点都已改成
`MeasureConfig_Init()` / `MeasureConfig_RestoreDefaults()`,**这个包装一个调用点都没有了**。

**处置**:删除,原地留一段注释说明 **`0x80`/`0x88` 现在只由 `measure_config.c` 写**。
理由写清:**两个写入方 = "谁最后写谁赢"的经典 bug 源**。以后要设频率请调 `MeasureConfig_SetDdsHz()`。
