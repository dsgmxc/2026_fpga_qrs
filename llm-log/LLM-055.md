## 模型回答

1. **先算,再改。** 唯一要求是 `L·f_e/f_s ∈ ℤ`;把 `f_e/f_s` 约到最简 `p/q`,
   取 `L = ⌊n/q⌋·q`。固定 65 MSPS 后四档的窗长是 **6500 / 7800 / 8190 / 8190**,
   最长 6500 > 旧缓冲 4096 ⇒ **"组合不合理"的算术根源在这里**。
2. **缓冲 4096 → 8192**(`adc_capture.v` 的 `BUF_DEPTH`/`BUF_AW`)+ 配套改掩码、上限、抽稀。
3. **解调参考表长度改为只跟 `L` 走**,与频率比脱钩(旧实现按 `f_s/f_e` 整数倍建表)。
4. **写规格文档** `docs/acquisition_demod.md`(该段唯一来源)+ 改写 `source_design_checklist.md` §3/§8、
   `CLAUDE.md` §八里所有陈旧口径(`clk_adc = 25 MHz`、`f_s = 20 MSPS`、`激励 1 MHz 固定`)。
5. **上板闭环**:源码上板 → 板上 `make` → 整板重启 → 探针实测 → 用户手点三档。

## 纠错轨迹

### 1. ★ 最重要的一次:**模型的"算术成立"掩盖了"物理不成立"**

用户第 1 条指令里给了 **10 MHz** 这一档,模型**照单全收**,
为它算出了完全合法的窗参数(`q = 13`、`L = 8190`、`m = 1260`),
并且**在文档里把它和另外三档并列写成一张"四档表"**。

**问题**:AD9833 的 MCLK 是**板载 25 MHz 晶振、焊死**(决策 D10)这条事实
**本次早就在模型的上下文里** —— 25 MHz MCLK 出 10 MHz ⇒ **只有 2.5 个 DAC 采样/周期**,
且 15 MHz 镜像离主频仅 5 MHz,低通滤不掉。**这是 DAC 采样定理层面的不可能,不是配置问题。**

- **模型错在哪**:把"**数字域能不能算**"当成了"**这一档能不能用**"。
  `L`、`m`、参考表全都算得对,于是这一档在表里看起来**和别的档一样正常**。
- **怎么发现的**:不是模型发现的 —— 是**用户上板选到 10 MHz 档,发现输出不了**,
  随即切回 1 MHz(日志:`[mc] 激励 → 10.000 MHz(0x80 = 0x6666666)` 紧跟
  `[mc] 激励 → 1.000 MHz(0x80 = 0xA3D70A)`,**中间没有任何测量**)。
- **改法**:删档,并在 `docs/acquisition_demod.md` §4.1 单独留一节写清"算术成立、物理不成立",
  附上"要 10 MHz 只能换 MCLK ≥ 100 MHz 的 DDS"这条出路。
  `pynq_protocol.c` 的抽稀表也同步删行,并注明"**stride 公式一个字都不用改** —— 它是由 `L`/`m` 现算的"。
- **遗留**:删档依据是**硬件算术 + 用户口头判定**,不是本次的仪表读数 ⇒ 记录里如实标注,
  没有把它写成"实测 10 MHz 无输出"。**不要为了把话说满而伪造一条实测。**

📌 **可复用教训**:给"频率/采样率"这类**跨数字域与模拟域**的参数建表时,
**必须先问一句"这套器件在物理上到不到得了这一格"**,再算数字。
**数字算得对,恰恰是最危险的状态** —— 它让后面所有审查看起来都没问题。

### 2. 三道"算得对、闸在中间"的静默关卡(同一个形状出现三次)

把缓冲从 4096 改到 8192,横跨 RTL / C / 界面三层,**每一层都有一道关卡,
失效形状完全相同:数字算得出来,被静默截断或拒绝,不产生任何错误。**

| # | 位置 | 不改的后果 |
|---|---|---|
| 1 | `cv_axi_lite_slave.v` 写掩码 `32'h0000_0FFF` | 写索引 ≥ 4096 被截成 `idx − 4096` ⇒ **读到另一个点的数据,不报错** |
| 2 | `adc_sample.c` `ADC_DEMOD_MAX_L = 256u` | `build_table()` **直接失败** ⇒ 报「窗长 6500 点,超出参考表上限 256」 |
| 3 | `ui_demo.c` `UI_WAVE_MAX_SAMPLES = 480` | 8192 点喂进波形图**静默截断到前 480 点** ⇒ 屏上"波形是平的" |

⚠️ **第 3 道不是"把上限调大"就完事** —— 波形图只有 480 像素宽,8192 点本来就画不下。
正解是 `pynq_protocol.c::adc_feed_point_waveform()` 改成两步:
**① 画 3 个周期(上限整窗)② 按 `ceil(显示点数/480)` 抽稀**。
**上板日志证明它是数据驱动的**:三档的"显示前 N 点"分别是 **6500 / 1950 / 195** ——
各不相同,写死任何一个常量都会让另外两行对不上。

📌 **教训**:"改一个容量"这类改动,**必须把该容量沿路经过的每一个`上限 / 掩码 / 截断`都找出来**。
它们的共同特征是**不报错**,所以只能靠**枚举**发现,不能靠"跑一遍看看报什么错"。

### 3. 陈旧常量在语料里的两次现形(都靠 grep,不是靠跑)

- `src/python/cv_regs.py::DDS_HZ_CHOICES` 里还留着**最初那套五档表**
  `(100k, 500k, 1M, 2M, 5M)` —— 与界面上的三档**完全不是一回事**。
  它不报错,只在有人从 Python 侧下激励时**悄悄下出一个不存在的档**。
- `tools/adc_probe.py` 的**位流身份判据**原写死 `== 0x0000000D`(旧位流的 `DIV=13`)。
  新位流的复位值是 `0x00000002` ⇒ 不改的话会**印出"疑似旧位流"的假结论**,
  而这条判据以前是拿来判"该不该相信后面的采集结果"的。

两条都是**改了实现、没改引用它的文档/工具**,属于同一类漂移。
📌 处置:改完实现后**主动 grep 旧数值**,而不是等它下次咬人。

### 4. 一次"我差点把自己的工具用错"的复核

`adc_probe.py` 把位流身份判据放在 **`init`**(刚 `Overlay()` 完、还没人写过 `0x88`)
而不是 **`attach`**。本次 `attach` 时读到的是 `0x88 = 0x0000FF02`
(`PH_OFF` 已被 `c_ui` 写成 `0xFF`)—— 若把判据放进 `attach`,
就会拿一个**被改过的值**去判"位流新旧",得到"版本不明"的假警报。
⇒ 复核后确认判据在 `init` 里,**不改**。记下来是因为这条约束很容易被后来人"顺手统一"掉。

### 5. 环境操作上的四次小翻车(都不影响结论,但都浪费了一轮)

| 现象 | 真实原因 |
|---|---|
| `sftp_put` 报 `FileNotFoundError`(8 个 C 文件) | 当前目录是工作区根,不是 `src/c_ui`,相对路径找不到 |
| 第一次后台重建**没有产出** `/tmp/build.log` | `setsid nohup bash -c "make …"` 根本没跑起来。单测 `sleep 30` 验证后台化本身可用后,**放弃后台化,改前台 `make -j2`**(设 10 min 超时)一次成功 |
| `systemctl cat qrs-ui` **挂住不返回** | pager 在 pty 里等按键。改用 `cat /etc/systemd/system/qrs-ui.service` |
| 两个文件被报 `rc=1`(虚假失败) | `gcc … \| grep -v` 取到的是 **`grep` 的**退出码(无匹配 = 1)。改成把过滤结果收进变量再显式打印,**三个文件全干净** |

📌 后两条同源:**退出码经过管道就已经不是被检查对象的了**。
