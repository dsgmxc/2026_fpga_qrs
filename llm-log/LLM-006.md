# LLM-006: 用数据手册解除 DAC1220 阻塞项 —— 并发现厂商例程本身有两处缺陷

- **日期**: 2026-09-16
- **模型**: Claude(本会话)
- **任务**: 用户拿到 DAC1220 资料(数据手册 + 厂商 STM32 例程),要我阅读并给出 PL 侧实现依据。
  此前 `docs/project_state.md` 把「DAC1220 手册待核」列为 🔴 阻塞项,卡住 `dac_1220.v` 的命令表内容。

## 提示词

```
我打算把dac控制写完直接上板测试dac控制效果，我刚刚复制了一份dac资料在桌面去阅读一下
```

## 模型回答

读了 `dac1220.pdf`(TI SBAS082G)与厂商两份 STM32 例程,产出 `docs/dac1220_interface.md`,要点:

1. **帧格式**:不是 24 位帧,而是「8 位命令字节 + 1/2/3 个数据字节」。命令字节 = `R/W | MB | 0 | ADR`
   (Table 6/7)。**`spi_master` 的 `DATA_WIDTH` 取 8 确认无误。**
2. **SPI 波形**:SCLK 空闲低、从机**下降沿**采样 → CPOL=0/CPHA=1(Mode 2)。
3. **`f_SCLK ≤ 246 kHz`**(由 `t3 ≥ 5×tXIN` 推出)→ **`SPI_HALF_T` 至少 204**(原为 10)。
4. **CS 全程拉低**,不参与分帧(`t14` 帧间隔 ≥ 41×tXIN = 16.68 µs)。
5. **Reset pattern** 四段窗口换算到 100 MHz 拍数;**最大表项 90000 拍 → 表宽必须 ≥ 17 位**。
6. 给出 8 步初始化序列,并**修正厂商例程两处**:CMR bit13 应写 1、进校准前应先配好模式。

## 纠错轨迹

> 本次**没有出现"模型结论被实测证伪"**的案例 —— 因为还没有实测。
> 如实记录三条**对上一轮(LLM-005)结论的修正**,不夸大、也不改写为"已验证"。

1. **上一轮的表项溢估算方式不可复现。** LLM-005 写的是 `2100 × 50 = 105000`,
   但 `50` 这个「每 tXIN 多少拍」的来源从未说明,按 `clk_axi=100 MHz` 实算应为
   `2100 × 40.69 ≈ 85449`,而按本项目取的中值窗口是 `90000`。
   **结论方向没错(表宽不够),但数字对不上。** 本次改为写明假设后实算。
2. **上一轮审查项 ④ 只指出了问题,没给改法。** "两套并行实现"是对的,
   但当时没说该怎么办。本次给出可落地改法:**改成一级 mux,输出脚只有一个驱动源**
   (`sclk = sel_reset ? reset_sclk : spi_sclk`)—— reset pattern 必须手工拨电平,
   这是**结构需求,不是设计疏漏**,原审查把话说重了。
3. **本次主动拒绝了一条断言。** 厂商例程把 `-10 V ~ +10 V` 映射到码值,
   很容易顺手写成"这块 DAC 输出 ±10 V"。但手册 Table 8/9 明写芯片本体是**单极性 `0 ~ 2×VREF`**,
   而**资料包里没有模块原理图** —— ±10 V 是模块模拟级的事。
   → 已列入 `docs/dac1220_interface.md` §八「未核实项」,**不写进结论**。

**本次最有价值的一条:厂商例程不是规范。**
两份例程看起来权威(能跑、有注释、还引了手册页码),但核对手册后发现两处不达标:
① 字节间距 `delay_us(10)` < `t14` 下限 16.68 µs;
② 读函数在 SCLK **上升沿**即刻采样,而手册说从机正是在上升沿更新输出(`t8` ≤ 50 ns)。
→ 教训:**例程是"能跑"的证据,不是"合规"的证据;时序类判断必须回到手册表格。**

## 补记(同日,用户贴出实例化代码后)

**模型犯了一个可记录的错:整张常量表用错了时钟频率。**

- 模型把全部「拍数」按 **`clk_axi = 100 MHz`** 换算,依据是 `CLAUDE.md` §八 里那句
  「`clk_axi` 100 MHz ← PS FCLK_CLK0」。
- 但用户贴出的实例化代码显示,`spi_master` 实际挂在 **`clk_50m`** 上
  (且注释写明「50mhz,100khz spi速率」)。
- **后果**:整套延迟常量差一倍。按 100 MHz 说要 `SPI_HALF_T ≥ 204`、
  字节间隔 2048、上电等待 20 000 000;按 50 MHz 实际只需 `≥ 102`、间隔 1024、等待 10 000 000。
- **用户侧的实际影响:无。** 用户自己填的 `SPI_HALF_T = 256` 在 50 MHz 下
  是 5.12 µs 半周期(97.66 kHz),**余量 +152%,完全安全** —— 用户的判断是对的。

**错因**:把设计文档里「最终架构」的参数,当成了「当前在跑的实现」的参数。
两者在自底向上开发中**必然不同**(当前是 PL-only 测试顶层,PS 的 `FCLK_CLK0` 还没进来)。

**改进**:凡涉及「拍数 / 周期数 / 分频比」的换算,先确认**被测模块实际挂的时钟**,
不能从架构文档推。这类常量在自底向上阶段会随顶层变化,文档里应写成
「时间 + 双时钟列」(已在 `docs/dac1220_interface.md` §5.1 改为此形式)。
