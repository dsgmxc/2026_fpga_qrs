## 模型回答(要点)

### A. 手册事实层(逐条有出处,`dac1220.pdf` SBAS082G)

| 结论 | 出处 |
|---|---|
| 命令 = **命令字节 + 1/2/3 个数据字节**,个数由命令字节的 `MB[1:0]` 位决定 | Table 6 / Table 7 |
| `t9` = **13×tXIN** —— 命令字节最后一个 SCLK 下降沿 → 首个数据字节 SCLK 上升沿 | Table 4 |
| `t14` = **41×tXIN** —— 上条命令最后数据字节 → 下条命令首个 SCLK,**描述末尾明写 `(CS tied low)`** | Table 4 |
| **CS 可以不用,接低即可** | p11:"**If CS is not used, it should be tied low.**" |
| CS 高时 SCLK 被忽略;**复位图案只在 CS 低时才可能触发** | p11 |
| 手册把时序分成两套图:**Figure 9 = CS 接低**,**Figure 10 = 用 CS 分帧** | p11 / Table 4 |
| 接口是**面向字节**的 | p11:"The serial interface is byte-oriented." |
| **CMR 在「写命令最后一个字节的最后一位 SCLK 下降沿」生效** | Table 13 原文 |
| 自校准:`MD1='0', MD0='1'`;2.5 MHz 下 **300–500 ms,且实际时间不确定**;纯写时 **"simply wait at least 500ms"** | p13 |
| 校准结束**芯片自动回 Normal 模式**,无需再写 CMR | p13 |
| CMR **bit13 必须写 1**(第一版芯片性能才最优);**bit9 = `CRST`,写 1 会复位校准寄存器** | p14 / Table 13 |
| I/O 恢复超时 ≈ **100 ms @2.5 MHz**,超时则**命令被取消,写命令不动寄存器** | p14 |

## 纠错轨迹

> ⚠️ 本次**仍没有"模型结论被实测证伪"**的案例 —— 因为依旧没有实测。
> 以下记录的是真实发生的**推理分歧、模型自查、以及用户对模型的纠正**。

### 1. 「一个信号不能承担两个语义」—— 本次最有价值的一条

用户主动提出的方案是:

> 「sclk 部分因为不能同时被两个块驱动我打算分两个 sclk 并且通过 **`init_done`** 通知上层选用哪个 sclk 作为输出」

用户**对一个引脚一个驱动源的直觉是对的**,但选择信号错了。模型核对后发现:

- `init_done` 在用户代码里被放在 `DELAY` 的校准分支入口 —— **即"复位图案刚结束"那一拍**,
  而不是"初始化全部完成"
- 它**碰巧**落在正确的切换时刻上,所以方案"看起来能work"
- 但语义上,上层看到 `init_done=1` 会以为 DAC 可用 → **立刻去写 DIR** →
  而校准还要跑 600 ms → **命令在校准期间发出 → 校准被破坏且读不回来**

**结论:拆成两个信号。** `man_mode`(内部选 SCLK,复位图案结束清 0)与
`init_done`(对外握手,600 ms 等完之后置 1)。

→ **教训:两个职责的时间点不同时,不能共用一个信号 —— 哪怕当前"刚好"对得上。**

### 2. 用户追问暴露了模型讲解没落地

模型讲完「CS 恒低」之后,用户问:

> 「你是说在发数据和指令的时候 cs 恒为 0 吗,难道他不是 spi 通信吗」

这是**合理且重要**的疑问 —— 说明模型前面在讲「CS 可以不要」时,
**没有先把「CS 在 SPI 里是选从机、不是分帧」这一层拆开**,导致结论听起来像"这不是 SPI"。

→ 模型补了对照:单从机总线 + CS 接低是标准接法;DAC1220 靠 **`MB` 位数字节 + SCLK 静默**
来界定命令;手册自己就分 Figure 9 / Figure 10 两条路。
→ **教训:讲器件特例之前,先复位对方对通用协议的默认假设。**

### 3. 代码审查发现 7 条阻塞级(全部由用户在自己代码里引入)

| # | 问题 | 后果 |
|---|---|---|
| ① | `spi_sclk` 端口从未被赋值 + `.sclk(sclk)` 接隐式网 | **校准阶段根本没有 SCLK**,5 个字节一个都发不出去 |
| ② | `output reg` 直接接子模块输出(`spi_cs` / `dac_mosi`) | IEEE 1364:变量不能接实例输出 → 非法 |
| ③ | `start` 拉高后从不清零 | `spi_master` 是**上升沿触发** → 只发得出一个字节 |
| ④ | 握手优先级 `if(!busy)` 写在 `if(done)` 之前 | `spi_master` 的 `busy<=0` 与 `done<=1` **同一拍生效** → `done` 分支永远进不去 |
| ⑤ | `cal_cnt` 先自增再取字节 | 配对所有往后错一位 → **命令字节 `0x24` 被跳过** |
| ⑥ | `CAL` 门限写 `< 5-1`,无 else | **`0xA1`(真正触发自校准的字节)发不出去**,且到 4 即死锁 |
| ⑦ | `init_done` 全模块只有两处 `<= 0`,**无一处置 1** | 唯一握手输出恒 0(后经用户修改,见 §1) |

其中 **③ + ④ 合起来的症状极具迷惑性**:波形上只看得到一个字节,
看起来像"命令错",实际是**握手协议写反**。

### 4. 模型代改 9 处(用户授权,`Edit` 最小 diff)

| 处 | 改动 | 性质 |
|---|---|---|
| 1 | `output reg dac_sclk` → `output wire` | 修 ② 的同族问题 |
| 2 | 新增 `man_sclk` / `man_mode` + `assign dac_sclk = man_mode ? man_sclk : spi_sclk;` | 一级 mux |
| 3 | `localparam` 加 `CAL_WAIT`;新增 `PWR_WAIT = 10000000` | 终止态 + 上电等待 |
| 4 | `reg [15:0] init_sclk [0:5]` → `reg init_sclk [0:5]` | 6×15 位白占 |
| 5 | 复位分支加 `man_sclk <= 0; man_mode <= 1;` | — |
| 6 | `IDLE` 由"无条件跳 INIT"改为**先数 `PWR_WAIT`** | 补 200 ms 上电等待 |
| 7 | `INIT` 加 `if(init_cnt < 6)` 保护 | **越界防护,见下** |
| 8 | `CAL` 门限 `<5` → `<6`,并补 `else → CAL_WAIT` | 修 ⑥ |
| 9 | 新增 `CAL_WAIT` 状态:数 `cal_delay[6]` 后置 `init_done <= 1` | 修 ⑦ |

**「改 A 时预先想到 B」—— 本次一个值得记的正面样本**

修 ⑥ 需要把 `DELAY` 的复位门限从 `< 6-1` 放宽到 `< 6`,这会让 `init_cnt` 走到 **6**。
而 `init_sclk` 是 `[0:5]` —— **直接改就会读到 `init_sclk[6]`,越界**。
模型在改 `DELAY` **之前**先在 `INIT` 里加了 `if(init_cnt < 6)` 保护。

→ 与 LLM-004 记录的「**改 A 引入 B**」恰成对照:**同一类风险,这次在落笔前被拦住了。**
→ 可提炼为审查动作:**改任何循环上界前,先枚举它下游所有用该计数器做索引的地方。**

### 5. 模型一处**未经证实的推断**(主动标注)

模型在解释字节间隔时称:

> 「背靠背发字节时,`t9` 的"下降沿→上升沿"只有**半个 SCLK 周期 = `SPI_HALF_T` = 256 拍 = 5.12 µs**,
> 而 `t9` 要 5.29 µs —— **差 3.3%,不满足**」

**这条是纯推演,没有波形依据。** 它依赖两个未验证的前提:
① `t9` 量的是"下降沿→上升沿"因而等于半个周期;② CPHA=1 下命令字节的最后一个沿是下降沿。
`pdftotext` 抽不出 Figure 9 的波形,模型**没有在时序图上确认过**。

→ 已在本记录中标注为**推断**,引用前必须用波形实测(方法:`docs/dac1220_interface.md`
§3.1 已写明的"在波形上量一次下降沿→上升沿的实际空闲时间")。

**实际影响:无。** 本项目字节之间由 FSM 显式插 1024 拍,不依赖这条推断。

### 6. 用户对模型建议的取舍(「我不同意 / 我改了」类证据)

| 模型建议 | 用户处理 |

| `dac_cs` 改成 `assign dac_cs = 1'b0;` | ⏸ **暂未采纳** —— 保留 `output reg` + 状态内赋值(语义等价,只是表达方式) |

## 沉淀

<!-- 本次经验能变成 skill/ 下的哪几项 -->
→ 候选 `skill/one-signal-one-meaning/` —— **一个信号不能承担两个语义**。
  检查动作:列出每个对外信号的"置位时刻"与"含义",**两次对不上就是设计缺陷**,
  哪怕当前波形"刚好"能跑。本次 `init_done` 就是典型。
→ 候选 `skill/spi-master-slave-handshake-checklist/` —— 审查主从 SPI 胶合逻辑的固定清单:
  ① `start` 是电平还是脉冲?从机是边沿触发还是电平触发?**发完必须清零**
  ② `done` 与 `busy` 是否同一拍翻转?**先判 done,再判 busy**
  ③ 循环上界 `/` 索引偏移 `/` 数组长度 三者是否自洽(本次 ⑤⑥ 都是这个)
  ④ 选择信号用**寄存器**而非"判状态名"(状态会被复用,判状态名会静默走错分支)
→ 候选 `skill/loop-bound-change-safety/` —— 改循环上界前的连锁检查:
  **枚举所有用该计数器做索引的地方,确认越界保护存在**。
→ 候选 `skill/cs-is-optional-in-spi/` —— 「CS 恒低还算不算 SPI」这类疑问的标准答复:
  先拆「CS = 选从机 ≠ 分帧」,再讲单从机总线 + 手册的两条对照路径(Figure 9 / 10)。
