## 模型回答

**一句话**:把 `ARCACHE` / `ARPROT` 拆成两次单变量实验,做成 2×2;
四个格子**全部实测**,得到 —— **`ARPROT[1]`(NS 非安全位)置 1 必然导致 DECERR,
`ARCACHE` 完全无关**。位流修正后显示通路端到端打通。

六步,全部有实测支撑:

1. **重启后第一枪仍是 DECERR** → 否掉"重启能恢复"。boot `1`,`uptime` 43.43 s,冷启动首测即 DECERR。
2. **按 `PL_KEY0` 让厂商例程跑一次 HP0 事务** → 用**独立观测者**确认写成功
   (PS 侧从 `0x10000000` 读回自增数 `1…16`,按键前是 DTB `0xEDFE0DD0`)。
   紧接着加载我方位流 ⇒ **仍 DECERR**。⇒ "厂商成功事务能清故障"也不成立。
3. **交替加载 A/B/C** → 同 boot 内 `a963(000)`→有数据、`298c(010)`→全零、`a963(000)`→有数据。
   ⇒ **结果跟位流内容走,不跟板子状态走。**
4. **EXP-A**(只动 `arprot`):`ARCACHE=0011` / `ARPROT=000` ⇒ **有数据**
5. **EXP-B**(只动 `arcache`):`ARCACHE=0010` / `ARPROT=010` ⇒ **DECERR**
6. **终值** `ARCACHE=0010` / `ARPROT=000` ⇒ `rresp=OKAY`、`axi_or_nz=1`,
   **用户目视确认**图案三元素全对。

## 结果

☑ ✅ 直接可用   ☐ ⚠️ 部分可用   ☐ ❌ 不可用

**根因坐实、位流修正、显示通路打通(M13 证据到手)。**
遗留:`ARPROT[1]` 的**机理**仍无权威出处(本机无 UG585/TRM),取值属
「与已验证参照物对齐」。

## 验证方式

| 项 | 具体方式 |
|---|---|
| 常量是否真的进了位流 | **每一次**综合后 `open_checkpoint` + `write_verilog -mode timesim`,从网表里逐位读 `.S_AXI_HP0_ARPROT({…})` / `.S_AXI_HP0_ARCACHE({…})`,**先核网表再上板** |
| 单变量分离 | 4 份独立构建(A/B/C 交替 + EXP-A + EXP-B + 终值),`reset_run synth_1` + `launch_runs impl_1 -to_step write_bitstream` |
| 数据是否真的进来 | 板上 `0x74 DBG_BEATS` + `rresp_lat` / `axi_or_nz` / `px_or_nz`,连采 300 次取最大值 |
| 厂商 HP0 事务是否成功 | **不采信 LED**。厂商 RTL 写自增数到 `0x10000000`,PS 侧 `/dev/mem` 只读回读,按前是 DTB、按后是 `1…16` |
| 显示是否正确 | **两个独立观测者**:硬件寄存器(`axi_or_nz`/`px_or_nz`/`rresp`)+ **用户目视**三元素图案(底色/横带/角块) |
| 板上位流真值 | `md5sum /home/xilinx/qrs.bit` 与本地归档逐一对齐 |

> ⚠️ **仍无独立观测者抓 AXI 波形。** 工程里那个 `ila_0` 只探 SPI 引脚且未例化。
> 本轮靠"交替加载 + 网表核对 + 双观测者"绕开了这一限制,**但机理层面仍是黑箱**。

## 纠错轨迹

### ① 🔴🔴 本轮推翻的是**我上一轮写的"推翻"** —— 而且错因和上一轮刚总结的教训是同一条

上一轮(`falsified.md`)的结论:「`ARPROT`/`ARCACHE` 假设**已被实测推翻**,
故障是 PS 侧粘滞二态,重启不恢复」。

支撑它的**全部依据,是 A/B 表里的第 2 行 `cdfbe0f5`**(`010`/`0011` → 却读到 OKAY)。
本轮查证:**这一行的取值是从源码读的,从来没核过网表**;核过网表的只有
`a9636e0d` 和 `298c8f1f`。`cdfbe0f5` 已被后续构建覆盖,**无法复查**。

**而上一轮我在同一篇文档的 §四 里刚写下**:

> 「**位流 md5 不是"改动是否生效"的合格判据**」

**同一次会话,转身又拿"源码"当"位流里是什么"的合格判据。**
同一个坑的两个方向:一次是"以为改了没进去",一次是"以为没改其实进去了"。

⇒ **已立规矩**:凡把某个 RTL 常量当**实验自变量**,必须**先核综合后网表,再上板**。
已写进 `cv_sys.v` 注释与 `20261003_hp0_decerr_rootcause_arprot.md` §5。

### ② 🔴 我把一条**正面证据**读成了**反面证据**

上一轮的推理是:「重启之后仍然 DECERR ⇒ 故障与位流无关」。

**方向反了。** 若根因写在位流里,重启**当然**不能恢复 ——
「重启后仍故障」恰恰是「故障与位流有关」的正面证据。
我把它当成「与位流无关」的论据用了。

> **教训**:否定一条假设时,要问「**这个观测能区分我要区分的那两种情况吗**」,
> 而不是「这个观测符不符合我的预期」。
> 「重启无效」能区分的是**有无持久存储**,不能区分**故障在 PL 还是在 PS**。

### ③ 🟡 用户交回技术判断权时,更要把「为什么这么选」写清楚

本轮用户对两个岔路都答「按你认为最好的方案改」。这不是可以省掉论证的信号 ——
恰恰相反,报告里(B06「设计判断依据」)要写的就是**这个选择当时是怎么权衡的**。
已按此在记录里保留了 2×2 分离实验的设计理由。

### ④ 🟢 有效的做法:让用户当观测者时,给**可判读的图案**

"屏亮了没有"这种问法只能得到一个是/否,分不出"缺一块"。
本轮用**三元素图案**(整屏绿 + 中间红横带 + 左上白块):一次就能区分
「全对 / 少角块 ⇒ 行内偏移 / 全黑 ⇒ 无数据」。
用户回报"三元素全对",**一条信息就同时否掉了行内偏移假设**。

> 与该判据同源的还有:**红横带顺带证了无 R/B 交换**(用户确认是红的)。

### ⑤ 🟢 取值要有出处,而且要标明**出处的强度**

终值 `ARCACHE=4'b0010` / `ARPROT=3'h0` 的出处是本机 Vivado 里的
Xilinx AXI master 模板(两处同源副本)与厂商已验证例程 ——
**这属于「与参照物对齐」,不属于「已知原理」。** 报告里必须如实标注这个差别,
否则就是把"照着抄"包装成了"我懂"。
