## 纠错轨迹

1. 🔴 **用户说的「仓库」不是 git 仓库 —— 模型按术语理解,追问了一轮不存在的问题。**
   用户原话「**日志你再另起一个仓库吧,report我主要是拿来写项目报告以及存放参考文献的**」。
   我把「仓库」按 git 语义理解,于是提问围绕**新建远端 Gitee 仓 / token / remote URL** 展开
   (还准备了「先建本地仓、远端你来建」的推荐方案)。
   用户回:**「我是说在项目仓库里再建一个文件夹不能建吗」**。
   **根因**:用户的上一句落脚点是「report **拿来干什么**」,即**内容往哪儿放**;
   上下文里根本没有「另一个 git 仓库」的位置。我用自己领域的术语去替换了用户的词。
   ⇒ **用户的词 != 该词的术语含义**;追问时应当**用用户自己的语境复述确认**(「你是说在同一个仓库里
   另放一个目录,对吗?」),而不是**先按术语展开方案再问**。
   📌 注意这次翻车的**位置**:不是结论错,是**提问错** —— 一个不该问的问题消耗了一轮交互,
   而它本来靠读上下文就能避免。(与 `LLM-024` 的「指令没写执行位置」同类:**上下文假设**出错。)

2. 🟡 **「同步」的方向差点搞反 —— 靠实测拦住,未造成损害。**
   见「模型回答」§1。危险点在于:工作区的 `src/rtl/swm.v` 是**修复前**版本,
   而 `cp -r` 的惯性方向正好会用它覆盖掉仓库里修好的那份。
   **拦住它的不是判断力,是一条实测命令**(与 Vivado 工程逐文件 `cmp`)。
   ⇒ 凡是「两边都有、且可能各自演化过」的目录,**同步前必须先定方向**。

3. 🟡 **搬目录打断了 79 处交叉引用 —— 处置上区分了「导航链接」与「历史叙述」。**
   把 `report/measurements/` → `board/measurements/`、`report/llm-log/` → `llm-log/` 之后实测:
   **25 + 12 = 37 处**引用指向旧路径;另有 `report/source_design_checklist`(**7**)、
   `docs/project_state`(**18**)指向**按用户决定不进仓库**的文件;还有 `qrs_2026_fpga`(10)、
   `Task_Requirement`(7)指向工作区与赛题资料。
   处置**分了两类**:
   - `docs/*.md` = **活文档**,链接是给读者指路的 ⇒ `sed` 改写(**10 处**,改完实测可用);
   - `llm-log/` 与 `board/measurements/` = **历史存档**,里面的路径是**当时的事实描述**
     (如 `LLM-026` 写「`report/measurements/` 内**仍无文件**」、`LLM-020` 讨论两个目录的分工)
     ⇒ **一个字都不改** —— 改存档等于篡改记录(`CLAUDE.md` §6.2 红线)。
   - 剩余 5 处指向未发布文档的引用(**事实陈述**,如「上游依据:`…` §六 决策 D22」)
     ⇒ 在 `README.md` 里**列表交代**「这两份文档未随仓库发布、保留在工作区」,**不改原文**。
   ⇒ 教训:**移动目录前先 `grep` 引用,并把「导航链接」与「历史叙述」分开处置** ——
   前者必须修,后者**不能动**。这条是本轮最可复用的产出。

4. 🟡 **`cp` 的源路径打错,报错与「成功」同时出现 —— 靠核产物而非 rc 定案。**
   M03 那 4 份报告,我把 `$P/qrs.runs/...` 误写成 `$P/qrs.qrs.runs/...`,报错信息里出现了这个
   不存在的路径;但脚本**仍然打印了 `COPIED OK`** —— 两行输出互相矛盾,**无法从输出判断到底落地了几份**。
   我**没有信这行输出**,改用**逐个 `md5sum` 与源对比**:4/4 一致。
   ⇒ **「打印了成功」不等于成功,验收要看产物。**
   📌 与 `LLM-040` 纠错 1(`SSH 重启漏 `sudo -S`,脚本 `pgrep` 匹配到旧进程于是"顺利通过"`)
   **同型**:都是**失败零报错**、都是靠**换一个独立判据**(时间戳 / md5)才看穿。
   ⇒ `skill/stale-artifact-silent-reuse/` 值得再补一条:**"脚本自报的成功"本身也是一种可能失效的判据**。

5. 🟢 **凭据处理走的是临时通道,但风险未消除(需用户处置)。**
   用户把账号密码放在 `~/Desktop/password.txt`。推送用临时 credential store,用完即删,
   **未进命令行参数、未进 git 配置**。
   ⚠️ **但仍存在的风险**:密码**明文存放在桌面文件里**,且该文件**权限为 `-rw-rw-r--`(组与其他用户可读)**。
   本轮**未擅自改动该文件**(不是模型创建的)。建议改用 **Gitee 私人令牌**或 **SSH key**,
   并至少 `chmod 600`。
