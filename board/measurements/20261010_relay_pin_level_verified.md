# 继电器引脚电平实测 —— 极性 / 位序 / 通路 三项一次坐实(2026-10-10)

**被测对象**:板上位流 md5 `9613c2928a01f832b71aef7c45c4c0b9`(同
`20261010_relay_cfg_write_anomaly.md`)。
**测量人**:用户(万用表,直流电压档;黑笔接 J4-37 GND,红笔点各继电器脚)。
**触发原因**:`board_pins.md` 注③ 明写「`ACTIVE_LOW=0` 是**继承前序 STM32 工程的约定**,
**不是**从驱动板手册查来的」—— 这是一条**未验的假设**,而它一旦反了,
上电配置期(引脚高阻/上拉)会**同时吸合全部 7 只继电器**。

---

## 1. 测量方法与命令

用 §8 的绕法(settle 先置 0)把组合写到 `0x10`(`AllOff/reset`,前序文档 §3.8 定义
= **只有 K5 高**,**不是**七路全低):

```bash
echo xilinx | sudo -S -p "" python3 /tmp/poke_relay.py w 0x24 0x00000000 0x1C 0x10
```

⚠️ 只 mmap `/dev/mem`,**不加载位流**(此刻 `lcd_fb_reader` 正在 HP 口上读 DDR)。

> 📌 **2026-10-10 晚更正**(本次测量**结论有效**,只是当时的归因说法已过时):
> 上式里的"绕法"(`settle` 先置 0)**不是必需的** —— 那批工具走的是裸 mmap,
> **一次写就是一拍**,本来就不会触发 `0x1C` 异常;当天晚上查明该异常的根因是
> Python 侧的 `struct.pack_into` **多发一笔 `0x00`**,与"要不要置 settle"无关
> (见 `20261010_relay_cfg_write_anomaly.md` §10)。**本节读数与结论不受影响。**

## 2. 结果

**用户读数:只有 `W11`(J4-26)为 3.3 V,其余 6 个继电器脚均为 0 V。**

| K | 球号 | J4 脚 | 位 | 预期(写 `0x10`) | 实测 |
|---|---|---|---|---|---|
| K1 | U15 | 30 | bit0 | 0 V | 0 V ✓ |
| K2 | U14 | 29 | bit1 | 0 V | 0 V ✓ |
| K3 | U13 | 28 | bit2 | 0 V | 0 V ✓ |
| K4 | V13 | 27 | bit3 | 0 V | 0 V ✓ |
| **K5** | **W11** | **26** | **bit4** | **3.3 V** | **3.3 V ✓** |
| K6 | Y11 | 25 | bit5 | 0 V | 0 V ✓ |
| K7 | Y12 | 24 | bit6 | 0 V | 0 V ✓ |

## 3. 这一次同时坐实了三件事

| # | 结论 | 依据 |
|---|---|---|
| 1 | **极性:`ACTIVE_LOW = 0`(高电平有效)成立** | 写 `0x10` ⇒ 目标脚**高**。若低有效,写 `0x10` 应把 K5 拉**低**而其 6 脚高 —— 与实测完全相反,排除 |
| 2 | **位序:`K1..K7 = bit0..bit6` 成立** | 高电平落在 **`W11` = bit4 = K5**,不是任何其它脚。位序若反,高的会是别的脚 |
| 3 | **★ 通路:`relay_reg` → FPGA 引脚 是活的** | 写 `0x10` ⇒ 引脚就是 `0x10`。这一条以前**从未验过** —— 之前所有结论都只到**寄存器回读**为止 |

**第 3 条是本次真正的增量。** 在此之前,本项目对继电器的全部知识都停在
「`0x1C` 读回是什么」;现在第一次知道**引脚电平确实跟着寄存器走**。

## 4. 由此**可以**推出的一条(不再是悬案)

`relay_ctrl.v:347-358`:

```verilog
assign relay = ACTIVE_LOW ? ~relay_reg[6:0] : relay_reg[6:0];
```

这是一条**纯组合通路**,且上面第 3 条已用一组值实测**打通**。
⇒ 既然「`relay_reg = 0x00`」是独立实测过的(`anomaly` 文档 §7.2 的 ③④),
则**被拒收的写之后,引脚组合确实会变成 `0x00`(全低)**。

⇒ `anomaly` 文档 §5 那条安全项 ——「一个被拒收的写仍会把继电器组合实际拨到 `0x00`」——
**从"仅寄存器侧"升级为"引脚侧成立"**。导线验活了,它送的就是寄存器里那个值。

## 5. 仍然**没有**验的(不要越界)

⚠️ **继电器触点(COM/NO/NC)本身从头到尾没量过。** 本次量的是 **J4 排针**,
即**驱动板的输入侧**,不是继电器输出侧。

- 「FPGA 引脚电平对了」✓ 已验
- 「驱动板收到电平后继电器线圈得电、触点真的翻转」✗ **未验**
- ⇒ 中间还隔着**驱动板**(型号/极性/是否共地/是否有反相)这一层

要闭环这一步只能量**继电器本体**的 COM–NO / COM–NC 通断,在驱动板上,不在 J4。
**在量到之前,任何"继电器已切到 X 回路"的说法都只到引脚级。**

另:上电**配置瞬间**(PL 未配置、引脚高阻)的电平本组也没覆盖 —— 量的是配置完成后的稳态。

## 6. 复现命令

```bash
# 板上(需 root);poke_relay.py 只 mmap /dev/mem,不加载位流
echo xilinx | sudo -S -p "" python3 /tmp/poke_relay.py w 0x24 0x00000000 0x1C 0x10
# ⇒ 万用表:J4-26 (W11) = 3.3 V,其余 J4-24/25/27/28/29/30 = 0 V,参考地 J4-37/39
```
