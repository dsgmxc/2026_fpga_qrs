## 三、RTL 层:三项上板实测

全部通过**常驻探针**(`tools/adc_probe.py`)的 **`attach` 模式**取得 ——
`attach` 只映射 MMIO、**不加载位流**,所以不会触发上面那条"一个周期一次 Overlay"的限制。
产出:`artifacts/20261008_adc_window_probe.out`。
⚠️ 板载时钟比宿主机**慢 5 天**(板 `Sat 03 Oct` vs 宿主 `10-08`),板上文件时间戳不可与宿主时间对齐。

### 3.1 读指针掩码真的是 13 位

```
>>> wr 0x94 0x1FFF
  write 0x94 = 0x00001FFF  → 读回 0x00001FFF
```

判读:旧掩码是 `32'h0000_0FFF`,**写 `0x1FFF` 会被截成 `0x0FFF`**。
回读等于写入值 ⇒ 掩码已放到 `32'h0000_1FFF`(`cv_axi_lite_slave.v:492`,已核)。
⚠️ 这是本次改动**最容易漏**的一处:不改掩码不会报错,只会**读到另一个点的数据**。

### 3.2 缓冲真的是 8192 深(用时延反推)

`adc_capture.v` 是**单次采集**:`go_pulse` 清 `wr_ptr` → 写满到 `wr_last` → `done` 置位。
⇒ **`GO → done` 的时延 = `DIV × BUF_DEPTH / 130 MHz`**,是个可对拍的硬指标。

| `DIV` | 实测(3 次) | **8192 预测** | 4096 预测 | 判定 |
|---|---|---|---|---|
| 65 | 4.3 / 4.3 / **5.4** ms | **4.096 ms** | 2.048 ms | ✅ 贴 8192 |
| 130 | 10.2 / 8.7 / 8.8 ms | **8.192 ms** | 4.096 ms | ✅ 贴 8192 |
| 255 | 18.1 ms | **16.07 ms** | 8.03 ms | ✅ 贴 8192 |

- **4096 假说被排除**:三档分别差 **2 / 4 / 8 ms**,而探针的轮询分辨率是 **2 ms**
  ⇒ 不是量化误差,是**系统性差一个档**。
- ⚠️ 实测值**偏大**于预测(DIV=255 偏 2 ms),符合预期:探针是**轮询** `done`,
  每次还要额外读 4 个点、走 AXI-Lite 事务。**判据是"落在哪个假说上",不是"等于理论值"**。
- 单次采集耗时 **126 µs**(`2 × 8192 / 130 MHz`)—— 时延量级的 4 ms 是**探针开销**,不是采集本身。

### 3.3 四个频率码全部原值回读

```
>>> wr 0x80 0x1A36E    → 读回 0x0001A36E     10 kHz
>>> wr 0x80 0x10624E   → 读回 0x0010624E     100 kHz
>>> wr 0x80 0xA3D70A   → 读回 0x00A3D70A     1 MHz
>>> wr 0x80 0x6666666  → 读回 0x06666666     10 MHz  ← 见 §四
```

判读:`f_out = code × 25 MHz / 2^28`,四条与 AD9833 手册逐位相符。
⭐ **10 MHz 那一条也读回正确** —— 这正是"**算术成立、物理不成立**"的直接证据:
**寄存器通路没问题,是模拟输出出不来**(见 §四)。

## 四、10 MHz 为什么删:寄存器收得下,频谱仪上出不来

| 项 | 值 |
|---|---|
| AD9833 MCLK | **25 MHz,板载晶振焊死**(决策 D10,FPGA 供不了) |
| 10 MHz 时每周期 DAC 采样点 | **2.5 个** |
| 主频与 15 MHz 镜像的间隔 | **仅 5 MHz** ⇒ 低通滤不掉 |
| 寄存器 `0x80 = 0x6666666` | ✅ **能写能读**(§3.3) |

⇒ **不是配置问题,是 DAC 采样定理的硬限制**。要 10 MHz 只能换激励源(MCLK ≥ 100 MHz 的 DDS)。
**2026-10-08 从界面与档位表删除。**

**上板佐证**(`artifacts/20261008_cui_4slot_window_taps.log`):

```
[mc] 激励 → 10.000 MHz(0x80 = 0x6666666)      ← 用户选中
[mc] 激励 → 1.000 MHz(0x80 = 0xA3D70A)        ← 立即切回,**中间没有任何测量**
```

⚠️ **口径**:用户给出的判据是口头的「**输出不了**」;
日志只能证明"选中后未做测量即切回"。**删档的依据是硬件算术 + 用户口头判定,不是本次的仪表读数** —— 如实标注。

## 五、C 侧与界面层:三档窗长逐位对上(用户手点)

这是本次**最核心的证据**。同一次会话里把三档依次点过、每档都做了一次单点测量。
日志原文(`artifacts/20261008_cui_4slot_window_taps.log`,节选):

| 档位 | 界面选择日志 | **解调日志(窗长 / 周期数)** | 设计值(§4 表) | 判定 |
|---|---|---|---|---|
| **10 kHz** | `[mc] 激励 → 0.010 MHz(0x80 = 0x1A36E)` | `窗长 **6500** 点(**1** 个激励周期)` | 6500 / 1 | ✅ |
| **100 kHz** | `[mc] 激励 → 0.100 MHz(0x80 = 0x10624E)` | `窗长 **7800** 点(**12** 个激励周期)` | 7800 / 12 | ✅ |
| **1 MHz** | `[mc] 激励 → 1.000 MHz(0x80 = 0xA3D70A)` | `窗长 **8190** 点(**126** 个激励周期)` | 8190 / 126 | ✅ |

⭐ **三档 × 两个数字 = 六个数全部逐位一致**,且**三档各不相同**
⇒ 排除了"窗长写死成常量"这种假通过 —— 它是**跟着激励现算的**。

**同一次会话的汇总统计**(日志末尾 `──── c_ui 统计 ────`):

```
  ADC 采集  成功=6  失败=0
```

⇒ 6 次采集**零失败**(10 kHz 三次、100 kHz 一次、1 MHz 一次,外加切换时的采集)。
**"没有失败"本身就是判据之一** —— 旧设计下 10 kHz 会报
「窗长 6500 点,超出参考表上限 256/8192」,是**报错**而不是静默错误。

**画图抽稀也对了**(此前"波形是平的"那个坑的回归验证)。
规则是 `pynq_protocol.c::adc_feed_point_waveform()` 里的两步:
**① 画 3 个周期,但不超过整窗;② 按 `ceil(显示点数 / 480)` 抽稀**(480 = `UI_WAVE_MAX_SAMPLES`)。

| 档位 | `L/m`(点/周期) | ① `L/m × 3` | 截到整窗后 `show` | ② stride | **实际喂进图** | 日志原文 |
|---|---|---|---|---|---|---|
| 10 kHz | **6500** | 19500 | **6500**(整窗,只有 1 个周期) | 14 | **465** | `显示前 6500 点、每 14 点取一 → 465 点` |
| 100 kHz | **650** | 1950 | **1950**(3 个周期) | 5 | **390** | `显示前 1950 点、每 5 点取一 → 390 点` |
| 1 MHz | **65** | 195 | **195**(3 个周期) | 1 | **195** | `显示前 195 点、每 1 点取一 → 195 点` |

⭐ **三行的 `show` 各不相同(6500 / 1950 / 195)** —— 这只有"**每条都按自己的 `L/m` 现算**"才可能,
写死任何一个常量都会让另外两行对不上 ⇒ **抽稀逻辑真的是数据驱动的**。
📌 这正是 §5.1 第 3 道闸的正解:旧实现是"8192 点喂进去**静默截断到前 480 点**"(屏上一条平线),
现在是"**先算画几个周期、再抽稀**"。**改大上限解决不了问题** —— 图只有 480 像素宽。

### 界面层:删档删干净了

对**已部署二进制**做字符串提取(客观检查,不靠肉眼):

| 字符串 | 存在 |
|---|---|
| `10kHz` / `100kHz` / `1MHz` | ✅ **在** |
| `10MHz` | ⛔ **不在** |

⚠️ 这是一项**版本核对,不是功能验收** —— 它能证明"四档变三档",
**不能**证明按钮点得动(那要靠 §五 的日志)。

## 六、代价(M10 优化前后对比)

Vivado 2025.2,同一工程、同一综合/实现策略,**唯一变量是上述改动**。

| 资源/时序 | **改前**(2026-10-07) | **改后**(2026-10-08) | Δ |
|---|---|---|---|
| Slice LUTs | 1662(3.12%) | **1665(3.13%)** | +3 |
| Slice Registers | 1886 | **1888** | +2 |
| **Block RAM Tile** | **2.5(1.79%)** | **4(2.86%)** | **+1.5** |
| DSPs | 0 | 0 | 0 |
| **WNS** | +1.055 ns | **+1.023 ns** | −0.032 ns |
| **WHS** | +0.045 ns | **+0.067 ns** | +0.022 ns |
| 失败端点 | 0 / 4938 | **0 / 4976** | — |
| 约束满足 | — | **`All user specified timing constraints are met.`** | — |

时钟(实现后报告):`clk_fpga_0` **50.000 MHz** / `clk_adc_raw` **130.000 MHz** / `clk_fb_raw` **50.000 MHz**。

**判读**:代价集中在 **BRAM(+1.5 tile = 器件 2.86%)**,LUT/FF 几乎不动,时序余量 1.023 ns 充裕。
⇒ 用 2.86% 的 BRAM 换回"**10 kHz 与 100 kHz 可测**"——这两档在旧设计里是**做不到**,不是"做得差"。
📌 B04 素材:这里**没有**为性能牺牲资源;真正的取舍在"**主动放弃自由度**"(删 10 MHz、固定采样率)。
