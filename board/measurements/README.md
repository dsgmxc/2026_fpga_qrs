# 实测输出存档

> 本目录存放**上板实测证据的原始文件**(照片 / 示波器截图 / ILA 波形 / 串口输出)。
> 对应必做点 **M13**(板上跑通并提供实测输出,指南 3.3.3.2)与 **M04**(实测输出与参考结果的比对)。
>
> ⚠️ **"测过"不等于"有证据"。** 本项目已多次出现"读数只有口述、无截图"的情况
> (DAC1220 三点电压、AD9833 正弦输出)—— 报告引用时只能如实写"用户口述",
> 这比"有照片"弱一档。**每做一次上板测量,先想好这次留什么文件。**

## 命名规范

```
YYYYMMDD_<主题>.<扩展名>
```

> 🆕 **`_TEMPLATE_display_touch_bringup.md`** —— 显示 + 触摸**首次上板**的空白模板。
> 一次性覆盖风险 **D1 / R1 / R2**、触屏通信、LVGL 首页五件事。
> 用法:**改名**成 `YYYYMMDD_display_touch_bringup.md` 后逐格填。
> ⛔ **模板里的空全部待填,不要预设任何数字**;没测的格子写「未测」,不要留空。

示例:

| 文件名 | 内容 |
|---|---|
| `20260925_lcd_colorbar.jpg` | LCD 彩条(白\|黑\|红\|绿\|蓝) |
| `20260919_dac_three_points.md` | DAC1220 三点电压读数与预期对照 |
| `20260921_ad9833_1khz.png` | AD9833 正弦输出(示波器) |
| `2026xxxx_dlia_ila.png` | DLIA 解调 ILA 波形 |

## 子目录 `artifacts/` —— 大段原文放这里

**整份的机器输出**(寄存器探针日志、`fsync` / 终端会话照录、Vivado 报告文本)放
`artifacts/YYYYMMDD_<主题>.<扩展名>`,与 `.md` 正文分开。

理由:一份 `.log` 动辄几百行,整份贴进 `.md` 会把结论淹掉;**但删掉又违反"实测必须留证据"**。
所以正文写结论与预期/实测比对,原文整份另存。**同一次上板的 `.md` 与 `artifacts/` 一起更新**。

> 小段终端输出(几十行以内)**仍建议直接贴进 `.md` 正文**,不必单开文件 —— 读者少跳一次,证据链更短。
> `.gitignore` **不拦** `*.log` / `*.rpt`(见交付仓库 `.gitignore` 末尾「故意不忽略」一节的说明)。

**对照实验位流原件也放这里**(2026-10-05 起),命名带实验标签与自身 md5 前 8 位:

```
qrs_hp0_<实验名>_<ARPROT[3:0]>-<ARCACHE[3:0]>_<md5前8位>.bit
例:qrs_hp0_good_0010-000_0e4cb57c.bit   ← 该文件自身的 md5 确实是 0e4cb57c…
```

**为什么值得进库**:位流是**跑一次不一定能再出来**的东西(要重建工程、重跑综合实现),
而 2×2 对照实验的结论(`ARPROT[1]` 置 1 ⇒ `S_AXI_HP0` 每个读事务回 `DECERR`)全靠
**四个位流里恰好四个取值**支撑 —— 文件名里写着取值、md5 又自证是同一份,
读者才能把 `20261003_*.md` 里的结论和二进制对上。
⚠️ 每个约 4 MB,是本目录唯一的二进制证据,会随仓库一起变大。

## 每条证据必须同时记录(写在同目录的 `.md` 里,或直接标注在文件名旁)

| 项 | 为什么 |
|---|---|
| **被测对象 / 测点** | "模块 SMA 输出口" 与 "FPGA 引脚" 是两回事 |
| **所烧位流版本** | 时间戳或 `qrs.bit` 的 md5 —— **排除"烧的是旧程序"** |
| **烧录时间** | 与源码文件时间戳比对,证明板上的与源码同版 |
| **板型 / 屏型号** | 复现时的环境 |
| **预期值 vs 实测值** | M04 要的是**比对数据**,不是单个数字 |
| **仪器 / 量程** | 万用表 DC 挡测正弦会读成平均值 —— 量具本身会影响结论 |

## 已知的"量具坑"(本项目踩过或差点踩过)

- **万用表 DC 挡测正弦** → 读到的是平均值,看不出有没有振荡(LLM-017)。
- **用 Waveform 查看器看反相信号** → 反相的正弦看起来还是正弦(LLM-019,AD9238)。
- **时间戳法只能排除"忘了重跑综合"**,证明不了板上烧的就是那一版(LLM-018)。
- **彩条的顺序才有判别力** —— 颜色顺序错说明 24 根 RGB 位序错;
  只看到"有彩条"不能证明接线全对(LLM-021)。
