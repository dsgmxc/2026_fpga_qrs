## ⚠️ 先说一条会误导人的前提:板子的时间戳不是日期

| 项 | 实测 |
|---|---|
| 板子 `timedatectl` 的 `RTC time` | **n/a**(无 RTC 电池) |
| 板子当前时间 | `Sat 2026-10-03 19:30:19 UTC` |
| 宿主机当前时间 | `2026-10-06 23:52 CST`(= UTC 15:52) |
| **偏移** | 板子比宿主机慢约 **68 小时** |

(相对量仍可信:`qrs-ui.service` 的 `ActiveEnterTimestamp` 减文件 mtime,能判断同一次开机内的先后。)

## 二、★ 从 `point_result_three_cards` 里看出的一个真问题

这张图是 **`LLM-049` 那条发现的同族第二例**,而且比它更有价值:

- **现象**:单点结果页三张卡片 CISS / COSS / CRSS **全部 `OK`**,`Cs` 三路**完全相同**(`18.913 pF`)
  —— 因为三路共用**同一次** ADC 读数(没有继电器,只有一条测量回路)。
- **但这一页处理对了**:卡片下方**明写**「数据来源:测量页最近一次写回的读数;
  **未测过的回路显示 `--`**」⇒ 读图的人不会误以为做了三次独立测量。
- **对照**:扫压结果页**没有**这句话 —— 它给三条 series 配了三种颜色的**图例**,
  视觉上暗示三次独立测量,实际是同一个读数的三份拷贝(见 `LLM-049`)。
  ⇒ 🟡 **可执行的小改**:扫压结果页**照单点结果页那样标一句**,
  比"改绘制逻辑"更小、更诚实。

📌 **一条可复用的判据**:**同一个工程里,同一件事一处说明了、一处没有 —— 没说明的那处就是缺陷所在。**
"三路共用读数"这件事在单点结果页是**写明的设计**,在扫压结果页就变成了**会误导的图例**。

## 四、复现方法

```bash
# 板上(需 root 读 /dev/mem)
echo xilinx | sudo -S /usr/local/share/pynq-venv/bin/python3 \
    /home/xilinx/fb_dump.py 0x38100000 /home/xilinx/fbX.ppm
# 宿主机取回并转 PNG
python3 /tmp/bx.py -d /home/xilinx/fbX.ppm /tmp/fbX.ppm
python3 -c "from PIL import Image; Image.open('/tmp/fbX.ppm').save('/tmp/fbX.png')"
```

## 五、🆕 `20261006_board_point_fail_state.png` 的来历(2026-10-08 补档)

这张**不是** 2026-10-06 那次归档的一部分 —— 它是**第 50 次会话收尾清板时**才从板上捞出来的。

- 板上遗留 9 个 `.ppm`(`fb0_chk` / `fb0_now` / `fb1_now` / `fbA`–`fbF`)。
  **删除前逐张与工作区全部 13 张 PNG 做过像素级比对**(转 RGB 后比 `md5(pixels)`,不是比文件哈希 ——
  PNG 编码方式不同,文件哈希必然不等)。
- 结果:**8 个与已归档 PNG 逐像素相同**(`fb0_chk` = `20261006_board_reset_page_after_reset.png`;
  `fbA/B` = `20261008_ui_home_before_65msps.png`;`fbC/D` = `20261008_ui_now.png`;
  `fbE/F` = `20261008_ui_after_65msps.png`),**只有 `fb0_now`(`=` `fb1_now`,两张内容相同)在归档里查无对应** ⇒ 补档为本文件。
- **归属 2026-10-06 的依据**(不是猜的):板上 `fb0_chk` 与已归档的 `20261006_board_reset_page_after_reset.png`
  **逐像素相同**,两者板载 mtime 相差 **4 分钟**(`19:55` → `19:59`)⇒ 同一批。
- **内容是「100 kHz 单点失败」的依据**:同一批归档的
  `20261006_qrs_ui_full_log.log` 第 **1416** 行写着
  `[adc] 🔴 单点测量:采集或解调失败 —— 解调不可用:每周期 100 点,超出参考表上限 64`,
  第 **1797** 行 `ADC 采集 成功=332 失败=5` —— 与屏上 `状态:单点失败(见 [adc] 日志)`
  / `测量结果无效` 相符。⇒ **截图与日志互为佐证**(见 `LLM-049` / `LLM-050`)。
- ⚠️ **不要过度解读这张图**:它证明的是**屏上当时显示成什么样**,不证明失败次数、也不证明根因;
  次数与根因见上述日志与 `LLM-050`。

📌 **这次清理用的判据值得复用**:板上文件的删除条件是
「**它是不是唯一一份**」,而"是不是唯一一份"**必须用内容比对去查,不能用文件名或大小去猜** ——
`fb0_now` 与 `fb1_now` 文件名不同、`fbA` 与 `fbB` 文件名不同,内容却各自完全相同;
而 `fb0_chk` 名字看着像"检查图",实际就是已归档的那张复位页。
