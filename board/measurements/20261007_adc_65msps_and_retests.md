### §1-2 的细节:窗口没有因换线平移

`eye` 全范围扫 `PH_OFF`,DIV=13 与 DIV=26 两档:

| DIV | 平坦带(实测) | 公式 `[2−P/2, +1]` | 端口 A 中心 `1.5−P/4` | 实测 A 落点 |
|---|---|---|---|---|
| 13 | `[−4, +1]` | `[−4, +1]` ✅ | −1.75 → −2 | −2 ✅ |
| 26 | `[−11, +1]` | `[−11, +1]` ✅ | −6.5 → **−5** | −11…+1 内 ✅ |

平坦带 = **端口 A(INA,未接源)**,电平恒 4076;带外 = **端口 B(INB,接 DDS)**,
是 1 MHz 正弦。DIV=26 时两带各 13 拍,**13+13 = 26 正好整除** —— 时分复用模型成立。

⇒ `20261007_rewire_rebuild.md` §四 担心的"换脚即平移传播延迟 ⇒ 稳定窗公式
可能不再成立"**没有发生**。`adc_window()` 的守卫仍然可用。

### §3 的细节:OEB —— 本次没测到,原因是测法够不着

**⚠️ 这一条是本次的一个自我纠错,结论是「没测到」而不是「未复现」。**

我写的是 `wr 0x88 0x0002050D`(DIV=13 / PH_OFF=5 / **OEB_N=1**),然后 `dump 13 5 200`。
结果 p-p=39、去重 28 —— 看起来"OEB 没效果"。**但这个测法是无效的:**

```python
# tools/adc_probe.py :: cmd_go()
cfg = (div & 0xFF) | ((ph & 0xFF) << 8) | ((1 if cont else 0) << 16)
m.write(R_ADC_CFG, cfg)          # ← 这一句把 0x88 整个重写了
```

`cfg` **只含 DIV / PH_OFF / CONT**,**不含 bit17(OEB_N)、不含 bit18(PDN)**。
⇒ `dump` / `wave` / `eye` **每执行一次就把 OEB 清回 0**。
我那句 `wr 0x88 0x0002050D` 在 `dump` 起来的那一刻就被覆盖了,
**从头到尾测的都是 OEB 关**。

⛔ **故本条不作任何结论。** 上次"`OEB_N=1` → 128 点全同 4095、p-p=0、去重=1"
的结论**没有被推翻,仍然有效**(那次显然是直接写寄存器 + 读缓冲的做法,
绕开了 `cmd_go` 的重写)。

**要重测需先给 `adc_probe.py` 加一条能带 OEB/PDN 的采集路径**
(或在 `wr` 之后不走 `cmd_go` 直接触发 GO)。已记入 §六 遗留。

📌 附带教训:「**下发参数的命令**」和「**执行动作的命令**」合在一条里时,
后者会静默覆盖前者设定的一切 —— 而回读 `0x88` 恰好显示的是**被覆盖后的值**,
看日志也发现不了。判据应该是回读位域、不是回读整个寄存器字。

## 二、65 MSPS:实测可用

### 位流与时钟

```
wr 0x88 0x00000002      (DIV=2 ⇒ adc_clk = 130/2 = 65.000 MHz)
0x90 = 0x00000003       mmcm_locked=1  done=1  busy=0
[go] done 置位,耗时 0.0022 s      ← 与 DIV=13 相同,无额外延迟
```

### 全范围 `eye` 扫(可达刻度只有两个)

```
  PH_OFF  p-p   去重  mean     首8点
     -1      5     6   4072.5  4074 4072 4073 4072 4073 4072 4073 4072   ← 端口 A(死)
      0     42    41   4060.2  4051 4053 4056 4058 4057 4061 4062 4064   ← 端口 B(DDS)
```

**⇒ P=2 下 A 在 `−1`、B 在 `0`,各占一拍,没有余量。**

### 波形与解调(见 PNG 第 6 联)

DIV=2 / PH_OFF=0 / 1 MHz,250 点里 **3.85 个周期**(目视数峰也是 ~65 点/周期):

| 采样率 | L | M | 点/周期 | DC | mag(码) | 解调残差 rms |
|---|---|---|---|---|---|---|
| 10 MSPS(DIV=13) | 250 | 25 | 10.00 | 4066.1 | 18.182 | 2.054 |
| **65 MSPS(DIV=2)** | 195 | 3 | 65.00 | 4059.6 | **18.501** | 1.488 |

**同一路 1 MHz 正弦,两种采样率、两套完全不同的窗结构,幅值只差 1.8%**
⇒ 解调算法与 65 MSPS 通路都对。

### 挡住 65 MHz 的那一行(不是 RTL)

`pynq_regs.h::cv_adc_phase_center()` 在 `P=2` 算出 **+1**,
而寄存器合法范围是 `[−P/2, P−1−P/2]` = **`[−1, 0]`** —— **不相交**。
⇒ 刻度永远命中不了,`done` 不置位,界面表现为"点了没反应"。

同一个文件里 `cv_adc_phase_center_b()`(端口 B)**本来就有折回**(`t > hi` 时
`t -= P`),P=2 时算出 0 ✅;A 少了同一条。补上后折回得 **−1**,正是实测值。

`measure_config.c::adc_window()` 同病:P=2 返回 `[1,1]`,与合法范围不相交,
`NudgePhase` 会把刻度钳到 1。同样折回 ⇒ `[−1,−1]`。

📌 **折回只改动 P=2 这一档**;P=3/4/5/10/13/26/65/130 上界都不越界,逐位不变
(已逐个对拍 C 与 Python 两侧,9/9 一致)。

## 三、信号质量:真正的限制在前端,不在算法

| | 值 |
|---|---|
| INB 信号 p-p | **44 码 = 21 mV**(满量程 2 V ⇒ **1.07%**) |
| 直流坐点 | 4076 / 4096 = **99.5% 满量程**,离上轨只剩 **9 码** |
| 解调 SNR | **22.5 dB**(100 kHz @ 10 MSPS,残差 1.035 码 ≈ ADC 自身抖动底) |

解调残差已经压到 ADC 的量化抖动底(±1 码),**算法这侧没有余量可挖了**。
要提信噪比只有两条路:① 前端加增益把信号做到满量程的几十个百分点;
② 加大激励。⚠️ 但直流坐在 4076 意味着**任何超过 ~9 码(≈4 mV)的正向摆幅都会削顶** ——
加增益之前必须先解决偏置点。

📌 幅值换算用的是 `ADC_SAMPLE_VFS_PP = 2.0` 与 `ADC_SAMPLE_R_TIA = 1000`,
**两者都未标定**(见 `adc_sample.h` 自述),故上面这些码值只有相对意义。

## 五、工具侧:`adc_probe.py` 新增 `attach`

**为什么需要**:`adc_probe.py` 原有每条命令都要求先 `init`,而 `init` 里那句
`Overlay()` 是**本上电周期唯一允许的一次** —— 它已被 `main.py` 用掉了
(UI 正常跑着就是这个状态)。于是探针在这个状态下**一条命令都用不了**。

`attach` 只做 `/dev/mem` 的 MMIO 映射,**不加载位流、不碰 FCLK0**
(`/dev/mem` 的 mmap 不排斥多进程)。成功后主动占住 `st['ol']`,
复用 `cmd_init` 开头既有的守卫来拦住后来的 `Overlay()`。

⚠️ **`init` 与 `attach` 每个上电周期只用其一。**
